# Evals — 持续评测（Anthropic: 每次换模型或改规则，先跑一组固定任务）

## 为什么需要

软件测试回答「代码还能不能用」，Evals 回答「**这套 AI 工作配置**（模型 / CLAUDE.md / Skill / Hook / 提示词）还能不能达标」。两者都要有，互相替代不了。

改了下面任何一样东西，就在动手前跑一轮 Evals：

- 换模型或模型版本
- 改 CLAUDE.md / AGENTS.md / rules/
- 新增或修订 Skill / Hook
- 改提示词模板 / 收口清单

## 怎么跑

1. 从 `cases/` 里选一组用例（首次建议 20–50 个历史任务，没有就从 5 个开始，逐步积累）。
2. 每个用例 = 给 AI 一个历史任务 + 对照 `expected`（当时的正确产出要点）检查。
3. 用 `ai-native metrics` + 人工判定打分，结果记进 `cases/<name>.result.md`。
4. 通过率明显低于上一轮 → 回滚本次配置变更，先修再上。

## 用例来源

- 历史上有代表性的真实任务（好任务 + 翻车任务都要）
- **每一起线上事故，必须转化为一个回归用例**（Anthropic: 避免模型或规则升级后又踩回旧坑）

## 用例格式

见 `cases.template.md`。新用例复制该模板到 `cases/<name>.md`。
