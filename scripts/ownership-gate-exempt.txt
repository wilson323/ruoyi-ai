# scripts/ownership-gate-exempt.txt — 资源归属门禁的存量基线（豁免清单）
#
# 门禁：scripts/check-write-endpoint-ownership.py（配套公共函数 scripts/lib/audit-gate-input.sh）
#
# 每行格式：<控制器.java>#<方法名>\t<豁免理由>
#   —— 理由是必填项，缺理由的行门禁会 exit 2 拒绝加载（防止「先加白名单让它过」）。
#
# 纪律（只减不增）：
#   1. 本清单只允许删除，不允许新增。新写端点忘了归属校验 → 门禁直接报红，
#      要放行必须先补校验；确认无归属概念才准加一行，并写明理由。
#   2. 清单里某行对应的代码补了归属校验后，门禁会报「豁免已失效」并 exit 1，
#      逼迫你回来删这一行 —— 防止基线变成僵尸白名单。
#   3. 本清单为空时门禁 exit 1（不是 exit 0）。空清单 = 门禁什么都不判 = 假绿。
#
# 数据来源：ownership-inventory 逐条核出的分级（/tmp/ownership-inventory.md，2026-10-03）。
# 数字口径：ruoyi-ipd controller 共 209 个写端点，其中 88 个带角色注解但无归属校验。
# 分级分布见文件末尾统计。**存量修复（P4）完成后逐行删除对应条目。**
#
# ---- 2026-10-03 HIGH 7 条清零 ----
# HIGH 7 条全部删除，原因分两类，都逐条读过控制器方法体 + 一跳服务：
#   A 类 6 条（BidController close/publish/preSelectToken/withdraw、
#            DemandController#linkProject、GateMaterialController#upload）：
#      上一轮已在控制器里加了归属守卫，但守卫封装在私有 helper 里
#      （requireInvitationWritable / requireDemandGroup / requireGateGroup），
#      而门禁 GUARD_RE 只扫**端点方法体文本**，helper 名字不在 GUARD_TOKENS 里，
#      于是被判成「无归属校验」，基线行一直留着（stale = exempt - found 也命中不到）。
#      本轮把「解析归属」与「断言归属」拆开：私有 helper 只解析出目标组 ID
#      （资源缺失时 fail-closed 抛 FORBIDDEN），端点方法体里显式调
#      IpdIdorGuard.assertSameGroupIpd(actor, 解析结果) —— 门禁能看见，职责也更清晰。
#   B 类 1 条（RecoveryWarningController#check90d）：真缺，控制器只有角色门
#      requireLeaderOrAdmin()、actor 丢弃，service 无条件 selectList 全库项目逐个 insert。
#      本轮 actor 传进 service（IRecoveryWarningService#checkAndGenerate(IpdActor, LocalDate)），
#      非超管只扫 main_group_id 等于自己组的项目。
#
# 附：本清单只覆盖「带 @SaCheckPermission 且无归属校验」的端点。

# ---- 已知未覆盖面（本门禁不覆盖，别误读成「已安全」）----
# 1. 不带 @SaCheckPermission 的写端点（约 50 个）：连角色注解都没有，
#    归属校验无从谈起，但本门禁 R3 只判定「有角色注解」的端点，故不进基线。
#    下一轮需单独定范围（要么要求补注解，要么整类豁免）。
# 2. 一跳以外的传递调用：控制器 → 服务A → 服务B，守卫落在服务B 时不判定。
#    刻意不做多跳：多跳解析的误报率会高到门禁被关掉，得不偿失。
# 3. 守卫是「存在即算」判定，不判断守卫语义对不对 ——
#    写了 requireSuperAdmin 但没查资源归属，本门禁看不出来。
