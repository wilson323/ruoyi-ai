## 教训沉淀

1. **R25 兄弟会话 ahead 分支是会随治理轮持续累积的**：每轮治理都产生新分支，老分支要么 squash merge 落 main、要么 ahead commit 被吸收、要么变历史快照
2. **wt-r39 remote refs 是兄弟 wt 的镜像**：兄弟 wt 删除时本地 remote refs 残留，必须手动清（git remote prune 不删）
3. **packed-refs 中的 backup/main**：update-ref 删不掉，必须 rm 文件 + sed -i.bak 改 packed-refs + 删 bak
4. **tag 不该自动清的**：v2.0.1~v3.1.0 是项目版本 tag，但本仓已用 commit 标识管理，按 owner 指令全清
5. **snapshot 防护快照保留**：R25 reference-transaction hook 设计的孤儿化防护，32 个 snapshot 命名规范清晰（如 fix-p0-r2-round1-20260909-20260909T093621-77386），不主动清
