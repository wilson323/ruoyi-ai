## 2. R34 扫出了什么(大白话)

按 4 种坏法分类,每种给一个具体例子。

### 2.1 脏数据污染 — 测试夹具跑进了真库

**坏在哪**:测试用的假数据被写进了真数据库,而且这些数据看起来和真业务数据一模一样。

**典型例子**:
- `products` 表有 27 条 ACTIVE 的产品,**全是测试名**(像 `P072-xxx`、`QA03-xxx`、`E2E-0911`)。用户在产品下拉框里能看到这些假产品,可能误选。
- `projects` 表有 11 条 ACTIVE 的项目,全是 `QA03-矩阵实测` / `R30验收` / `P132-HARDWARE` 这种测试名。
- 3 个 SUPER_ADMIN 账号同时 ACTIVE,违反"只能有 1 个超级管理员"的公司规则。

**根因**:`2026-09-06-ipd-zk-scenario-seed.sql` 这个 SQL 文件没加防护(`@Profile` 守卫),测试种子数据直接写进 ipd_dev 真库。

### 2.2 配置漂移 — 同一份配置写了两份,改了一边另一边忘改

**坏在哪**:系统里有些配置有两个地方可以改,但代码只读其中一个,另一个就成了"僵尸数据"。

**典型例子**:
- `bonus.poolRate`(奖金池比例)在 `system_configs` 和 `ipd_business_config` 两张表都写了。代码只读 `ipd_business_config`,`system_configs` 那条就是死的。
- `application-prod.yml` 里**直接写了 16 处生产密钥**(justauth 第三方登录用的 client-secret),包括微信/钉钉/支付宝/百度/CSDN 等 11 个渠道的明文密钥。

**根因**:配置表拆分没同步,代码只接一张表,另一张无人维护;生产配置没有从环境变量或密钥管理服务读。

### 2.3 API 契约错位 — 文档写的是一回事,代码做的是另一回事

**坏在哪**:后端 Controller、文档、前端 API 文件这三处对不上,外部对接方按文档集成会全失败。

**典型例子**:
- 后端 `IpdPlatformAuthController.java` 这个文件**在主仓库根本不存在**,只在 8 个兄弟工作区(其他会话临时拉的分支)里有。意思是:`git clone` 主仓代码后编译能过,但 `/api/v1/auth/platform-token` 这个端点会 404。
- 文档 §9.2 写 `POST /api/v1/bonus/calculate`,后端实际是 `/api/v1/bonus-pool/compute`。

**根因**:Agent 并行开发时没合并回主线,文档更新没跟上代码重构。

### 2.4 前端假禁用 + DTO 字段缺位

**坏在哪**:前端按钮看起来 disabled(灰色不可点),其实不是"功能没做完",而是"加载中"或"DTO 缺字段被强行兜底"。

**典型例子**:
- KPI 月数下拉框 6/12/24/36 全 disabled — **其实是 loading 状态**,数据加载完就能点。R33 报告误判为"功能半瘫"。
- 后端 `IpdRequirementChangeController.create()` 直接接 Domain 对象(不是白名单 record),前端可以传 `status='APPROVED'` 绕过双签流程。

**根因**:后端 Controller 没强制入参白名单,DTO 字段缺位时 Service 层自动填默认值(比如把 CRITICAL 事故记成 MEDIUM)。

## 4. R33 的 4 个异常,有 3 个被反转了

R33 报告里说"KPI 月数全 disabled 是 P0 异常",实际上只是 loading 状态;说"allowance.L3 漂移是配置 bug",实际上是验收脚本的高频震荡。每一次反转都是**真实测试**的结果,不是凭记忆。

### 4.1 KPI 月数 disabled → 降级为"UX 优化"

- R33 报告:`kpi/index.vue:129` 月数下拉 4 选项全 disabled = P0
- 真活测试:实测是 `v-loading` 副作用,数据加载完就恢复
- **结论**:不算 P0,只是 UX 上需要 loading 占位提示

### 4.2 allowance.L3 = 1500 → 降级为"高频验收震荡"

- R33 报告:allowance.L3 当前 1500 ≠ 默认 2000 = P0 配置漂移
- 真活测试:`system_config_versions` 19 个版本,2026-09-06~08 共 27 次 SYSTEM_CONFIG_UPDATE 审计记录完整
- **结论**:不是漂移,是 P0-3.3 验收脚本在反复改,**审计链完整无缺失**

### 4.3 `/auth/platform-token` 缺失 → 反转为更深层 P0

- Agent C 初判:这个端点不存在 = P0
- 真活测试:实测 HTTP 200,端点存在
- 反转 → 真正 P0:实现这个端点的 `IpdPlatformAuthController.java` 在主仓**根本不存在**,只在 8 个兄弟工作区里有。意味着 fresh clone 会得到功能残缺的后端

## 5. 深度反思(按 R25 模板的"5 类反复根因"框架)

### 5.1 根因 ①:改主代码后测试没跟上

**症状**:products / projects 写了 27+11 条 ACTIVE 测试夹具,代码改了但没 cleanup。

**治本**:测试 seed 脚本必须强制加 `namespace` 隔离 + `@AfterEach` cleanup hook。

### 5.2 根因 ②:提交不完整 — fresh clone 必炸

**症状**:`IpdPlatformAuthController` 只在兄弟工作区,主仓没合入。CI 拉 fresh commit 编译过但运行 404。

**治本**:merge 前置 gate — 主仓源码树完整性校验脚本(扫所有 Controller 是否在 main HEAD 存在)。

### 5.3 根因 ③:规则表靠人肉对账

**症状**:allowance.L3 改了 19 次没人写 SSOT 钉死;配置双写没人维护。

**治本**:`system_configs` + `ipd_business_config` 合并成一张 SSOT 表 + 改 `BonusPoolService` 读 SSOT。

### 5.4 根因 ④:前后端契约无门禁

**症状**:13 条 §9.2 文档错位 + 6 条 §9.3 错位 + 前端 5 处 disabled 硬编码。

**治本**:写 OpenAPI 生成链 — 后端注解驱动生成前端 TypeScript 类型,文档自动从注解拉。

### 5.5 根因 ⑤:多事实源无对账

**症状**:Runner 写 -1,SQL 写 NULL,test 写真库无 cleanup — create_by 来源 3 套。

**治本**:写 `entity↔真库 drift-check` 门禁脚本(已有),接 CI 卡死三轨不一致。
