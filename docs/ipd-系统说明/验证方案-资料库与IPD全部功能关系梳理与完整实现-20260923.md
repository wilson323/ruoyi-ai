## 二、Fresh 验证基线（2026-09-23 当前真活快照）

下面这些数字是写门禁脚本前现场拉到的初始值，验证方案所有"期望值"都从这里出发。

| 指标 | 当前值 | 说明 |
|---|---|---|
| `ai_documents` 表总行数 | **4** | 项目级 AI 草稿库 |
| `ai_documents` 各状态分布 | GENERATED=2 / REVIEWED=1 / ARCHIVED=1 | 4 篇分别处于不同状态 |
| `ai_documents` 中 `doc_type` 分布 | PRD=2 / DESIGN_REVIEW=1 / 1 篇为空 | doc_type 字段已存在 |
| `ai_doc_embeddings` 表总行数 | **0** | 阶段 1 验收要让这个数字 > 0 |
| `ai_doc_embeddings` 索引现状 | PRIMARY / idx_emb_project(2 列) / idx_emb_doc | **无 `idx_emb_doctype`**（阶段 3 加） |
| `ai_model_configs` 表生效配置 | 暂无 | 阶段 1 实施步骤 0 要先 INSERT 一行 |

**重要对照**：当前 `sources: ["config.disabled"]`——这说明：
1. AI 模型配置还没起来，AI 副驾走的"未启用"短路分支
2. 即使阶段 1 让 `ai_doc_embeddings` 有行数，阶段 2 接 RAG 后 `sources` 才会变成 `["project.history_docs"]`
3. 阶段 2 的验收脚本要在"AI 模型启用 + RAG 已接 + ai_doc_embeddings 有行"三件齐备时才能绿

## 三、阶段 1 验证（RAG 真活触发）

### 3.1 验收目标

让 `ai_doc_embeddings` 表行数从 0 变成 ≥ 1，证明 `embedAsync` 真活流程跑通了。

### 3.2 三证律验证

**证 1：DB 回读**

```bash
mysql --defaults-file=.codex/ipd-dev/config/mysql-client.cnf \
  -e "USE ipd_dev; SELECT COUNT(*) FROM ai_doc_embeddings;"
```

期望：返回 `> 0`。当前是 `0`。

**证 2：后端日志**

```bash
grep -E '\[AI-STRAT-1\] 向量化完成' \
  /Users/mac/Documents/ruoyi-ai/.codex/ipd-dev/runtime/app-*.log | tail -5
```

期望：看到至少一行 `向量化完成: docId=... projectId=... model=... chunks=...`。

**证 3：浏览器截图**

打开超管后台 → AI 文档管理 → 找一篇 `status=REVIEWED` 的文档 → 截图看页面状态。
或打开 DB 客户端工具连 `ipd_dev.ai_doc_embeddings` → 截图看至少 1 行。

### 3.3 实施前置（写代码的人要做的）

1. 在 `ai_model_configs` 表 INSERT 一行 `is_active=1` 的配置，`config_json` 含 `embedEndpoint/embedModel` 两键
2. 找一篇 `status='GENERATED'` 的 `ai_documents`（共 2 篇：id=2097190178236985345 / id=2097867527915900930）
3. 调 `AiDocumentService.review(versionId, operatorId)` 触发审核（versionId 是上一步的 id，operatorId=900101 超管账号）
4. 审核通过后，`AiDocumentService.review()` 调 `docEmbeddingService.embedAsync()` 异步向量化
5. 等 5-10 秒，DB 回读确认行数 > 0

### 3.4 阶段 1 门禁脚本

见 `scripts/check-rag-docType-20260923.sh`（包含行数检查 + 索引检查两个职责合一）。

## 四、阶段 2 验证（AiCopilotService 接 RAG）

### 4.1 验收目标

`AiCopilotService` 调 `retrieveContext` 后，HTTP 响应 `data.sources` 数组里出现 `project.history_docs` 这个来源标识。

### 4.2 三证律验证

**证 1：HTTP 响应**

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:16039/api/v1/auth/login \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data-binary '{"username":"ipd-admin","password":"Ipd@123456"}' \
  | grep -oE '"token":"[^"]+"' | head -1 | sed -E 's/"token":"//; s/"$//')

curl -s -X POST http://127.0.0.1:16039/api/v1/ai-copilot/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data-binary '{"projectId":"9140001","message":"历史文档里这个项目有什么？"}' \
  | grep -oE '"sources":\[[^]]*\]'
```

期望：响应里 `sources` 数组含 `"project.history_docs"`。
当前是 `["config.disabled"]`——不达标。

**证 2：DB 回读**

阶段 1 通过后，`ai_doc_embeddings` 至少 1 行，且 `project_id` 等于 9140001（与 HTTP 请求的 projectId 一致）。

**证 3：浏览器截图**

打开前端 → 选项目 9140001 → 打开 AI 副驾 → 输入"历史文档" → 截图看回答下方"参考来源"标签。

### 4.3 实施前置（写代码的人要做的）

1. `AiCopilotService` 构造函数加 `AiDocEmbeddingService docEmbeddingService` 参数
2. `chitchatPath` 在 `composePrompt` 之前调 `retrieveContext`
3. `composePrompt` 加 `String ragCtx` 参数，prompt 里加"【项目历史文档（RAG）】"块
4. 把 RAG 上下文块作为第三个 sources（命名 `"project.history_docs"`）

### 4.4 阶段 2 门禁脚本

见 `scripts/check-copilot-rag-20260923.sh`。

## 五、阶段 3 验证（retrieveContext 分 docType）

### 5.1 验收目标

`retrieveContext` 加 `String docType` 参数后，DB 层面有 `idx_emb_doctype` 索引支撑过滤，避免全表扫描。

### 5.2 三证律验证

**证 1：DB 索引检查**

```bash
mysql --defaults-file=.codex/ipd-dev/config/mysql-client.cnf \
  -e "USE ipd_dev; SHOW INDEX FROM ai_doc_embeddings;" \
  | grep -E 'idx_emb_doctype'
```

期望：返回 1 行（或更多），含 `Key_name=idx_emb_doctype, Column_name=doc_type`。
当前是**无匹配行**——索引不存在。

**证 2：DB 真活盘点**

```bash
mysql --defaults-file=.codex/ipd-dev/config/mysql-client.cnf \
  -e "USE ipd_dev; SELECT doc_type, COUNT(*) FROM ai_doc_embeddings GROUP BY doc_type;"
```

期望：至少 1 个 doc_type 有行数 ≥ 1。

**证 3：单测**

`AiDocEmbeddingServiceTest.retrieveContext_filterByDocType` 单测验证：
- 同一 projectId 下插入 docType=PRD 和 docType=MRD 各 2 条
- 传 docType=PRD 时只返回 PRD 的 2 条
- 传 null 时返回所有 4 条（向后兼容）

### 5.3 实施前置（写代码的人要做的）

1. 先 DDL：`CREATE INDEX idx_emb_doctype ON ai_doc_embeddings(doc_type);`
2. `AiDocEmbeddingService.retrieveContext` 加 `String docType` 参数
3. SQL 查询加 `eq(AiDocEmbedding::getDocType, docType)`（docType 非 null 时）
4. `AiGenerationService.generate()` 调 retrieveContext 时传 `req.docType()`
5. `AiCopilotService` 调 retrieveContext 时传 null（向后兼容）

### 5.4 阶段 3 索引检查归入总脚本

阶段 3 的 DB 索引检查并入 `scripts/check-rag-docType-20260923.sh` 一起做，避免脚本爆炸。

### 7.1 阶段通过条件（三件齐备才翻绿）

### 7.2 误报抑制（避免假绿）

- 门禁脚本默认连 `127.0.0.1:16039` 和 `ipd_dev` 库，环境变量可改
- 自证能红：每个脚本支持 `FAIL_SEED=1` 强制失败一次（用于开发期验证脚本不假绿）
- 输出格式严格区分：`SCRIPT_FAULT`（脚本自身故障，误报）vs `BUSINESS_FAIL`（业务真问题）
