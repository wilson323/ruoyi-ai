**真实结论**：权限码常量**严格遵守单一事实源**（IpdPermissionCode 接口）。仅 2 个死配置待清理（属于预留位/规划中）。

### 2.2 鉴权机制分布（单一事实源复核）

| 维度 | 数 | 单一事实源判定 |
|---|---|---|
| `@SaCheckPermission` 注解 | **223 处** | ✅ 唯一权限拦截方式 |

**真实结论**：**后端只有一套权限拦截机制（Sa-Token + IpdPermission 工具类）**，没有多套混用。这条**纠正了 R185 收口汇报的失真**。

### 2.3 多租户白名单（双轨风险）

| 维度 | 数 | 判定 |
|---|---|---|
| `application.yml` 的 `tenant.excludes` 表白名单 | 31 张表 | **唯一事实源** |
| `@InterceptorIgnore(tenantLine="true")` 类级关掉 | **2 处**（AiModelConfigMapper、AiDocEmbeddingMapper）| ⚠️ **真实双轨** |
| `@TenantIgnore` 注解 | 0 处 | 不存在 |
| `TenantFilter` / `TenantInterceptor` 自定义类 | 0 处 | 不存在 |

**真实双轨点**：

- `tenant.excludes`（白名单在 yml）与 `@InterceptorIgnore(tenantLine="true")`（类级注解关掉）**是两个并行的事实源**
- 注释明确写"31 张 excludes 表的同类问题修法对齐本注解"——本意是统一用 `@InterceptorIgnore` 替代 `tenant.excludes`，但目前 2 个 mapper 用了 `@InterceptorIgnore`、其他 31 个表仍在 `tenant.excludes`，未收敛到单一事实源

**根除方向**：要么全部用 `@InterceptorIgnore(tenantLine="true")`（类级标注）+ 删除 `tenant.excludes`，要么反过来。建议走 `@InterceptorIgnore` 路线（已在代码注释中表态），收敛后只需 grep "InterceptorIgnore" 就能列出全部豁免表，不必再维护 yml 列表。

### 2.4 审计机制（双轨 + 冗余实现）

| 维度 | 数 | 判定 |
|---|---|---|
| `@IpdAudit` AOP 注解 | **3 个文件** | 用得少 |
| `audit(operator, action, ...)` 工具调用 | **5 个文件**（PersonSyncController / PersonController / HrSyncController / CoefficientChangeService / LaunchDateChangeService）| ⚠️ **真实双轨 + 5 份重复实现** |
| 全仓 audit 调用次数 | **74 处** | 散落 5 个文件 |

**真实双轨点**：

- `@IpdAudit` AOP 是声明式（一行注解搞定），`audit()` 工具调用是命令式（手动传 4 个参数）
- **5 份私有 `audit(...)` 方法实现几乎完全相同**——同一段 `auditLogService.append(AuditLog.builder().operatorId...action...entityId...reason...)` 模板被复制粘贴 5 次
- 3 份用 `IpdActor` 参数，2 份用 `Long operatorId`——签名不统一，调用方需要在 actor / id 之间手动转换

**根除方向**：抽 `AuditHelper` 单一工具类（接受 actor 或 id 参数，内部自动判断）+ 把 5 份私有实现替换为调用。或推 `@IpdAudit` AOP 全覆盖（74 处 audit() 全部加注解，aop 自动写审计）。

## 四、本轮工作的自我反思（失真→纠正→对账）

### 4.1 R185 收口汇报失真的根因

1. **违背 Fresh 验证铁律**——汇报时没跑 grep 现查，凭上一轮记忆直说
2. **把"语义相关字面量匹配"当真实证据**——grep 用 `TenantIgnore\|TenantFilter\|tenant.excludes` 复合模式，把所有含 "tenant" 字面的代码都算成"多套闸"，但实际只有注释里有这个词
3. **没分类就下结论**——46 controller 的统计本身没问题，但没区分"含此关键字的 controller 数"和"实际混用多套注解的 controller 数"

### 4.2 本轮对账方法学的核心教训

- **comm 命令要看上下文**——当两边行数相同时，comm 输出"全空"可能是因为用反了参数，要用 diff 直接对比
- **正则要锚定边界**——`grep -E '[A-Z_]+'` 会把 `OPERATION_PRODUCT_GROUP` 切成 `OPERATION_P` + `RODUCT_GROUP`，必须用 `[A-Z][A-Z_0-9]*` 加首位字母大写约束
- **comm 的 `-23` 是"第一个文件独有的"，`-13` 是"第二个文件独有的"**——之前记反了，导致假空集
- **所有"未找到"结论都要二次复核**——本轮 comm 第一次输出"空"我没立即怀疑是命令错，是后面重新 diff 才看出问题

### 4.3 R186 工作建议（基于本轮真实对账）
