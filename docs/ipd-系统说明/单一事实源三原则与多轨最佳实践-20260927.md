## 3. 三原则逐条深析

### 3.1 原则一：单一事实源 = 头号原则（成立；残余清单见 §5 表）

盲签的同构性论证严密：盲签防的是**两个评判者共享中间态**导致的相互污染；双源病是**两个事实源共享同一消费方**导致的相互覆盖。药方同为「隔离或定序」：

- **隔离**（消除双源）：C0 择一、死配置删除、F1 把工作树真相并入 main；
- **定序/适用域**（双源合法化）：三套引擎 ADR 补编「IPD 制度性审批留自研 guard / 通用行政流走 ruoyi-workflow / 两者不得互写状态」；tenant.excludes 主路径 + @InterceptorIgnore 兜底被 R186-② 复核判定为**分层防御而非双轨**——说明「消双源」前必须先做 Fresh 验证分清「真双轨」与「主路径+兜底」，误收敛同样是污染。

### 3.2 原则二：按可逆性分流审批（已实质落地，边界待成文）

现状已经形成三态，建议明文固化进 AGENTS.md / CLAUDE.md：

| 态 | 定义 | 通道 | 现例 |
|---|---|---|---|
| 可逆 | 文档勘误、已验证偏差追认、当日成果入库、dev 库 apply（有备份表+幂等） | **owner 常令自动收口**，不等单独拍板 | F1 六批次、F3 偏差追认、R238 F2 apply（先建 agent_info_bak_r236） |
| 不可逆 | 业务语义（C0/C1/C2）、生产写、权限语义变更、git 历史重写、删分支 | 单独会审/授权，AI 只备料不代拍 | C0 会审、空 commit 历史清理「高风险禁自动」、生产 SQL 待 DBA 窗口 |
| 追认窗口 | 先入库后拍板的既成事实 | 留痕 + 追溯账 + 明确追认或回退 | 盲签批（R238 ⑥）、b62a99e6 错账回退收编 |

**常令边界三问（建议 owner 一句话明确）**：①覆盖对象是否含前端在途批（今日 17:52 批即适用样本）；②门禁 FAIL 时是「自动回退 staged 留工作树」还是「停下等人」；③与 OPS-09 单一写入者的优先级——建议表述为「常令授权的是**收口动作**，不解除**批次归属登记**：谁验证谁收口，撞车走透明披露（R237/R238 双通道先例），不做历史重写」。

### 3.3 原则三：裁决在上，代码在下（方向正确；需给既成事实建追溯账）

理想态是「未拍板业务模型的实现只进草稿区（worktree/branch）不进 main」。现实偏差已发生：盲签批进 main 属 F1 全批授权追认。纠偏不建议回滚（授权链完整、契约测试本身是资产），而是补两件机制：

1. **裁决前入库追溯账**（本条即首笔登记）：每笔「裁决前入库」记录 hash、受影响文件、依赖裁决的分叉点、拍另一方向时的回退成本。盲签批的分叉点：GateReviewService 双签盲签语义按 SPEC69 实现（MARKET_PM+RD_PM 并行，与原型 100% 对齐，R232 §2 核查）；若 C0 拍 PROTOTYPE37 为主基准，五节点顺序签需新增链路，双签盲签降级为子场景——回退成本中低（领域服务保留，编排层改），AiCardBlindSignContractTest 527 行需按新口径改写断言。
2. **BLOCKED_C0 依赖标签**：凡下游卡（C1 waiver 口径、C3 waiver 全链、C4 聚合器、奖金核算、L6 制度文本）在看板与镜像标 `BLOCKED_C0`，裁决前禁止新开扩大受影响面的实现卡——这就是「不进 main」在多轨现实下的可行等价物（进 main 可以，但**停止生长**）。

## 4. 多轨最佳实践 Playbook（8 条，全部来自实测教训）

1. **批次是收口单位，不是会话**：F1 证明按批次分批精确纳管、每批独立 commit 带 marker、禁 `git add -A`，可在多会话并发下当日清空 6 批次；反之多批次堆同一共享工作树，每一批都是下一批的回退引信（8.4 三起事故同根因）。
2. **共享 index 是危险区**：commit 前必 `git diff --cached --stat HEAD` 自查陈旧 blob（log.md 陈旧 index 引信实测）；跨 worktree 写操作前必 `pwd && git rev-parse --show-toplevel`（09-09 落错分支事故）。
3. **竞态透明而非互斥**：temp-index + commit-tree + update-ref CAS，失败即弃用悬空对象、不 prune、不历史重写；撞车后转独立复核者（R237/R238 双通道先例）。多轨的并发冲突不可能靠锁消除，靠「谁先落地谁算数 + 后者复核留痕」收敛。
4. **执行者与验证者分离按轮轮换**：R238 由非执行会话做 fresh-clone 模拟复核（wiki-lint 126/0/0、2946 绿），Validator 不依据 Executor 总结。多轨下每个会话都既是某轨的执行者又是他轨的验证者。
5. **接手三步法**（R25 软化后）：逐文件处置结论（原样/修改/还原）→ SSOT+log 登记接手事实与 commit 号 → 兄弟编号 `ORIGIN-` 前缀保留史实。LC03 让码协调（42→41 行制重排、R236 契约零改写）是满分样板。
6. **登记先行**：向任何持久化载体写可精确验证的事实必现查现写（五必现查规约）；「拍板登记 ≠ 拍板执行」，AI 侧交付到「可 apply 材料 + 建议选项 + 待拍标注」为止（C 批次 SQL 草稿先例）。
7. **门禁必须自证能红**：FAIL_SEED 双向触发标配；门禁 FAIL ≠ 真异常，需分诊设计误判/真异常/环境问题（R238 门禁 0 wiki 交叉引用属真拦截、门禁 1/2 连库 286s 属瞬时假性拦）。假红处理是错峰+单模块复跑，不是绕闸。
8. **双源要么消灭、要么声明适用域，禁止无声明并行生长**：判定顺序 = Fresh 验证（分清真双轨 vs 分层防御）→ 能消则消 → 不能消则写适用域登记（一页边界登记 + 会红的对账脚本）。
