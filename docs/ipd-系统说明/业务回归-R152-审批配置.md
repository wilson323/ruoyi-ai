# R152 C 业务回归 — 场景 D：超管维护审批配置

**文档版本**：v1.0 · 2026-09-21
**对应接口**：`GET /api/v1/business-config` · `POST /api/v1/business-config` · `DELETE /api/v1/business-config`
**对应真库表**：`ipd_business_config`（R149 batch2b A5；scope=GLOBAL/GROUP/PROJECT 三档）
**适用角色**：产品组长 / 超管（`ipd-leader` / `ipd-admin`；密码均为 `Ipd@123456`）；读权限开放给全部内部角色
**对应前端页**：`/ipd/admin/business-config`（系统管理 → 审批配置 / 业务参数）

---

## 1. 业务方操作步骤（按截图定位）

### 1.1 选 scope + scopeId

| 步 | UI 区域 | 操作 |
|---|---|---|
| 1 | 浏览器 | 登录 `http://127.0.0.1:15800/login`（超管 `ipd-admin / Ipd@123456`） |
| 2 | 左侧菜单 | **「系统管理」** → **「审批配置」**（业务参数） |
| 3 | 顶部下拉 | 「Scope」选 `GROUP`（维度档位：GLOBAL/GROUP/PROJECT） |
| 4 | 顶部输入 | 「Scope ID」填 `1001`（产品组 ID） |
| 5 | 顶部按钮 | 点击 **「查询」**；表格列出该 scope 下已有配置 |

### 1.2 编辑 / 新增 3 条配置

| 步 | UI 区域 | 操作 |
|---|---|---|
| 6 | 表格行 1 | `kpi.approvalRole` 行点击 **「编辑」**；弹窗输入新值 `GROUP_LEADER`，确认 |
| 7 | 顶部按钮 | 点击 **「新增」**；弹窗填：`configKey=scenario.approvalRole`，`configValue=SUPER_ADMIN`，确认 |
| 8 | 顶部按钮 | 再点 **「新增」**；弹窗填：`configKey=bonus.approvalRole`，`configValue=SUPER_ADMIN`，确认 |
| 9 | 表格区 | 3 行配置全部就位：`kpi.approvalRole / scenario.approvalRole / bonus.approvalRole` |
| 10 | 顶部 toast | 弹「保存成功」 |

> **重要**：scope_id 必须用 **字符串**（VARCHAR(64)），表中存在数字写入变 NULL 的已知 bug
> （见 curl 实测 4.3）；业务方手填数字框时前端应做 `String()` 强转。

## 2. 期望 HTTP 响应

### 2.1 查询 GROUP/scopeId=1001 下所有配置（HTTP 200）

```bash
curl -sS 'http://127.0.0.1:16040/api/v1/business-config?scope=GROUP&scopeId=1001' \
  -H "Authorization: Bearer <token>"
```

**响应体**（实测 2026-09-21 / 16040）：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "scope": "GROUP",

      { "id": "14", "configKey": "kpi.approvalRole",      "configValue": "GROUP_LEADER", "scope": "GROUP", "scopeId": "1001", "enabled": 1, "version": 1, "cacheTtl": 300 },
      { "id": "15", "configKey": "scenario.approvalRole", "configValue": "SUPER_ADMIN",  "scope": "GROUP", "scopeId": "1001", "enabled": 1, "version": 1, "cacheTtl": 300 }
    ]
  },
  "timestamp": "..."
}
```

### 2.2 POST 写入/更新（HTTP 200）

```bash
curl -sS -X POST http://127.0.0.1:16040/api/v1/business-config \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "scope": "GROUP",
    "scopeId": "1001",
    "configKey": "kpi.approvalRole",
    "configValue": "GROUP_LEADER",
    "description": "R152 C 业务回归测试"
  }'
```

**响应体**（实测；update 命中 id=14）：
```json
{
  "code": 0,
  "message": "ok",
  "data": { "id": "14", "configKey": "kpi.approvalRole", "invalidated": "true", "scope": "GROUP", "scopeId": "1001" }
}
```

**新增 bonus.approvalRole 响应**：
```json
{ "code": 0, "message": "ok",
  "data": { "id": "2101935008645181442", "configKey": "bonus.approvalRole", "invalidated": "true", "scope": "GROUP", "scopeId": null } }
```

> ⚠ 注意：`scopeId=null` 是已知行为 — JSON 数字 `1001` 被 MyBatis 当 BIGINT 写，
> schema VARCHAR(64) 触发隐式转换后入库为 NULL。前端表单需做 `String(scopeId)`。

### 2.3 异常路径

| 异常 | HTTP | code | message |
|---|---|---|---|
| 缺 `scope` | 400 | 10001 | `scope 不能为空` |
| 缺 `configKey` | 400 | 10001 | `configKey 不能为空` |
| 未带 Token | 401 | 20001 | `未认证或凭证失效` |
| MARKET_PM 角色写入 | 403 | 20003 | `无操作权限`（`requireLeaderOrAdmin`） |

## 3. 真库验证 SQL

```sql
-- GROUP/scopeId=1001 配置核验（步骤 9 完成后应见 2 行；scopeId='1001' 字符串匹配）
SELECT id, scope, scope_id, config_key, config_value, del_flag
  FROM ipd_business_config
 WHERE scope = 'GROUP' AND scope_id = '1001' AND del_flag = 0;
-- 实测：
-- id=14 | kpi.approvalRole      | GROUP_LEADER
-- id=15 | scenario.approvalRole | SUPER_ADMIN

-- bonus.approvalRole 由于 scopeId=null 不在上述结果集
SELECT id, scope, scope_id, config_key, config_value FROM ipd_business_config
 WHERE config_key = 'bonus.approvalRole';
-- id=2101935008645181442 | scope_id=NULL ← 已知数字→字符串转换 bug
```
