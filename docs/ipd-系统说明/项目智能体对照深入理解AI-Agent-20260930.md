## 1. 裁决

三条投诉各自对应的原则如下。原则来自书，落点来自上面这些 IPD 文件。

### 1.1 没有交互按钮

书的原则有两条，而且必须是代码闸门，不是提示词自觉。

- **「任务理解与需求澄清」和「编写设计文档」**（第 5 章 5.1.3）：边界清楚的小改动可以直接做。需求含糊、路径很多、或影响面很宽时，必须先问人。设计写完要交给人审查，**等批准后再继续**。在含糊状态下动手，书里写成会大量返工。
- **「护栏与安全性 · 人工干预」**（1.2.5.2）和执行层护栏（1.2.5.1）：高风险、不可逆动作要在动作生效前由上下文之外的机制复核（人在回路、沙盒、最小权限）。提示词里的「不要做」只降低概率，消融实验（1.1.4）写明：模型没有工具时仍会给出排版完整的答案，约束「并不能消除」编造。第 5 章 5.1.4 把同一句话说成工程原则：**能用代码强制的规则不要写成「请遵循」**。

IPD 落点：`ProjectAgentIntent.decide` 在模型之前用原文、动作码和技能「## 步骤」做确定性判断。选择型「还是」变成带「」的一句问题；套话走固定问句。`prompt()` 仍把「不要调用工具」写进系统提示，但 `ProjectAgentRunExecutor.start` 在 `publishIntent` 之后**不再无条件** `kernel.execute`：`shouldAwaitUser` 为真时 `awaitUser` 把状态改成 `WAITING_APPROVAL`，再写 `STEP` `kind=AWAIT_USER`，然后 return。澄清（问题列表非空）和未绑定动作的自由计划会停。已绑定动作的计划、以及第一行恰好是「按已确认计划执行」且后面至少有一行步骤的消息，仍会执行内核。

界面按钮已经挂在 `intent-card.vue`：澄清选项、未绑定计划的「开始执行 / 先改范围」。点击分别走 `answerClarification` / `confirmPlan`，都是取消等待中的运行后再 `create`，不新开会话协议。WorkBuddy 稿第 1 节、第 6.7 节写的「publishIntent 之后无条件 kernel.execute」「根本没有闸门」对**本次读到的执行器已经过时**。稿第 10.1 节要求澄清卡在闸门未接通时显示「执行前切断尚未接通」；代码里的 `clarificationStillGenerating` 只在没有 `AWAIT_USER` 且已经写出正文或工具时才说「判定为先澄清，当前仍会继续生成。」有等待步骤时不说这句话。

### 1.2 输出很乱

书把一次模型回复拆成三块，不把它们当成一段话（1.1.4）：思考（reasoning）、给用户的文本（content）、工具调用（tool_calls）。给最终回答时通常是思考加正文；决定动手时通常是思考加工具调用。1.2.2「保持透明」要求把规划步骤、执行日志和决策轨迹明示给用户，因为黑箱错误外面无法纠正。5.2.5 说明纯文本线性对话在「要选项、要看关系」时不可读。6.2.4 进一步说：有的产品把模型的全部 assistant 话直接倒给用户，用户被迫在同一会话里看工具过程；更好的沟通工具是**单独的发送通道**，而不是把轨迹原文当回复。

IPD 落点：事件类型已经拆开（`STEP` / `TOOL_CALL` / `TOOL_RESULT` / `TEXT_DELTA`）。`timeline-model.ts` **没有丢掉** INTENT 的 `questions` / `steps`（`intentView` 用 `stringList` 保留纯字符串数组）。`timelineTranscript` 仍只拼接 `kind==='text'`，供右侧一个 `AssistantTurn`。中间 `run-timeline.vue` 按条目分身：意图卡、步骤、工具卡、正文。乱的来源是对话栏把模型正文（含未拆干净时会掉进回答的 `<think>`）收成一只气泡；`model-message.ts` 已经循环剥全部 `<think>`，避免后段思考整段掉进回答。工具和计划不应该再进这只气泡。

### 1.3 不是流式机打

书里的「流式」是模型输出顺序和传输，不是事后播放动画。

- 第 2 章实验 2-1 的观察第 4 点：流式输出让用户实时看见思考、工具决策和结果处理。同一节「输出的顺序结构」：token 先是 `<think>`，然后是给用户的正文，最后是工具调用。实现要点是 **`<think>` 一出现就切到思考状态**；**第一个工具调用参数完整并通过校验就执行**，不必等模型把后面的工具也生成完。5.1.6 把「等一个工具做完再生成下一个」写成传统串行浪费。
- 后记「第一朵乌云」：今天多数 Agent 仍是按轮次的「想一整段，再一次性吐出结果」。书把这视为未解决的实时性缺口，并把它和「边想边说」对照。书没有定义界面上的假打字机。

IPD 落点：`ProjectAgentRunHandle.onText` 把模型增量先放进缓冲。满 `TEXT_FLUSH_CHARS`（200）或距上次落库达到 `TEXT_FLUSH_INTERVAL_MS`（120 毫秒）才写一条 `TEXT_DELTA`，payload 字段是这段缓冲的 `text`。这不是逐 token 写库，也不是运行结束才写一整段。前端轮询事件，时间线把连续 `TEXT_DELTA` 合并成一块。`assistant-turn.vue` 的 `pace` 只揭示**已经收到**的前缀（`text-reveal.ts`：不补字）。本次读到的右栏 AI 气泡和中间正文都传了 `pace`。机打应绑在这层揭示上；副驾 classic 已逐 token，注释写明不要再开 pace。

## 2. 澄清与选项：落在现有三栏

不新开布局。左历史、中本次运行、右对话，顶栏六阶段只切浏览，与 WorkBuddy 稿第 5 节一致。书没有这套三栏，下面是把 5.1.3 和 5.2.5 安到已有栏位上。

### 2.1 什么时候必须问人

按 5.1.3，简单、影响面小的请求直接做。必须问的是：用户说不清要什么、存在多种做法、或一改会碰到很多块。IPD 不把这个判断再交给模型。`decide` 已经收敛成三类：

| 输入 | 结论 | 还问不问 |
|---|---|---|
| 空或套话（看看 / 做一下 / 继续 / 你好） | 澄清，步骤空 | 必须问；问句是固定的交付与范围，不是散文 |
| 选择型「还是」（两侧各 2～12 字，排除「还是要 / 继续 / 需要 / 先」） | 澄清，一句带成对「」的问题 | 必须先选定一侧 |
| 已绑定动作且技能有「## 步骤」 | 计划，步骤逐字来自技能，最多 8 条 | 不问；卡片只展示 |
| 未绑定且多条动词分句 | 自由计划 | 先给人看步骤，确认前不执行 |
| 第一行逐字「按已确认计划执行」且其后至少一行非空 | 计划，步骤即这些行 | 这是上一次确认的回传，直接执行 |
| 其余短请求 | 直答 | 不问，也不先写计划 |

「还是要做竞品分析」按现有规则**不算**选择，不会为此停下来。这是代码，不是书里的泛泛「含糊就问」。

### 2.2 问题怎么变成选项，而不是一段散文

5.2.5「澄清用户意图」：纯文本一问一答轮次多，选项之间的依赖也说不清。书建议一次结构化提交（下拉、单选、复选、日期），选「往返」才出现返程。实验 5-12 的验收是一张表单一次提交，再带着结构化字段继续执行。

IPD 不让模型现场生成 HTML（见第 5 节）。选项用已有按钮，数据只来自 INTENT 的 `questions` 字符串：

- 一句里有至少两个「」：每个引号内的词是一颗按钮（`clarificationChoices`）。原句可以留一行，避免选项离开原话。
- 没有成对引号：整句是一颗按钮。这仍偏长。下一期渲染若还要更像书里的控件，应把固定问句改成短选项文案，**不要**在按钮上展示整段说明书。这一步是文案，不是新事件。

### 2.3 按钮出现在哪一步，点下去怎么走

| 栏 | 放什么 | 不放什么 |
|---|---|---|
| 左历史 | 运行列表、产物、定档。澄清按钮不放这里 | 提问原文、选项点击日志 |
| 中本次运行 | 意图卡：澄清选项或计划步骤。发送后切到这一栏（`presentProjectAgentResult` 在 `started` 时 `focusPane('cards')`） | 项目小阶段页（那是顶栏浏览，和本次运行互斥） |
| 右对话 | 同一张意图卡，放在正文气泡上面。点选项或「开始执行」仍调面板已有方法 | 不要把选项画成聊天气泡里的一段话 |

未确认时：

- 澄清，或未绑定动作的计划：执行器不调用内核，不写工具、不写产物。界面只显示问题和按钮。用户没点、也没另发一句之前，没有正文。
- 已绑定动作的计划：书的「等设计批准再写代码」**不覆盖**这条。步骤来自技能，WorkBuddy 稿 6.8 规定展示后直接执行。按钮只有说明句「步骤来自动作技能，本次按此执行」，没有「开始执行」。
- 拒绝 / 先改范围：`revise` 只把焦点放回现有输入框，不创建运行。取消走已有 cancel。不在卡片里改同一条事件。

点选项：`chooseClarification` 把选项留在输入框，发送正文是 `已选：{option}。{问题短句}`，经 `answerClarification` → `submitText` → 现有 create。若等待中，先 cancel。新运行只存摘要和字数，不存提问原文。客户端必须把选项写进新 message，因为旧原文不在库里（WorkBuddy 稿第 7 节，与本次 `clarificationSendText` 同向）。点「开始执行」：新 message 第一行固定「按已确认计划执行」，后面每行一条事件里的步骤原字，且去掉 `actionCode`（`confirmPlan`）。不另存提示词原文。

## 3. 输出分层

五层都不进「最终答复」气泡。气泡只放模型给用户的 content，并且已经剥掉 `<think>`。

| 层 | 出现位置 | 禁止 |
|---|---|---|
| 思考 | 中栏与右栏正文组件内部的折叠「思考」。未闭合时展开，闭合后一行标题，正文在限高区 | 禁止进 summary 以外的气泡正文；禁止把推理原文另存库（现有内核约定：思考只以正文里的 `<think>` 出现在事件文本中） |
| 工具 | 中栏本次运行的工具卡（`tool-call-card`）。右栏若要看见，复用同一事件数组的工具卡，放在意图卡和正文之间 | 禁止把 `TOOL_CALL` JSON 拼进 `timelineTranscript` |
| 澄清选项 | 意图卡上的按钮。中栏、右栏同一张卡 | 禁止写进助手正文；未点选前不生成回答 |
| 计划步骤 | 意图卡的有序列表，状态点只根据已有事件（正文已开始则最后一步「执行中」，成功终态全「已完成」） | 禁止把步骤再写进模型正文让用户当计划读；禁止写 `plans/PLAN.md` |
| 正文 | 只含 `TEXT_DELTA` 拼出的用户可见回答。中栏按事件一块，右栏 `timelineTranscript` | 上面四层任何一层混进来都算气泡被撑破 |

`timelineTranscript` 继续只服务正文。意图用 `intentFromEvents`，不要从转录里抠问题。

书的 2.6「Agent 状态栏」是给**模型**看的（轨迹末尾的 TODO、工具计数），不是第五层用户界面。不要把 `<agent_status>` 画进聊天气泡。用户看得见的状态已经是运行状态、意图卡和工具卡。

6.2.4 的 OpenClaw 把工具细节藏起来。IPD 不采用。1.2.2 要求轨迹可见，WorkBuddy 稿要求中间栏工具卡。藏工具和「不把工具倒进正文」不是一回事：工具单独成卡，正文里没有。

## 4. 流式：TEXT_DELTA 与揭示层

书的增量对应 IPD 的模型 `onText` 增量，落库形态是 `TEXT_DELTA`。

后端现在不是「等整段再刷」，也不是每个 token 一条事件：

- 缓冲满 200 字，或 120 毫秒到了且缓冲非空，写一条 `TEXT_DELTA`。
- 其它事件插入前会 `flushText`，避免半段卡在缓冲里。
- 终态前再刷一次。
- 取消探测命中则不再写。

所以用户看到的增长取决于轮询（面板默认间隔在 `use-project-agent-run.ts`，本次未改）加上这些块的到达。慢速吐字时 120 毫秒一截，界面不该空白到结束。一次模型如果很快吐完并在终态一次刷出，观感会接近整段，那是块的大小，不是又等了一份假文本。

UI 揭示（`pace`）绑在**已经落进事件的真实字符串**上：每次最多 6 个已有字符、16 毫秒一拍，必须是全文前缀，模型没写过的字不出现。历史回放若不再处于流式，组件注释写明直接显示全文，避免打开旧运行再假打一遍。

不要做的：

- 不要在没有新 `TEXT_DELTA` 时循环打省略号冒充模型。
- 不要把副驾 SSE 的逐 token 和项目智能体的块混成一条发送路径。AI 模式只走 create run。
- 书里的「工具参数刚校验完就执行」属于内核与工具闸门，不是揭示层能假装出来的。

## 5. 和 WorkBuddy 稿的重合与冲突

IPD 硬边界优先：不能上网、不能跨项目、不能代写 Gate、不能存原文、不新增事件枚举、不开 Plan Mode、不写 `plans/PLAN.md`。书与稿冲突时按这个顺序。

### 沿用

- 三栏和顶栏六阶段不动。意图用现有 `STEP` `kind=INTENT`，等待用 `kind=AWAIT_USER`，不新增 `AgentEventType`。
- 先判定再执行。提示词里的「不要调工具」不够。执行器已按稿 6.7 / 6.8 的方向接上：澄清或未绑定计划停在 `WAITING_APPROVAL`。
- 选项和「开始执行」都是下一次 create。取消旧的等待运行，事件不回写。新 message 带上选项或步骤原字，因为库里没有原文。
- 已绑定动作的步骤以技能「## 步骤」为准，不等人改写，也不让模型另写一份计划盖掉它。
- 定档仍是「待审核」，索引不是就绪。Gate 结论不由智能体写。
- 思考折叠、正文限高、发送后切到本次运行：稿 5.2 / 5.3 / 10.1。本次读到的右栏已有意图卡、`pace` 和 `focusPane('cards')`。

### 以 IPD / 已落地代码为准（稿里的「现状」过时）

稿写于同一天更早的读盘。本次执行器和 `timeline-model.ts` 已经：

- 保留 questions / steps，而不是只留 title / detail。
- `publishIntent` 之后按条件跳过 `kernel.execute`，而不是无条件执行。
- 澄清选项和未绑定计划按钮已经走到 create，而不是「闸门未接通前只让用户自己再打一段」。

稿 10.1 的诚实句「执行前切断尚未接通」只适用于**事件证明内核仍在写**的旧运行。新运行若已有 `AWAIT_USER`，界面应显示等待，不要继续贴那句。否则用户会以为系统没停，和执行器事实相反。

### 以 IPD 硬边界为准（书让路）

| 书 | 冲突 | 以哪边为准 |
|---|---|---|
| 5.2.5 让模型生成 HTML 表单甚至整页应用来澄清 | 生成的界面可执行脚本，书自己也在同节用 A2UI 说明：只输出组件清单，客户端用受信任组件渲染；AG-UI 是事件流，不是界面语言 | IPD：不用生成 HTML。用现有 Vue 按钮和意图卡。这符合书里「受信任组件目录」，不符合「现场写 form」 |
| 5.2.5 用自然语言生成 SQL 再在前端执行 | IPD 不能给模型一条可写库的旁路，也不能代查别的项目 | 不落地。检索仍走本次 `toolIds` 里的项目知识工具 |
| 5.1.3 凡是设计都等人批准再改文件 | 已绑定动作的步骤是技能权威，等人等于第二套计划 | WorkBuddy 6.8：绑定了就展示并执行。未绑定才等「开始执行」 |
| 6.2.4 用户不必看见工具 | 和 1.2.2 透明、以及中间栏工具卡冲突 | 工具单独成卡，不进正文；不藏成只有一句秘书口吻 |
| 6.2.5 虚拟机、上网、多渠道召回 | 直接违反不能上网、不能跨项目 | 不做 |
| 后记：用更快的 decode 抹平「想完再说」 | 那是模型侧，不是让前端伪造逐 token | 前端只揭示已收到的 `TEXT_DELTA` |
| 1.2.4 自主 Agent 可以中途问人并改路径 | IPD 的问人必须停内核，并用下一次 create 回答，不能在同一次内核里「问完继续写」 | 执行器闸门。提示词即使写了问题，等待期间也没有内核 |

稿与书都同意的计划权威是 INTENT 事件里的 steps，不是 AgentScope Plan Mode。这一点沿用，没有冲突。

## 6. 下一期只做渲染时，先落地哪三条

假设内核闸门保持本次读到的行为。渲染不再重复接闸门，也不要为了像书再生成一套界面。
