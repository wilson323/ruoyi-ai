## 2. 做了什么(大白话)

### 2.1 老版改名

- **改前**:`/Users/mac/Documents/ZK-IPD/产品流程细化管理工具/` (43MB,15 个一级文件 + 2 子目录)
- **改后**:`/Users/mac/Documents/ZK-IPD/_ARCHIVED_v1_产品流程细化管理工具_决策草稿_20260918/`
- **命令**:`mv "/Users/mac/Documents/ZK-IPD/产品流程细化管理工具" "/Users/mac/Documents/ZK-IPD/_ARCHIVED_v1_产品流程细化管理工具_决策草稿_20260918"`
- **耗时**:1 个 mv,< 5 秒

### 2.2 新版不动

- **保持**:`/Users/mac/Documents/ZK-IPD/产品流程细化管理工具 2/` (792MB,Vite + Fastify + SQLite 可运行原型)
- **不动原因**:这是 ZK-IPD一致性红线 memory 认定的 **UI/字段/演示数据对照基准**,归档/改名都违反"严格禁止和 ZK-IPD 不一致"

### 2.3 命名约定

新名字三个要素:
1. `_ARCHIVED_` 前缀 — 一眼看出是归档(非活跃)
2. `v1_` — 明确版本号(对照新版 = v2 隐式)
3. `_决策草稿_` — 明确角色定位(决策 vs 实现的对照关系)

## 4. 为什么选 B 不选 D

(D = 老版并入 ruoyi-ai/docs 历史决策-v1/)

| 维度 | B 改名 | D 搬迁 |
|---|---|---|
| 改动面积 | 1 个 mv | 14 文件跨仓 + 删老目录 + 改引用 |
| 撞车风险 | 0 | 中(ruoyi-ai/docs 兄弟在改) |
| 保留现场 | 决策+原型在 ZK-IPD 并列 | 拆走老版失去并列对比 |
| 撤销难度 | 改个名字(1 秒) | git revert 或反向搬运 |
| 老版 git 化 | 不享受 | 享受(ruoyi-ai 是 git) |

D 的唯一优势是**老版进 git 享受版本控制**,但 v1 决策草稿是历史档案不是活跃编辑对象,**没人需要 git 化**;真要 git 化,B 改名之后单 `git init` 老版目录即可,不需要搬。
