## 二、完整业务逻辑输出（核心链路 + 机制 + 一致性标注）

### 2.1 三大业务闭环（权威 = 工程合同/业务决策确认-20260905.md）

**闭环 1 · 项目从立项到上市**
```
需求录入(游客 portal 提交 / 内部录入) → 需求分诊 triage → 关联项目 link-project
→ 项目创建(立项) → 六阶段推进(advance-stage + stage_actions 校验) → 每阶段 Gate
→ Gate 评审(材料上传 → 要素打分 → sign 顺序签署 → 分歧 arbitrate → final-ruling)
→ 上市 → 上市后评审(G5+90 天复盘) → 归档(删除申请双审 → purge/软删)
```
- 校验：阶段动作前置完成度（stage_actions 2304 行高频）、Gate isReady 材料齐备（materials?projectId → {uploaded,missing,isReady}）、签署顺序、跨组越权 403。
- 回滚：reopen（Gate 重开）+ withdraw（删除申请撤回）；审计：audit_logs hash 链 + rebuild-chain。
- **一致性**：与原型页 03/05/07/14~24 对齐 ✅；**双 PM 五节点签署链与豁免流后端未交付**（E1/E2 🔴）与原型不一致 → 前端诚实暴露不造假 ✅。

**闭环 2 · 激励全链**
```
月度 KPI 采集(raw-records) → 功能/绩效 KPI 计算(7 公式) → 共担 KPI 归集+确认(deadline-scan)
→ 项目绩效评定(project-score-tasks/scan → settle) → 贡献度评定(save→preview→market-share→confirm)
→ 奖金池核算(compute→auto-compute→freeze→distribute) → 津贴台账(auto-scan→ledger→pending-stop)
→ 系数变更双签(leader-decision) / 上市日变更双签(second-decision) / 负反馈(submit→decide→lift)
→ 回款台账(by-project→refunds)
```
- 异常：PENDING_SECOND+NULL 死路已清零（0924 现查）；津贴 distribute 真活待验。
- **一致性**：与 49 页 spec 页 27~37（激励域）对齐 🟢；project_scores 三表 0 行 → 用户可见的空态风险（数据回填待派）。

**闭环 3 · 合规治理**
```
认证(登录/改密/登出/即时撤销 inreview) → 权限(前端 meta.access 闸 + 后端 403)
→ 审计(scope/verify/export) → 通知(dispatch-pending) → 移交给办(batch/accept/scan-overdue/月度归属)
→ HR 离职(mark-resigned→escalate) → 人员同步(jobs/retry) → 删除申请(leader→admin→purge)
→ 合规(retention/audit-trail/permission-separation)
```
- **一致性**：SEC-04 十六探针真活过（✅）；HR/人员同步 11 端点前端未接（🔴孤儿）；合规无独立页（🟡）。
