## 一、P0 · 权限缺口：知识库菜单对所有 IPD 角色进不去

### 已验证的事实（不要重测）
```bash
TOK=$(curl -s -X POST http://127.0.0.1:16039/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ipd-admin","password":"Ipd@123456"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

curl -s http://127.0.0.1:16039/api/v1/auth/me -H "Authorization: Bearer $TOK" \
  | python3 -c "import sys,json;c=json.load(sys.stdin)['data']['person']['permissionCodes'];\
print('总',len(c),'ipd:*',len([x for x in c if x.startswith('ipd:')]),\
'system:*',len([x for x in c if x.startswith('system:')]))"
# 实测：总 89 / ipd:* 89 / system:* 0
```

`ipd-admin` 是 `sys_role.role_id=1`（超级管理员），按 Sa-Token 语义应放行一切，
**但只拿到 `ipd:*`，没有 `system:*`**，而知识库接口要 `system:info:list`。

### 要查清什么
1. 超级管理员的「全权限」为什么没覆盖 `system:*`？——查权限码的**装载来源**
   （`IpdAuthSession` / `KnowledgeAccessGate` / `StpInterface` 的 `getPermissionList` 实现）
2. `sys_menu` 里有没有 `system:info:list` 这条权限码的登记？有的话为什么没进 token？
3. **这是不是全局问题**——其它走 `system:*` 的接口（附件、OSS、租户）对 IPD 角色是否同样进不去？

### 修完的验收
