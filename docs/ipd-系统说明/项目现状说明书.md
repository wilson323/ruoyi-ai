
**⚠️ 口径说明（这是本仓最容易骗人的地方之一）**：根 `pom.xml` 里 surefire 配了
`<groups>${profiles.active}</groups>` + `<excludedGroups>exclude</excludedGroups>`。
默认 `dev` profile 下**只跑带 `@Tag("dev")` 的测试**——没打标签的测试类被静默跳过，
不是失败，是不出现。所以「全量测试数」和「`mvn test` 实际跑的数」差一个量级的口径差。

## 六、已知会骗人的地方

1. **审计报告是快照，不能直接引用。**
   `docs/ipd-系统说明/全局漂移审计-20261003.md` 是 10-03 的快照；`docs/wiki/raw/` 48 份里 16 份已与活文件漂移。引用前必须现核字节。

2. **`.claude/CLAUDE.md` 里的代码索引落后 669 个提交。**
   它写「Last indexed: 2026-09-21 (commit 9015a2d)」，
   实测 `git rev-list --count 9015a2d..HEAD` = **669**（HEAD `39ac04eb`，分支共 2,375 提交）。
   用它查代码会查到半个多月前的状态。

3. **测试里还留着已退役实体的字符串。**
   `grep -rl 'BonusPool' --include='*.java' ruoyi-modules` = **16 个文件**（测试 6 + 主源码 10）。
   但**实测绝大多数是注释/javadoc 提及**（如「随 BonusPoolService 删除后就地保留」），
   非注释行只命中 1 处（一个测试方法名 `acInc12SDefaultAndBonusPool`）。
   → **「命中 16 个文件」不等于「16 处活代码在调已删的类」**，引用前要剔注释。

4. **`CLAUDE.md` §结论纪律第 5 条的归档数字已失效。**
   它写 `.codex/` 有 19,848 个 `.java`、`.harness/` 有 12,786 个。
   实测：`.codex` = **263**，`.harness` = **0**（总文件 115）。
   → 归档规模已经变了，但**排除规则本身仍然必须内置**，理由不变。

5. **`new ActionDef(` 数（68） ≠ 有效动作数（67）。** 多出的 1 行是非目录用途构造。

6. **`grep -rl` + `xargs grep` 组合在中文路径 / 长文件列表上会静默少算。**
   必须 `| tr '\n' '\0' | xargs -0`。本次实测：不用 `-0` 时 `@Test` 计数得 **0**（全错），用 `-0` 得 4,736。

7. **`gate_review_elements` 的真实行数必须连库查，代码 seed 数（33/14）≠ 生产库数。**
