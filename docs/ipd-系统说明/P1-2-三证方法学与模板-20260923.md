## 一、三件套产出格式（每页必产 3 个文件）

### 1. 浏览器截图（PNG）

```
路径: docs/ipd-系统说明/验收/evidence-p1-2-<page-slug>-<YYYYMMDD>.png
示例: docs/ipd-系统说明/验收/evidence-p1-2-page-projects-20260923.png

内容校验: 顶栏 logo + 用户名、侧栏菜单激活态、主区域业务内容、底部无 JS 错误
```

### 2. HTTP trace（TXT）

```
路径: docs/ipd-系统说明/验收/trace-p1-2-<page-slug>-<YYYYMMDD>.txt
格式: 每行一条 API 调用，附 method/path/status/elapsed_ms/body_snippet
示例:
  GET    /api/v1/auth/login          200  45ms  {code:0, data:{token:xxx}}
  GET    /api/v1/workbench/summary   200  18ms  {code:0, data:{pendingCount:8}}
  GET    /api/v1/projects?keyword=   200  32ms  {code:0, data:{items:[...]}}
```

### 3. DB 回读 SQL（SQL）

```
路径: docs/ipd-系统说明/验收/db-p1-2-<page-slug>-<YYYYMMDD>.sql
格式: 真实可执行的 SELECT 语句（真库 127.0.0.1:13306 ipd_dev）
示例:
  SELECT COUNT(*) AS project_count FROM projects WHERE del_flag = '0';
  -- 29 行（与 HTTP trace 返回 29 条一致）
```

## 二、操作步骤（每页固定 5 步）

### 步骤 1：登录态建立（限流规避）

```bash
TOKEN=$(curl -sS -X POST http://127.0.0.1:16039/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"ipd-admin","password":"Ipd@123456"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
echo "TOKEN_LEN=${#TOKEN}"
```

> ⚠️ 限流提示：`IpdAuthController` 登录限流 5/60s，每会话登录 ≤ 2 次；TOKEN 全程复用。

### 步骤 2：浏览器自动化（chrome-devtools MCP）

```python
# MCP 工具序列（chrome-devtools 服务器）：
mcp.new_page(url="http://127.0.0.1:15666/ipd/<page-slug>")  # 新建页签
mcp.fill_form(fields={...})                                   # 如有登录弹窗
mcp.wait_for(text="<关键业务文案>")                           # 等渲染
mcp.take_screenshot(filePath="evidence-p1-2-<page-slug>-<date>.png")
```

### 步骤 3：API trace 抓取（chrome-devtools → network）

```python
# MCP 工具序列：
mcp.list_network_requests(filter="api/v1")
# 导出关键 API 调用 → trace-p1-2-<page-slug>-<date>.txt
```

> 备选：直接用 curl 复用 TOKEN 调 API，绕过浏览器。

### 步骤 4：DB 真值回读（mysql client）

```bash
mysql --defaults-file=.codex/ipd-dev/config/mysql-client.cnf \
  -e "SELECT ... FROM <table> WHERE ...;" \
  | tee docs/ipd-系统说明/验收/db-p1-2-<page-slug>-<date>.sql
```

> ⚠️ 必须用 13306 真库，不是 3306（项目本机数据源约定）；凭证走 socket 不上命令行。

### 步骤 5：三件套交叉验证

| 验证项 | 浏览器截图 | API trace | DB 回读 | 期望一致性 |
|---|---|---|---|---|
| 数据条数 | 主区域显示 N 条 | `data.items.length == N` | `SELECT COUNT == N` | 三者一致 |
| 关键字段 | 截图显示 status=ACTIVE | API 返回 status=ACTIVE | DB 列 status=ACTIVE | 三者一致 |
| 排序顺序 | 第一条 id=X | items[0].id == X | ORDER BY id LIMIT 1 = X | 一致 |

## 四、L2 模板化推进方案（推荐路径）

按本方法学，单会话可完成 10-15 张 P1-2 三证（vs L1 手工 1-2 张/会话）：

### 单会话工作流

1. **会话启动**：本仓会话拉取镜像最新 P0-10.x 列表，确认已做/未做
2. **分批跑页面**：每批 5-10 张，按 P0-10.x 编号顺序（如 P0-10.3 → P0-10.4 → ...）
3. **每页 5 步**（登录 → 截图 → API trace → DB 回读 → 交叉验证）
4. **产出三件套**：截图 + trace + sql，每页 3 文件
5. **commit + push**：每批 5-10 张页面的三件套打包 commit
6. **下一会话接续**：从上次 commit 后的下一未做卡继续

### 估算

- 49 - 4（已做）- 8（兄弟累计）= **37 张剩余**
- L2 模板化：37 / 12 ≈ 3.1 会话可完成
- L1 手工：37 / 1.5 ≈ 25 会话

## 五、风险与红线

- **不撞号**：前端页面截图/trace 归属前端仓，本仓不主动跑前端；如需跨仓验证，必须先确认目标页面未被前端会话在途编辑
- **不假绿**：三件套交叉验证必须三方一致，任意一方不符即返工；不允许仅截图通过
- **不破 SSOT**：三件套文件名/路径统一（见第一节），禁止放多页混置
- **不破兄弟会话约定**：本仓会话不抢前端会话派单（P0-10.x 全部 ⊘ 移出待办池）
- **凭证不上命令行**：登录/DB 走 socket + token 复用
