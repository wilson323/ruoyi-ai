## R25 reference-transaction hook 设计意图

R25 (2026-09-09) 治理轮加的 `.githooks/reference-transaction` hook 设计目的：**任何 reset/branch 操作前自动快照 main HEAD 到 refs/snapshot/* 命名空间，防 reset 孤儿化**。

**该设计的局限**：snapshot 命名空间会无限累积，每轮治理都触发新 snapshot，8 天下来累积 32 个。其中 27 个唯一指向 commit 已被 squash merge 重复快照（merge 操作的 merge-base 检测会触发 hook）。

**R25 教训未被升级为定期清理**。R116 弥补：全清并记录。

## 教训沉淀

1. **R25 reference-transaction hook 设计的快照命名空间需定期清理**：8 天累积 32 个几乎全部已 squash merge 落 main，防 reset 价值衰减
2. **snapshot 命名规范清晰**：`<branch-name>-<ISO-timestamp>-<pid>` 命名一目了然，便于审计
3. **git reflog + snapshot 双保险共存**：snapshot 是 reflog（默认 30 天）的副本，过期 reflog 也可从 snapshot 找回
4. **R25 设计意图保留但需治理**：hook 不删，但 snapshot 命名空间需每 1-2 周清一次（hook 会自动重新生成）
5. **ahead commit + snapshot 双防丢**：ahead commit 仍在 5 个本地分支 + reflog；snapshot 防御 reset 误操作；两者互补不冲突
6. **.git 物理大小不会因 snapshot 清空而变小很多**：主要空间被 commit graph / tree / blob 占用，ref 命名空间是元数据 < 1M
