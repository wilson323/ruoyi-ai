## 7. 响应包络约定

### 7.1 实际响应类型（IPD 自定义）

```java
// ApiV1Response<T> 自定义（与基线 R<T> 不混用）
{
  "code": 0,                    // 0 = 成功（非 200）
  "message": "ok",              // 文案
  "data": { ... },              // 数据
  "timestamp": "2026-09-20T...", // UTC ISO-8601
  "traceId": "..."              // MDC traceId
}
```

### 7.2 与底座 R<T> 的对比

| 维度 | RuoYi R<T> | IPD ApiV1Response | 偏离 |
|---|---|---|---|
| 成功 code | 200 | 0 | **偏离**（TS-09 决议：code=0 而非 200） |
| 包络字段 | code / msg / data | code / message / data / timestamp / traceId | 加 timestamp + traceId |
| HTTP 状态 | 业务 code != HTTP status | 同 | 一致 |
| 引用数 | 0 处 R<T> 在 ipd | 1 处 import（未使用）；全部 Controller 用 ApiV1Response | 100% 偏离 |

> **结论**：ApiV1Response 是有意偏离（TS-09），视为**业务扩展而非违规**。但需在文档中明确登记。

### 7.3 异常响应（4xx/5xx）

- `ServiceException`（底座）→ 由底座 GlobalExceptionHandler 处理 → 默认 500
- `IpdBusinessException(ApiV1ErrorCode.X)` → 由 `IpdServiceExceptionAdvice` 处理 → HTTP 400/401/403/404/500
- 鉴权异常（`NotLoginException` / `NotPermissionException` / `NotRoleException`）→ 由 `IpdPermissionExceptionHandler` 处理 → 401/403
