# 事实源五必现查规约（2026-09-08 R13 立）

> 触发：R12.1 收口轮同一轮发生 3 项输出异常——marker 凭记忆写错 hash（136ef385 vs e8eb3136）+ shell cwd 漂到前端仓导致 git log 显示错误 hash + 看板 updated_at PUT 后不刷新。
> 目标：把「凭记忆写事实」升级为「现查现写」，根除事实源引用错位类事故。
> 适用于：所有会话（主协调 / 兄弟 / 蜂群 subagent），所有仓（ruoyi-ai / ruoyi-ipd-web / ZK-IPD）。

## 五必现查

### 1. commit / PR hash 必现查
- 任何 message / marker / 看板注记 / 镜像段里写 hash 前：`git log --oneline -5` 现查现复制
- **禁止**：从上一轮输出或记忆里复制 hash 拼进本轮 marker
- 实测教训：R12.1 marker 写了 R11 的 136ef385（正确应为 R12 的 e8eb3136），需要追加修正段才能闭环

### 2. 端口 / 库名 / socket / 字段名 / 枚举值必现查
- 真库探针：`SHOW TABLES` / `DESCRIBE <table>` / `SELECT ... FROM information_schema.COLUMNS WHERE TABLE_NAME='<t>'`
- 应用配置：按**键名** grep（不用行号，行号分钟级漂移）
- **禁止**：凭文档或记忆写端口号（3306 vs 13306 事故）/ 字段名（persons.role vs person_type 事故）/ 列存在性（proposer_group_id / project_members.group_id 不存在事故）

### 3. 镜像 / 文档段号必现查
- 引用段号前：`grep -n '^## ' <file>` 现查
- **推荐**：只写「R12 段」这类轮次标识，不带 L 号（段号随追加必漂）
- **禁止**：随手写 L658-684 这类区间（下一轮追加后即失效）
- 历史事故：application.yml `demo:` 段 20:56 在 :396、21:10 已到 :400；tenant.excludes 从 :148 漂到 :198

### 4. 看板写入后必 fresh 读回（GET + LIST 双复核）
- PUT 后：独立 GET `/api/tasks/<id>` + 独立 LIST `/api/tasks?project_id=<pid>`，对比 **desc_len + marker content**
- **不依赖**：`updated_at` 字段（实测 PUT 后不刷新，停在 created_at 时刻）
- **禁止**：只看 PUT 返回 200 / success=true 就判成功（该看板 PUT 有静默失败前科）
- 单卡 GET 偶发返回空描述 → PUT 整体替换会清空 content：**取基文用 LIST 端点**

### 5. 跨仓命令必 `cd 绝对路径 &&` 开头
- 多仓工作区（ruoyi-ai / ruoyi-ipd-web / ZK-IPD）里每条 git / mvn / pnpm 命令：`cd /Users/mac/Documents/<repo> && <cmd>`
- **禁止**：依赖 shell 会话残留 cwd（实测 Node fallback 后 cwd 漂到 ruoyi-ipd-web，导致 `git log` 显示前端仓 hash、`bd8b3bd3` 被报 unknown revision）
- 兄弟症状：同一条验证命令跑错仓 → 结论全错还自以为验证过了

### 6. 兄弟 commit hash 现查(R13-hard 升级,2026-09-19 R77 §四 立)
- **任何 commit 写之前**：必跑 `git fetch --all 2>&1 | head -3 && git log --oneline -5` 现查兄弟会话最近 5 commit
- **目的**：避免「只查 git status 返空就以为干净」的撞号撞车（实测 2026-09-18 R71 双 commit 场景）
- **撞号判据**：同一 R 编号(如 R71)在兄弟会话 commit 后 9 秒被我 commit → 撞号撞车
- **撞号后处置**：
  1. **不擅自 reset / revert** 兄弟 commit(不可逆,违反 AGENTS.md 主人授权纪律)
  2. 写新文件撞号透明登记双 commit(参考 R72 模式)
  3. 双 commit 互补保留 > 强行合并(避免丢信息)
- **commit message 模板升级**(撞号撞车后追溯):`基线:本决策包 {hash} 前序:{prev_hash} 兄弟:{sibling_hash}`
- **适用**：所有主协调 / 兄弟会话的 R 编号治理轮 commit(Loop 26+ 强制,Loop 1-25 撞号透明让路)
- **禁止**：仅查 `git status --short` 返空就以为工作树干净(实测 5/5 返空仍撞号)

### 7. 轮次文档数字必来自证据块 + 门禁 PASS（R212-根因 立，2026-09-24，机器强制）
- **硬规则**：round ≥ R212 的轮次主文（`docs/ipd-系统说明/R<n>-*.md`）里，凡作为结论的数字 / HEAD / 计数，必须：
  1. 在文档内 `<!-- round-evidence {json} -->` 证据块登记：`key / value / file（相对文档目录）/ json 或 kv 取值路径 / at 采集时间`
  2. 正文写成 `<!-- ev:key -->**值**`，标记后的值必须等于证据块；每个 claim 至少被正文引用一次
  3. 提交前 `node scripts/check-round-doc-evidence.mjs` EXIT=0；`ROUNDDOC_FAIL_SEED=1` EXIT=1（真注入篡改副本，检出才算能红）
- **HEAD 类**：只记「证据采集时 HEAD + 时间戳」，门禁只比对证据文件记录值；**禁止**写「当前 HEAD」——文档无法包含收录它自己的提交的 HEAD（R212 草稿 ebcfa3d6 在 12:38Z 是对的，被自身提交 7868a26a 推过后被误判「过时」）
- **同轮同主题只许 1 份 canonical**：改名/改版时旧文件必须缩成指针（≤15 行且含「指针」，或加 `<!-- round-doc: pointer -->`）；门禁 DUP_TOPIC 拦截
- **完成断言**：「全部补齐 / 全部完成 / 全部闭环 / 全绿 / 100%」所在段落必须引用证据路径（`验收/…` / `.json` / `.txt` / `.log` / `ev:` 标记），否则 COMPLETION_NO_EVIDENCE；转述草稿用「」括起并注明裁决
- **遍历/探针结果必须可复现**：参数钉死并写入结果元数据。路由遍历一律走 `scripts/run-route-traverse-with-meta.sh`（缺参 exit 2；真库预检 id 不存在 exit 2；输出 `{meta, summary, results}`，meta 含账号/角色/projectId/productId/双仓 HEAD/采集时间/路由清单 sha）；**禁止**对比两次参数不同的运行结果
- **证据文件须登记来源命令**：放进 `验收/<轮次>/` 的 JSON 若无生成命令登记，只能作「来源待验证」引用，不得作为唯一依据（R212 `contract-0921-baseline.json` 即此状态）
- **R212 实测教训**（根因 RC-1~RC-6 全表见 `log.md` R212-根因 段）：
  - 「T-V1 62 干净」被复跑「否决」——实为复跑没注入 env，参数落到悬空 9140004，52/12 是假象；钉参复跑 62/2 与首跑一致
  - 「孤儿 115→98」起点凭记忆，证据目录早有 `contract-0921-baseline.json` = 105；同时主文又误写「0921 差集未复算」——证据在目录里却没被登记消费
  - V2 与非 V2 同名主题 md 并存，差点形成双事实源
- **为什么以前没拦住**：`check-report-baseline-drift.sh` 只对 9 条硬编码 fixture 比对现态、默认 warning 不阻断、不扫新轮次；`check-doc-drift.sh` 管 API 锚点/表名；`check-duplicate-ssot.sh` 管常量；五必现查 §1~§6 只要求「现查」，没要求「写进文档的值可被机器回溯到证据文件」
