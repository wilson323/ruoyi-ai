# 智能体能力增强最佳实践 —— 基于本项目 AgentScope 单轨实现（2026-09-28）

> **研究方法**：四路并行研究（外部资料精读 34 篇 + 本仓资产盘点 45 文件 + AgentScope jar javap 现查 + 用户 5 份方案文档消化）交叉提炼。
> **证据分级**（沿用 ADR-0075 口径）：✅ 实证（本仓真跑过）/ 🔍 现查（源码/javap 核证未跑行为）/ 📄 文档级（外部文章或官方文档，未在本仓验证）。
> **配套文件**：《智能体系统提示词-AgentScope完整版-20260928.md》（本文档 §三/§四/§五 的行为协议形态）。

## 〇、结论速览

1. **能力上限在模型，可用下限在 Harness**：外部实证「同模型换 Harness，Terminal Bench 52.8%→66.5%、排名差 20+ 位；仅靠 harness engineering + 评估驱动 hill-climbing 即 +13.7%，不换模型不微调」📄。本仓同构证据：Executor/Validator 分离两次拦截 P0（ws 线程身份缺失、字典序越权放大）✅。
2. **本项目增强路径**＝AgentScope Java v2 成熟能力为底座（24 项三选一：替换 6 / 包装 11）＋ 自研治理资产保留 7（审批/恢复/预算/计划/访问控制/脱敏/Plan 版本）＋ **本文档定义的行为协议**（质量自证 / 自主进化 / 主动智能）落入系统提示词与门禁。
3. **「完成」是外部证据裁决的结构化状态，不是模型的自我声明**——这是全部外部资料与本仓工程宪法的共同第一原则。
4. 自主进化与主动智能**可以工程化**（五环闭环 + 触发器矩阵，见 §三/§四），但**防污染是第一约束**（Misevolution 论文实证：顶级模型 60%+ 中招经验主义陷阱 📄；本仓「恒真断言假绿」为同构实证 ✅）。

## 二、六大能力支柱（外部证据 × 本仓资产 × AgentScope 底座 × 增强方案）

### 支柱 1：任务完成质量保证

| 维度 | 内容 |
|------|------|
| **外部证据** | ① 确定性规则 + LLM 混合审查：已知漏洞（NPE/注入）走确定性流水线必被发现，LLM 只判「设计是否合理」📄；② **反合理化借口表**：「这个功能很简单不需要测试」「没有外部输入不需要安全检查」逐条显式反驳——AI 本质追求效率最大化，会自动跳过「看起来不必要」的步骤 📄；③ **四类检查分置**（请求进模型前拦不该执行的 / 结果离开系统前校验 / 工具参数与返回值本地校验 / 副作用动作前暂停等人确认）——合并成一个「是否允许」开关会同时漏掉好几种失败 📄；④ **验证证据门槛**：「如果你不能证明它是对的，那它就是错的」——测试通过？构建输出正常？运行时数据达标？「看起来对」不算数 📄；⑤ Eval 反作弊：验证器第一版特别容易被钻空子，须同时看 Agent 轨迹与验证器轨迹 📄；⑥ 意图-过程-产出三锚点（Story→Session→Commit 证据图）📄 |

## 三、自主进化五环闭环（落地设计）

```
①采集 ──→ ②提炼 ──→ ③应用 ──→ ④验证 ──→ ⑤升格/淘汰
(Trace级)   (结构化)   (参考级)   (独立证伪)  (频次阈值)
```

| 环 | 设计要点 | 证据 |
|---|---------|------|
| **① 采集** | 喂**完整 Trace 不喂分数**（看原始轨迹比只看分数效果好 44% 📄）；失败信号三源：门禁失败日志 / buglog / git reflog reset 痕迹；信号先三分类：**真失败 / 并发噪声（假红）/ 外部变动**——噪声与 API 变动不计入经验（本仓假红镜像：85 跑 71 Error 中 ≥66 假红 ✅） | Meta-Harness + 本仓 |
| **② 提炼** | 轨迹必须结构化提炼不能裸塞（0.540 vs 0.422 📄）；**经验条目九字段**＝SkillTTA 五要素（何时使用/可能失败模式/推荐流程/注意事项/最终检查清单）+ BCP 四字段（编号/来源/拍板位/**自证能红方式**）；提炼时强制「从失败提炼可泛化策略，不被场景特定细节带偏」（Guide 变体 📄） | SkillTTA + 本仓 BCP |
| **③ 应用** | **当前任务上下文永远最高优先级**（检索到的经验不得覆盖当前任务的输出格式/动作语法/返回类型 📄）；注入带「仅作参考须独立决策」前缀；top-k=3 少量高相关；进化/检索放**低频冷路径**（记忆影响技能进化器，不直接拼高频答案 📄） | SkillTTA + VisualClaw |
| **④ 验证** | 经验应用后必须过独立 Validator 证伪（判定权外置）；沉淀为规则时**自证能红**：注入 FAIL_SEED 验证门禁真的会红（防恒真断言——`sensitivityLexicographicOrder` 教训 ✅） | 本仓 |
| **⑤ 升格/淘汰** | **同一错误出现 ≥2 次→写入持久规则**；升格路径：候选→文档落档→owner 拍板→脚本化门禁（BCP 生命周期 ✅）；每周盘点合并近似、清理过期 | Anthropic/EvoX/本仓 |

## 四、主动智能触发器矩阵（落地设计）

**核心句式：主动发现 → 只读探查 → 登记风险 → 请求拍板。禁止主动=擅自修复。**

| 触发条件（具体可判定） | 主动动作 | 权限级 |
|----------------------|---------|--------|
| 状态变化：接线断开/契约漂移/门禁基线偏离 | 主动发起验证并登记风险（只读+登记，不改码） | Allow |
| 前置依赖未满足（如「缓存身份段未修就跑检索过滤=假绿」） | 主动**阻断**下游任务并说明依赖 | Allow |
| 验证完整性缺口（自己没验过的维度） | 主动补验证或标记 PARTIAL | Allow |
| 失败累积达阈值 | 唤醒离线进化器提炼经验 | Allow（离线） |
| 跨场景复用工具/技能时上下文不匹配 | 暂停并请求确认 | Ask |
| 敏感操作（push/基线编辑/白名单变更） | 主动请求人类审批 | Ask/Deny |
| 无显式指令的探索性行动 | **只发现不执行**（reme 模式） | 只读 |

**四条边界原则**：① 规则必须具体到场景（宽规则使触发不可判定）；② 主动发现的产出是登记/风险卡，不是擅自修复；③ 确定性子流程封装为 Tool 由 ReAct 自主决策何时调用（MountableResource 模式）；④ 自主度滑杆按任务调（探索性高自主，生产/共享资源人在回路）。

### 5.2 主动性越权风险六条

① 擅自修复超出任务面（一次一个原子 mutation + 精确 pathspec）；② 主动触发写操作冲击共享资源（并行会话主动跑构建=制造假红——禁跑、主会话统一回归）；③ 主动求助泛化（触发器必须场景化）；④ 主动验证本身制造假绿（前置依赖未满足时验证结果不可信）；⑤ 主动进化在热路径上（高频答案直接吃原始记忆=污染放大）；⑥ 静默接手他人在途工作（检测到在途改动即停、只读让行、显式登记）。

## 七、十大共性原则（跨来源收敛，外部 34 篇 + 本仓实证交叉）

1. 完成由外部证据裁决，模型自我声明不算数（「不能证明即错」）。
2. 裁判员运动员分开；对抗性验证优于自我复查。
3. 确定性兜底概率：已知问题走规则必被发现，LLM 只判需要判断的。
4. 状态是一等资产；Transcript 是审计材料不是运行状态。
5. 上下文当稀缺资源：渐进披露、三层加载、删除实验、工具越少越好。
6. 反偷懒显式工程化：反合理化借口表 + 验证证据门槛 + 根因说不清不许动手。
7. 经验沉淀有判据：多次交付重复出现 + 有产出与验证支持，而非高频 Tool Call（可能是噪声）。
8. 恢复与安全 fail-closed：interrupted≠aborted；恢复后续行需重新授权；副作用带幂等键。
9. 评测分层接门禁：结果/轨迹/组件三层；bad case 沉成回归样本。
10. 频次阈值升格：同一错误 ≥2 次→持久规则化（三处独立来源同款）。

## 八、本仓工程宪法精华（直接可执行条目，已验证）

1. **假绿三形态**：无 @Tag("dev") 被静默跳过 / 断言改成现状让用例转绿 / mock 造真库不可能的数据组合——绿的是契约不是既有实现。
2. **自证能红**：门禁须 FAIL_SEED 双向验证（正常态 PASS + 注入违规必红 = 双绿才算真绿；单绿恐惧=误报）。
3. **五必现查**：hash/端口/段号/看板回读/跨仓 cd 现查现写，禁止凭记忆。
4. **错峰构建**：多会话共工同一工作树，复核一律错峰+单模块+不带 -am/clean（防 target 交叉假红）。
5. **兄弟在途不捎带**：`git commit --only` 精确路径；检测到他人未提交改动即停，只读让行。
6. **四步收口**：commit+push → clean 验证 → 看板卡面同步（不许卡面滞后于事实）→ 镜像登记。
7. **单测绿≠业务闭环**：真库/HTTP 未跑即 inreview，owner 拍板才 done。
8. **第三方库行为最小探针实证**（jshell 五行复现定案，比读文档快且准）。
9. **登记不实施**：未做的逐条登记，比做了的更重要。
10. **业务规则 > 文档惯例 > 系统实现**（层级仲裁序）。
