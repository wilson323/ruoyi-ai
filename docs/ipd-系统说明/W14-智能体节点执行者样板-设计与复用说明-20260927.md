# R232-W14 智能体节点执行者样板 · 设计与复用说明

> marker: `r232-w14-reconcile-executor` ｜ 日期: 2026-09-27 ｜ owner 指令: 「按照建议完整执行」+「尽可能应用成熟解决方案，避免过多自定义代码，确保全局一致，文档先行」
> 定位：本文是**可复用范式文档**——后续任何「高质量智能体作为节点执行者嵌入端到端工作流」都应照本文件的复用矩阵与判据接入，而非另起引擎。

## 0. 方向锚点（为什么这样做）

前一路线被 owner 方向性纠正否决：**禁止「存量流程 + 外挂 AI 建议框」**（伪价值陷阱）。新路线 = **完整产品生命周期端到端工作流 + 高质量智能体作为节点执行者嵌入工作流内部**。本 W14 是该路线的第一个样板。

两条待拍板建议的落地口径：
- **引擎延迟引入**：不引 Flowable/Temporal，复用现成底座 `ai_agent_tasks` 五态 + `AiExecutionEngine`（退避 30s/2m/10m、≥3 次 DEAD 转人工 + 审计三件套）+ Warm-Flow 承载真人签署。价值验证后再评估 Flowable 7。
- **样板选 W14 共担 KPI 数据对账**（而非 W06 调研）：产出可独立验收、失败可降级不污染下游、可被同岗真人复算、不改流程天花板（裁决权留真人签署链）——四判据全满足。

## 2. 四判据落点（W14 为何适合做样板）

1. **产出可独立验收**：对账台账是一份 md，含逐项 stored vs recomputed 比对表 + 综合分复算 + 双 PM AC-KPI-11 校验 + 确认链状态，真人可直接核。
2. **失败可降级不污染下游**：对账**只读**，不改 KPI 记录、不 transit 动作状态；OSS 失败 → 引擎退避 → 终 DEAD 转人工，不写脏数据。
3. **可被同岗真人复核**：复算公式与归集公式同源（同一 `KpiSharedCollectionService`），组长用同一口径即可复核，不存在"AI 专用黑箱算法"。
4. **不改流程天花板（裁决权留人）**：执行器**不 transit、不 recordFields**，只 `addDeliverable` 挂证据 + 知会组长；是否采纳由真人签署链（Warm-Flow 双组长签署）决定。

## 3. 关键设计决策与理由

- **挂既有 K 码而非新增动作**：目录 69 数被 8 处测试锁死；且对账天然覆盖 K01-K04 四项整体，任一 K 动作触发的「AI 执行」都产同一份全周期台账（`supportedActionCodes = {K01,K02,K03,K04}`）。
- **`supportsSchedule() = false`**：对账只走组长 PASSIVE 手动触发，排除出 `scheduleWiredActionCodes`，防调度器每日自动堆台账（同 C08 填表族 / C11 HUMAN_GATE 排除先例）。
- **不用 `terminalNoOp` 终态守卫**：对账是只读复核，K 动作 DONE 后再对账仍合法，复用终态守卫会误吞复核。
- **缺值 PENDING_DATA 不伪判**（W14-02 语义）：从未归集 → 上月周期全项标 `PENDING_DATA`，不按 0 分伪造"一致"；待补台账仍是执行**成功**产出（有效交付），而非失败重试。
