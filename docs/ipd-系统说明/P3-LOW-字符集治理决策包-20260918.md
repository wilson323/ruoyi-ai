## 一、现状(真库现查,R13 五必现查)

| 字段 | 表 | COLLATION | CHARACTER SET |
|---|---|---|---|
| user_name | sys_user | `utf8mb4_0900_ai_ci` | utf8mb4 |
| username | persons | `utf8mb4_general_ci` | utf8mb4 |

- `sys_user` 4 行 / `persons` 27 行 / `sj_system_user` 0 行(基线空表,无影响)
- `persons.username` 有唯一索引 `uk_persons_username`(ALTER 需重建索引)
- 真活 JOIN 触发:`ERROR 1267 (HY000): Illegal mix of collations (utf8mb4_0900_ai_ci,IMPLICIT) and (utf8mb4_general_ci,IMPLICIT) for operation '='`

## 二、阻塞 vs 不阻塞

| 场景 | 是否阻塞 |
|---|---|
| IPD 独立认证(Sa-Token loginType=ipd,persons 自有认证) | ❌ 不阻塞(IPD 业务代码不 JOIN 这两张表) |
| 框架基线用户管理 + IPD 人员互通 | ✅ 阻塞(报 1267) |
| 跨系统用户同步(sys_user ↔ persons 互通) | ✅ 阻塞 |
| 统一权限视图(sys_user + persons UNION) | ✅ 阻塞 |

**当前业务**：仅 IPD 独立认证在跑,**1267 暂不阻塞**。但未来跨系统互通会立即触发。

## 三、3 方案 ALTER 选型

| 方案 | 改动范围 | 选型依据 | 风险 | 推荐度 |
|---|---|---|---|---|
| **A1(推荐)** | `persons.username` → `utf8mb4_0900_ai_ci` | IPD 业务核心表;27 行规模小;与 sys_user 对齐;前进式升级 | IPD 业务查询路径需复核;索引重建锁表瞬时 | ★★★★★ |
| A2 | `sys_user.user_name` → `utf8mb4_general_ci` | sys_user 是基线 RuoYi 框架表;4 行规模小 | 影响其他基线模块;等于降级 MySQL 8 默认 | ★★ |
| A3 | 同 A1(强调"前进式升级"语义) | 与 A1 等价 | 同 A1 | ★★★★★ |
| 维持现状 | 无 | 不阻塞 IPD 业务 | 1267 持续,跨系统互通立即触发 | ★ |

## 四、推荐方案 A1 详情

### 选型依据

1. **IPD 业务核心表是 persons**(基线 sys_user 是 RuoYi 框架表,改 IPD 表影响面更可控)
2. **数据规模 27 行**(实测),唯一索引重建瞬时(<1s)
3. **utf8mb4_0900_ai_ci 是 MySQL 8 默认**(Unicode 9.0,更新规则;与基线 sys_user 对齐)

### 风险评估

- **应用层 prepared statement 缓存**:ALTER 后需重启服务(16039 应用),否则连接池 stale
- **MyBatis 不会自动加 COLLATE**:SQL 层需显式 COLLATE,IPD 业务 `WHERE username=?` 查询路径需复核
- **唯一索引 uk_persons_username 重建**:27 行规模实测 <1s,瞬时锁表
- **IPD 业务查询路径**:persons 表 27 行,所有索引走 `uk_persons_username` 唯一索引,查询性能不受影响

### 实施 SQL(待 owner 拍板窗口)

```sql
ALTER TABLE persons
  MODIFY COLUMN username VARCHAR(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci NULL COMMENT '登录账号(默认手机号)';
```

### 回滚 SQL(如有需要)

```sql
ALTER TABLE persons
  MODIFY COLUMN username VARCHAR(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NULL COMMENT '登录账号(默认手机号)';
```

### 执行窗口建议(撞车 0 + owner 拍板后)

- 凌晨低峰(00:00-05:00 PDT)
- 应用连接池先清空(停服 5 分钟)
- ALTER + 验证 SQL 在 5 分钟内完成
- 回滚预案:ALTER 失败立即执行回滚 SQL
- 应用层 prepared statement 缓存:ALTER 后重启服务(PID 79305)
