## 2. B→A API 样例（真 HTTP 实测原文，非模拟）

统一包络验证符合 DOC-06 §2：`{code,message,data,timestamp,traceId}`、成功 code=0、ID 一律字符串（`"version":"3"`）、失败 data=null。

### 2.1 正例

**P1 小阶段推进成功** `POST /api/v1/ipd/stage/sub-stages/advance?projectId=2103550173220220929&targetSubStageCode=DEV-S1&expectedVersion=0` → HTTP 200：
```json
{"code":0,"message":"ok","data":{"projectId":"2103550173220220929","currentStage":"DEV","currentSubStageCode":"DEV-S1","version":"1","gateResult":"PASSED","replayed":false,"advanced":true}}
```

**P2 重放（幂等）** 同 target 重放 `expectedVersion=1` → HTTP 200：
```json
{"code":0,"data":{"currentSubStageCode":"DEV-S1","version":"1","replayed":true,"advanced":false}}
```
（重放不重复副作用：DB 审计 `PROJECT_SUB_STAGE_ADVANCE` 仅随三次真实推进 ×3 新增，重放/冲突零新增。）

**P3 游标回读** `GET /api/v1/ipd/stage/sub-stages/progress?projectId=…`：初始 `{currentSubStageCode:null, version:"0", replayed:false}`；重启后 `{DEV-S3, version:"3", gateResult:"PASSED"}` 持久化不回退。

**P4 成员申请/审批**（产品线空间）`POST /ipd/product-lines/{id}/join-applications` → `data.status="PENDING"`，附 `personId`（字符串）；review approve → `status="ACTIVE"`。

### 2.2 负例（三类全覆盖）

**N1 未登录**：任何 `/api/v1/**` 无 Bearer → **HTTP 401**：
```json
{"code":20001,"message":"未认证或凭证失效","data":null,"timestamp":"2026-09-29T17:10:00Z","traceId":"23573343c7004aaa979bb8867f6d0ec8"}
```

**N2 无权（已登录低权限）**：`ipd-rd` 调管理员面 `POST /ipd/product-lines` → **HTTP 403 / code 30001 "权限不足"**；组长改指定后旧组长读审批队列同样被拒（B1补-⑥f）。

**N3 版本冲突（CAS）**：`expectedVersion=99` 陈旧游标推进 → **HTTP 409 / code 50002 "小阶段版本已变化，请回读后重试"**，游标与 version 不变。

**N4 业务规则冲突**：乱序回退 → 50002 "小阶段只能按目录顺序推进一个节点"；暂停/归档项目推进 → 50002 "暂停或归档项目不可推进小阶段"；指定非成员为组长 → 50002 "组长必须是该空间的在职成员"。
