## 3. 5 P0 整改方案

**违规实数**：61 个 Service 全部直接 `@Service` 类，无任何 IXxxService 接口（impl 子包仅含 `DefaultStateMachineGuard.java` 1 个非 ServiceImpl 文件）

**工作量**：每个 Service ≈ 30 行接口 + 类改 `@Service` 加 `implements IXxxService` + 30 行实现体构造 ≈ 80 行变动 × 61 = **~4900 行新增**

| 第 1 批 | A / B / C | Ai* / Allowance* / Audit* / Bid* / Bonus* / Business* / Cert* | **15** | audit_logs / bid_responses / cert_templates / bonus_pools |

**重构模板**（每个 Service 统一）：

### P1-② DTO 后缀收口（71 个）

**现状分布**（8 种后缀）：

| 后缀 | 数量 | 收口目标 |
|---|---|---|
| `Req` | 31 | `Req`（保留） |
| `View` | 14 | `Resp`（视图层响应） |
| `VO` | 9 | `VO`（保留） |
| `Result` | 8 | `Resp`（操作结果） |
| `Request` | 4 | `Req`（短化） |
| `Row` | 3 | `Resp`（行数据） |
| `Resp` | 1 | `Resp`（保留） |
| `DTO` | 1 | `VO`（泛 DTO） |
| **合计** | **71** | 收口到 **4 种**（Req/Resp/Query/VO） |

**收口目标 4 种**：
- **`XxxReq`**：入参请求
- **`XxxResp`**：出参响应（含 View/Result/Row）
- **`XxxQuery`**：查询条件（**新增**，目前散在 Req 中）
- **`VO`**：内部值对象（保留）

**偏离底座**：底座 4 种 DTO 后缀约定，避免后缀洪流

**工作量**：71 × 1 行 import + 1 行类名 + N 行所有引用方 = **~500+ 行 + 200+ 个调用点改动**

**派单**：**单批一次性改完**（**最大破坏性**）

**owner 决策点**（**强决策**）：
1. **`XxxQuery` 是否新增**？（推荐新增，Query 与 Req 语义不同：Query 进 Controller、Req 进 Service）
2. **View 类是否拆为 View + Resp**？（View 通常含展示逻辑，Resp 是纯响应）
3. **是否兼容旧名**（`@JsonAlias` + 双类型共存）？**推荐**：直接落仓 + 一次性 migrate（不留兼容期）
