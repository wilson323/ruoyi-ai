## 1. 业务规则名称

**计划→开发出口（P10）同一未完成原因不复拦规则与原因追溯机制**。

业务上要求：决策 1 同时取消了两层硬否决——G2-6 评审不否决（"要素级"），P10 计划转开发出口对"同一未完成原因不复拦"（"流转级"）。两个层面须联动：G2-6 留下"未完成记录 + 责任人 + 计划"，到 P10 出口时门禁扫描须识别"同一项目、同一规划原因"，不能因旧 `isBlocking=Y` 标志位或同源遗留项而重新拒绝本次已允许的转换。

## 2. 决策摘要

- **业务实质**：决策 1 防止"通用遗留规则"在下一关再次拦住同一类未完成项，避免 gate 评审演化成"问题永久卡着"。关键差异是"P10 不复拦"≠"P10 全局不卡"——G2 其他 4 项硬否决（PRD 缺失 / 里程碑不可达 / 等）、G4 实际结果校验仍然独立生效。
- **当前实现**：DOC-05 §4 已明确"P10 复拦识别"语义，PLAN-P10 / PLAN-NO-REBLOCK 测试用例覆盖；但**"同一原因"的归因比对机制未在代码层独立实现**——门禁扫描当前依赖 G2 评审阶段写入"原因 ID / 责任人 / 计划描述"字段，P10 出口仅做字段存在性检查。
- **本次 docs-only 落档要点**：本注解记录"原事件如何描述、撞车时如何比对原因、撞号时如何升级"，把"原因 ID 同源判定"在文档侧固定下来，避免未来 owner 拍板扩展时跑题到"G3/G4 也全开绿灯"。

## 3. docs-only 注解正文

1. **不复拦对象边界**：仅限"决策 1 明文提及的同一未完成原因"（认证清单 / 周期未完 / 同源遗留项）；其他 G2 硬否决（PRD、里程碑、研发资源、合规等）和 G4 实际结果校验**不在本次放行范围**。
2. **原因字段必填项**：G2-6 评审结果写入 `block_reason_code`（枚举：`CERT_PENDING` / `CERT_PERIOD_CONFLICT` / `LEGACY_OPEN`）+ `block_owner`（具体责任人 UUID）+ `block_due_date`（≤P10 出口日）+ `block_close_link`（跟踪待办 URL）。P10 出口扫描"同一项目同原因"，命中则放行（仅本类），其他硬否决仍生效。
3. **不复拦扩域禁止**：本规则不扩展到 G3 阶段、G4 上市前、奖金终算；如未来业务上要扩，须 owner 拍板并落新 ticket，不能由工程子任务顺带"顺手打开"。
4. **撞号升级路径**：若 P10 出口发现同一项目同一原因被复拦（违反本注解），记 P10-ESCALATION，升级到 GATE_P10_ESCALATIONS 审计表，关联 owner 处理（≤P10 + 7 日内）。
5. **回退条件**：未来若用户业务决策变更要求"复拦"，须先撤决策 1 在业务决策确认-20260905.md L13 的原文，再回退本注解。
