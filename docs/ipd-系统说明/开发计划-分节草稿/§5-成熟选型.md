## 5.1 Generative UI 六条路径逐条评估

> 官方六路径总表：S1 L230–239。需求映射：**AI 引导（六阶段）+ 画布交互 + word/html 文档生成 + 传统 UI ⇄ AI UI 双模式**。双模式 = 文本降级恒在场（红线 R3），卡片是增强不是唯一通道。

### 路径 A — Agent 组件（`useComponent`）

| 项 | 结论 |
|---|---|
| 机制 | 前端声明组件即工具（`useComponent({name, parameters, render})`），schema 到达组件即 props，无 handler（S1 L245–298） |
| 适配本需求 | **辅助采用（仅无交互展示场景）**。优：零后端配合、最短路径。劣：**工具归属在前端**——官方判据"若删掉组件会从 agent 工具表消失，就是 useComponent"（S1 L292–298）；本仓工具由 Java 桥 `done+card` 帧驱动（S6 §4），**工具归属在后端**，六阶段卡片主体应走路径 B |
| 新增依赖 | 无（`@copilotkit/vue/v2` 已装，S2 pnpm-workspace.yaml L24） |
| ADR | 不需要（若仅做纯展示卡）；若用它承载**业务卡片**则与卡片单轨契约冲突（平行卡片体系红线），禁止 |
| 证据 | S1 L245–298；S2 L24；S6 §4/§5 |

### 路径 B — 自有组件（`useRenderTool` / `useFrontendTool`）— **本期主路径**

| 项 | 结论 |
|---|---|
| 机制 | agent 拥有工具、浏览器只画调用：`useRenderTool({name, parameters, render})`（S1 L308–379）；`useFrontendTool` 另可带 `handler` 在浏览器执行（S1 L399–437） |
| 适配本需求 | **✅ 主路径，现状即此**。优：卡片注册表 4 类型经 `useRenderTool` 循环注册（copilotkit-render.ts L194–206），与 Java 桥 AG-UI 帧映射（AgUiFrameTranslator）闭环；渲染 props 本仓已等价承接（§4 R3）；`useFrontendTool` 留作**纯前端交互工具**（如画布定位/高亮节点）——注意两套渲染 props 不通用（§4 R1），且 handler 写入动作受 C08 零直写约束（写入仍走既有端点/emit，handler 只做视图交互） |
| 新增依赖 | 无 |
| ADR | `useFrontendTool` 承载任何**写操作**前需 ADR（C08 边界 + 单轨红线"不加新写入端点"评审）；纯视图交互（画布 scrollTo/高亮）不需要 |
| 证据 | S1 L308–437；S3 copilotkit-render.ts L194–206；S6 §4；§4 R1/R3 |

### 路径 C — 默认卡（`useDefaultRenderTool`）— **兜底，现状即此**

| 项 | 结论 |
|---|---|
| 机制 | `useRenderTool({name:"*"})` 薄包装，无参调用装内置折叠卡（tool 名/状态/参数/结果），S1 L381–397 |
| 适配本需求 | **✅ 兜底路径**。优：一行升级裸 JSON；与命名渲染器并存不冲突（named 优先、`*` 兜底）。劣：无业务语义，不能做六阶段引导卡。本仓已注册（copilotkit-render.ts L206 `useDefaultRenderTool()`） |
| 新增依赖 | 无 |
| ADR | 不需要 |
| 证据 | S1 L381–397、L5282–5290；copilotkit-render.ts L206 |

### 路径 D — A2UI（`:a2ui`）

| 项 | 结论 |
|---|---|
| 机制 | agent 发声明式 A2UI 操作，前端按 catalog 组件目录构建界面；Vue 渲染器基于 `@a2ui/web_core`（已在 node_modules 传递依赖，`@a2ui/web_core@0.10.4`），无 React 依赖；runtime 侧 `a2ui: {}` 即开启，前端 `:a2ui` 仅覆盖（theme/catalog/loadingComponent/includeSchema）；客户端传 `catalog`（如 `vueBasicCatalog`）可反向开启（S1 L439–500） |
| 适配本需求 | **⏸ 本期不启用**。优：协议化 UI、agent 自由组合组件、依赖已在包内（零新增成立）。劣：①与本仓**卡片单轨契约直接冲突风险**——卡片数据走 `done+card`→TOOL_CALL 帧（S6 §4），A2UI 是另一条 UI 生成通道，启用即可能构成"平行卡片体系"红线；②Java 桥 GET /info 无 a2ui 字段（S6 §3.1），runtime 不报告配置则内置渲染器不激活；③catalog 设计 + 与 (type,version) 校验链对齐成本高 |
| 新增依赖 | 无（`@a2ui/web_core` 已传递在场） |
| ADR | **需要**（启用必开 ADR：红线合规 + Java 桥 /info 扩展 + catalog 设计） |
| 证据 | S1 L439–500；node_modules `@a2ui/web_core@0.10.4`（2026-09-28 实测）；S6 §3.1 |

### 路径 E — Open Generative UI（`:open-generative-ui`）

| 项 | 结论 |
|---|---|
| 机制 | agent 生成 HTML/CSS 在**无同源权限的沙箱 iframe** 内渲染，仅能经显式列出的 `sandboxFunctions` 回调宿主；`sandboxFunctions` 必须稳定数组；`designSkill` 覆盖生成设计指引（S1 L502–540） |
| 适配本需求 | **⏸ 本期不用于文档预览**。优：生成式界面零组件成本。劣：①**文档预览不该走沙箱生成**——html 文档应渲染本仓可信内容（TinyMCE 产物），不是模型现场生成的 UI；②sandbox 回调面 = 新写入面，触发红线"不加新写入端点"评审；③生成 UI 质量不可控、与 Ant Design Vue 体系不一致。合理定位：未来"agent 现场造一次性报表界面"类需求再评估 |
| 新增依赖 | 无（渲染器随 `/v2` 内置，S1 L502–540） |
| ADR | **需要**（启用必开 ADR：sandboxFunctions 白名单评审 + 红线合规） |
| 证据 | S1 L502–540 |

### 路径 F — MCP Apps

| 项 | 结论 |
|---|---|
| 机制 | MCP server 返回交互式 app 资源，内置渲染器**常驻并入** provider 活动渲染器，无需任何配置（S1 L542–547、L239） |
| 适配本需求 | **❌ 不适用，留观察**。本仓无 MCP server 链路（Java 桥为直连 AG-UI 翻译，S6），无交互式 app 资源来源。注意其"常驻并入"特性：未来引入 MCP server 后资源会自动进聊天流，须与卡片体系划清边界 |
| 新增依赖 | 无（不需要任何配置） |
| ADR | 本期不需要 |
| 证据 | S1 L542–547、L239 |

### 5.3.2 word 导出

| 项 | 结论 |
|---|---|
| 依赖现状 | **前端无 `docx`/`mammoth`/`html-docx-js`/`file-saver`（S2 实测未装）**；后端 POI 在场：`ruoyi-common-excel` 依赖 fastexcel，Java 源码 `import org.apache.poi.xssf.* / ss.usermodel.*` ⇒ poi-ooxml jar 在类路径，**XWPF（docx）同 jar 内**（「推断」：XSSF import 证明 poi-ooxml jar 在场，XWPF 类在同一 artifact） |
| **路径 1（零新增，本期推荐）** | **前端 HTML→`.doc` Blob 导出**：Word 可直接打开 HTML 内容的 `.doc` 文件（MHTML/Word HTML 格式），TinyMCE 的 html 产物加 Word 头（`xmlns:o/w/urn:schemas-microsoft-com:office:office` 等）后 `Blob + a[download]` 下载。**零依赖、纯前端**；格式保真中等（复杂表格样式/页眉页脚有限）「推断」。适用于六阶段产物（立项报告/评审结论等）的轻量交付 |
| **路径 2（真 .docx，需 ADR）** | **后端 POI-XWPF 生成真 docx**：复用既有导出模式（`ReportController` GET `/api/v1/report/export/*` 一族，ReportExportResult record {exportType,headers,rows,...}），新增 docx 导出返回文件流。**触发红线"不加新写入端点"评审**（导出为读端点，风险低，但端点新增仍须 ADR 走查）；优点：真 OOXML、模板化、批量 |
| **路径 3（禁止）** | 前端引 `docx`/`mammoth` npm 包 = 违反零新增前端运行时依赖，禁止 |
| **决策** | 本期 word = **路径 1 零新增**；若评审要求真 .docx/复杂版式，再开 ADR 走路径 2。html→docx 一体化（路径 1 的 html 同时是 doc 与预览源）即"单一事实源、双导出面" |
| 证据 | S2（无 docx/mammoth，逐项检索未命中）；S5（ruoyi-common-excel/pom.xml 依赖 fastexcel；Java 源码 import org.apache.poi.xssf.* 实证 poi-ooxml 在场；ReportController + ReportExportResult.java L21–28） |

### 5.3.3 图表

| 项 | 结论 |
|---|---|
| **决策** | **复用 `echarts@^5.5.1`（已装）**。AI 卡片内嵌图表（如门禁评分雷达、项目里程碑甘特近似）直接 echarts init 卡片容器；禁止引 chart.js/antv G2 等新图表库 |
