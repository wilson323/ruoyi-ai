# 项目智能体能力提升研究（2026-09-30）

只研究「一次运行能不能按动作交付」。澄清按钮、逐字输出、Work Buddy 版式对标不在本文重做。不改 Vue / Java，不作为实现单。

对照稿在 `项目智能体对照深入理解AI-Agent-20260930.md`，本文不覆盖它。当天交互设计在 `项目智能体对标WorkBuddy完整设计-20260930.md`。本文以当天磁盘上的 Java / 技能正文为准；设计和代码不一致时，写明哪一边过时。

---

## 1. 裁决：部分闭环

项目智能体已经是单轨任务入口，不是副驾问答的另一张皮。一次 C02 运行可以：冻结能力包、把技能正文和「## 步骤」写进系统提示、在套话或未选定方向时停住不调内核、可选地查本项目已审核资料、再把模型全文存成待审核草稿。

这还不是任务闭环。内核跑完之后，没有程序核对「六步做没做、格子有没有来源、有没有冒充 Gate」。用户看见的「竞品分析报告」可以是一段没有检索命中的散文，只要模型把字写完，运行就是成功，产物就是 `DRAFT`，定档后仍是 `GENERATED` / 待审核 / `NOT_INDEXED`。

一句话：现在会冻结一个能力包，注入技能正文（步骤已被服务端抄进提示词），可选挂上唯一检索工具，然后让模型写一段话。步骤清单停留在提示词和 INTENT 事件里，没有变成执行门禁。

## 2. 用文件证明现在实际会做什么

### 2.1 入口只有这一条运行轨

`ProjectAgentController` 只挂 `/api/v1` 下的能力目录、创建运行、列表、详情、事件、取消、产物 apply。没有第二套 run API。

`ProjectAgentRunPlanner.plan` 做的是冻结，不是规划算法：

- 能力包必须是清单里的 `code + version`。当前 `capability-packs.json` 的 `packs` 只有 `market-research@v1`，`actionCodes` 只有 `C02`，`skills` 只有 `competitor-analysis-ipd`，`tools` 只有 `project_knowledge_search`。
- 请求里的 `skillNames` 必须属于该包，否则 `PARAM_INVALID`。
- 请求里的 `toolIds` 必须属于该包且目录可执行，否则拒绝。清单没实现的工具，`ProjectAgentToolCatalog` 不可用。
- 动作绑定另走 `IpdActionSkillMapService.findByActionCode`：读 `ipd_action_skill_map.skill_names` JSON。显式技能和绑定技能求并集后，只有 classpath 上 sha256 对得上的正文才进入 `LoadedSkill`。绑定名文件缺失则跳过，不编造。请求里点名的技能加载失败则整次拒绝。

种子 `docs/script/sql/update/2026-09-30-ipd-project-agent-seed.sql` 写明：只在 C02 / `CONCEPT-S2` 且 `skill_names IS NULL` 时写入 `["competitor-analysis-ipd"]`。加载时用的是 JSON 清单，不是这张表上的 sha 列。

### 2.2 技能步骤已经是清单文本，还不是执行清单

`competitor-analysis-ipd/SKILL.md` 的「步骤」有六条：检索四个主题，没有竞品名单就停止比较只出缺项；按用户目的裁剪；四维填格并附来源；标可信度和时效；差异只基于有来源的事实；输出固定五段，禁止 Gate 结论、禁止编造、禁止声称联网。

`ProjectAgentIntent.orderedSteps` 只认标题恰好是 `## 步骤` 的有序列表，最多 8 条，正文去编号后逐字保留。已绑定动作且解析出步骤时，`decide` 返回 `needsPlan=true`，`steps` 就是这张表。`prompt` 把同一张表写成「必须遵守，不得改口」「不得增删改序」。`ProjectAgentPrompt.build` 再把整篇技能正文附在后面。`publishIntent` 把 `needsPlan`、`questions`、`steps` 写入已有 `STEP`（kind 为 INTENT）。同一函数算两次（事件一次、提示词一次）。

这部分相对「步骤只是散文」已经往前走了一步：服务端会把技能步骤锁进事件。它仍然不是执行清单，因为：

- 没有逐步状态（未开始 / 进行中 / 完成 / 因缺资料停止）。
- `ProjectAgentRunHandle.finish` 在 `SUCCEEDED` 时把助手全文写成产物 `DRAFT`，不读 `steps`，不读 `SOURCE`。
- 技能第 1 步「无名单则停止比较」只出现在提示词里。意图层对已绑定 C02 的明确句子直接 `planned(skillSteps)` 并放行内核，不会自己停在缺项。

当天设计稿 §6.11 表格里「按句切用户原文、再补核对功能」已和现稿 `ProjectAgentIntent.java` 不符。现稿已改成技能步骤优先，并禁止用动词表给已绑定动作补「核对×」。设计稿 §6.7「澄清仍会进入内核」也过时了：现稿 `start` 在 `shouldAwaitUser` 为真时调用 `awaitUser` 后 `return`，不调用 `kernel.execute`。条件是：问题列表非空的澄清，或「需要计划且没有动作、消息又不是逐字以『按已确认计划执行』起头并带至少一行步骤」。已绑定 C02 的计划不等用户确认计划，展示后直接执行。

### 2.3 内核关掉的能力，比打开的多

`AgentScopeProjectAgentKernel.buildAgent`：

- `skillsEnabled(false)`、`disableDynamicSkills()`、`disableDefaultWorkspaceSkills()`：模型不能再 `load_skill` 换正文。正文只来自上面的服务端注入。
- `disableFilesystemTools()`、`disableShellTool()`、`disableSubagents()`、`disableMemoryTools()`、`disableMemoryHooks()`、`disableTranscript()`、`disableSessionPersistence()`。
- ~~`ToolsConfig.setDeny` 含 `web_fetch`、`web_search`、`wait_async_results`~~。【2026-10-03 实测更正：`ToolsConfig.setDeny(List.of("web_fetch","web_search","wait_async_results"))` 已于 commit `b757fa7a`（commit message 仅 "test"）被删除，当前 `AgentScopeProjectAgentKernel.java:435` 为 `new ToolsConfig()` 空对象。`web_fetch` 实际仍可用并已真实调用成功（由 ProjectAgentOfficialToolGovernance 的 SSRF 防护部分兜底）；`web_search` 无任何出站管控，仅因缺 `TAVILY_API_KEY` 才不可用。依据原描述做的安全判断失效。】
- 只有 `toolIds` 含 `project_knowledge_search` 才注册 `ProjectKnowledgeSearchTool`。注册后若 Toolkit 实际暴露的名字超出本次 `toolIds`，关闭智能体并失败。权限模式是只读治理。

加号里不勾这个工具，Toolkit 就是空的。模型此时没有检索动作可做，只能对着提示词写字。

### 2.4 检索查什么、查不到时模型被允许说什么

`ProjectKnowledgeSearchTool` 的项目 ID 在构造时绑死，schema 不接受模型传入的项目。查询进 `AiDocEmbeddingService.retrieveContext`：只取该项目、当前仍为 `REVIEWED`、未删除的文档，再在对应向量切片里按余弦取 top-K。`GENERATED` 草稿、别的项目、未向量化的审核稿，都不在结果里。检索异常或没有审核稿，返回空上下文，工具把它收成零命中。

零命中时返回给模型的固定句是：`未检索到本项目相关的已审核资料。请在输出中将相关项标注为“未取得”。` 系统提示同时要求：事实只能来自本轮输入和该工具返回；没有来源标「未取得」；不得声称做过未执行的检索；不得输出 Gate 通过或不通过。

这是提示约束，不是输出校验。模型把价格写成具体数字、或写成「资料不足」但没有「未取得」，程序都不会拦截。工具也不是必调：C02 技能第 1 步要求检索，代码没有在进内核前强制打这四次查询。

### 2.5 产物与记忆边界

apply 走已有 `POST /api/v1/agent-runs/{runId}/artifacts/{artifactId}/apply`，调用 `AiDocumentService.createGeneratedAuthorized`。库内状态保持 `GENERATED`，用户可见名是「待审核」，索引回执是 `NOT_INDEXED`。不在 apply 时改成已审核，也不写成 `READY`。

`IpdAgentRun` 注释写明审计规约 L0-5：用户输入只存 SHA-256（`inputDigest`）和字符数，不落原文。这里的 L0-5 是项目审计条目的名字（`IPD全阶段AI代理执行闭环设计-20260926.md`：审计与任务行都不存 prompt / 响应原文），不是本书第 3 章的记忆分层编号。本书没有 L0–L5 这套标签。允许留在库里的是运行状态、事件、产物版本、动作码、能力包版本、技能名和 sha256。

### 2.6 前端只说明能力从哪进

加号选择器（`capability-picker.vue`）提交的 `skillNames` / `toolIds` 必须来自服务端能力目录。提示写明：市场上还没纳入这个能力包的，这次不能勾。`/mcp/market` 是另一套页面（`views/mcp/market`）。数字 id 不是 `project_knowledge_search`。澄清按钮在 `clarification-choices.ts`：从 INTENT 的 `questions` 拆可点项；有成对「」就拆两侧，否则整句是一个按钮。按钮不生成问题。

### 2.7 用户容易以为已经有、代码里没有

| 以为有的能力 | 代码事实 |

## 3. 能力缺口分层

每一层只写：现状、书里读到的主张、IPD 允许怎么做。允许的做法都落在现有类和现有 `POST .../agent-runs` 上。

### 3.1 任务能力：按动作交付

现状。C02 的交付物定义在技能「目标 / 步骤 / 禁止事项」：四维对比或一张缺项清单，供人做 G1-3，深管阻断。运行时把步骤编号后交给模型，不按步推进，也不在缺名单时由程序改走「只出缺项」。未绑定动作的多步计划会 `AWAIT_USER` / `PLAN_CONFIRM`；C02 不会。

书中原则（实际读到）。

- **1.2 Harness 工程**：重心在约束、验证与纠正。流程状态管理要知道执行到哪一步；错误要能停、能交还人。工具本身只是一小部分。
- **1.2.4 编排模式：工作流与自主**：步骤能拆成固定子任务时，用代码规定顺序，模型只在节点内生成。支付未完成不得去订座这一类规则不能靠模型自觉。同一节也警告不要先堆一条复杂多 Agent 流水线；程序只守住必须成立的边界，某类失败反复出现再升级成验证器。
- **2.4.3 流程驱动 vs 规则堆砌**：提示词应是标准作业步骤（做不到就停止），而不是一叠同时适用的零散禁令。
- **2.5.1 Skills**：Skill 是按需加载的操作手册。书主张目录常驻、正文要用时再加载。本项目故意反着做全量注入，是为了 SKILL_LOADED 事件能证明正文进了这次运行。只有一篇 C02 技能时，这个反差不是缺口。缺口是手册没有变成状态机。

IPD 允许的做法。继续用 `ProjectAgentIntent` 解析「## 步骤」。在 `ProjectAgentRunExecutor` 里为已绑定动作增加步骤游标：每步只允许规定的动作（检索或写作），把结果写进已有 `STEP` 的新 kind（与 INTENT、AWAIT_USER、SKILL_LOADED 一样，不新增 `AgentEventType`）。无竞品名单且检索零命中时，程序直接进入「只出缺项」并跳过对比步，而不是再问一次模型该不该停。不要为 C02 再挂一个规划智能体。

### 3.2 工具能力

现状。运行时注册的 toolId 只有 `project_knowledge_search`。目录注释写明 W1 仅此一个只读工具。定价类、渠道政策类技能文件存在，但 `packs[0].actionCodes` 不含对应动作，点名那些 skill 会被判「不属于该能力包」。

做不成真正竞品分析，缺的不是 MCP 市场里的数字 id，而是下面这些**本项目内**的动作（现在都没有 toolId）：

- 一次运行内按主题检索并留下四条独立 SOURCE（功能 / 价格 / 渠道 / 技术），而不是模型自己决定打不打、打几个。
- 把命中片段绑到对比表的格子上。现在 SOURCE 只有 query、hits、preview，产物正文和来源没有格级对照。
- 定价动作（成本、毛利、渠道价）所需的已审核字段读取。正文技能在，工具和能力包不放行。下一期不要为了「看起来像定价师」去接外网行情。

书中原则。

- **4.2.1 能力的表达形式**：专用工具参数受 schema 约束；Skill 用自然语言写流程，靠通用执行器去做。书的默认是通用工具优于专用工具，除非有明确的安全、权限或性能理由。
- **受控执行 4.1 / 4.2**（`04-controlled-execution.md`）：模型看见工具、Harness 注册工具、本次任务获准执行，是三件不同的事。MCP 能描述工具，不代替授权、租户隔离和业务验证。工具粒度应是一个可授权、可观察、可验证的业务动作。
- **plan-mode.md**：Plan 阶段只留只读工具，写操作在人确认前被拒绝，拒绝发生在工具层而不是提示词。计划文件默认写到 `plans/PLAN.md`。本文不采用这套文件。

IPD 允许的做法。安全理由已经足够：不上 shell、不上网。不要把书的「默认通用执行器」搬进来。下一期仍只暴露 `project_knowledge_search`，但由执行器按技能第 1 步代为调用四次（同一工具、不同 query），调用结果走现有 `SOURCE`。用户加号取消该工具时，C02 不得冒充已检索，只能走缺项或要求先把资料定档。定价不在下一期：先改能力包就会变成第二个产品面，超出「一次 C02 更强」。

### 3.3 资料能力

现状。检索域 = 当前项目 ∩ `REVIEWED` ∩ 当前嵌入模型的切片。未命中句要求模型写「未取得」。已审核但还没向量化的文档，检索侧也是空，代码不会告诉模型「库里有这篇，只是还没有向量」。

书中原则。

- **3.3.4 智能体化 RAG**：传统 RAG 是查一次就写。智能体化 RAG 是反复改查询、交叉看材料，材料够了再动笔。
- **3.3.3 冲突与失效**（同一章，紧挨 3.3.4 之前读到）：证据不足时保留冲突和待确认，不得收成一个确定结论。检索必须按调用者权限过滤，越权内容不能进上下文。

IPD 允许的做法。权限过滤已经做了（项目绑死 + 只读）。下一期允许的「更智能」只限于：四个固定主题各查一次，零命中就在产物模板里写入「未取得」，并由验证器拒绝出现具体价格或竞品名却没有命中。不增加跨项目语料，不把用户没点过审的生成稿检进来。未向量化与「真的没有资料」要在 SOURCE 里分开，否则模型会把「还没建索引」说成「项目没有竞品资料」。这一条要改 `retrieveContext` 的空结果原因，或在工具侧区分 `approved` 为空与候选切片为空。仍用同一个工具名。

### 3.4 判断能力：直答、澄清、计划

现状。`decide` 不调模型。套话或空消息 → 固定问句。选择型「还是」（两侧各 2～12 字，且不是「还是要 / 继续 / 需要 / 先」）→ 一句带「」的问题。有动作且技能有步骤 → 计划并执行。有动作但没有步骤节 → 一句「按动作 X 与已加载技能执行」。无动作且至少两个动词分句 → 计划并等待确认。其余直答。

澄清按钮的选项全部来自这几句。技能正文、模型，都不是选项来源。因此用户点的经常是整句「请说明要交付的结果…」，而不是「只出缺项」或「按已上传的三家资料做四维表」。

书中原则。

- **1.2.4** 与 **6.2.4 用户沟通工具**：信息不足应先确认再动作；对人说话可以是显式动作。书里的沟通工具是独立消息通道。本项目已有 INTENT 卡片和按钮，不必再做一个 `reply_to_user` 工具。
- **9.2.2 将经验写成指令**：Skill 规定某领域该怎么做；系统提示对所有任务生效；硬约束归程序。反思句子本身不是证据。

IPD 允许的做法。问题仍由 `ProjectAgentIntent` 生成，不增加一次意图模型。C02 技能增加可解析的固定选项（frontmatter 里短列表，或「步骤」前的固定小节，二选一，不要两套）。模糊输入时，问题改成这些选项，界面现有「」拆分就能变成按钮。已写明范围的句子仍走技能六步，不要用固定句把合法的「资料不够只出缺项」拦成澄清。未绑定动作的计划确认保持现有「按已确认计划执行」起头，不要再发明确认 API。

### 3.5 验证能力

现状。没有验证器。`finish(SUCCEEDED)` 只看有没有助手文本。技能要求的五段标题、来源格、禁止 Gate，都不检查。

书中原则。

- **7.4.2 验证器**：模型可以写一篇看起来完成的报告。评估必须核对机器能独立复核的事实，而不是 Agent 的自我陈述。只证明「修好了」不够，还要证明「没弄坏」（SWE-bench 的两组测试）。书同时写明开放式任务往往只能用 rubric，不能假装有唯一字符串答案。
- **5.1 从 Coding Agent 抽出的原则**（紧挨 5.1.5 之前读到）：能用代码强制的就不要写成「请遵循」。验证要自动。反馈要靠近出错时刻。结果对了但过程违规（为了交差删掉数据）仍然失败。
- **9.3.1 可验证闭环的边界**：开放式写作很容易稳定地产出「像成果的东西」。要求把结论和证据分开；找不到来源的数字不能算发现。
- **受控执行 4.4 / 4.6**：高影响动作走预览、批准、提交、再查真实状态。失败后的正确补丁是拆开动作并加确定性回归，不是在提示词里再加一句「请谨慎」。

IPD 允许的做法。在 `ProjectAgentRunHandle` 落 `DRAFT` 之前加一个纯函数检查（可放在现有 handle 或旁边的一个无 I/O 类，由 handle 调用）。C02 最低检查：

- 有对比表时，每个价格 / 竞品格必须能对上本次 SOURCE 的非零命中；对不上则整段改为缺项，或运行 `FAILED`（选定一种，不要两种语义并存）。
- 正文含「通过 / 不通过 / 建议 Gate 签署」一类结论 → 不落成功产物。
- 「资料核对、对比表、差异机会、冲突与待确认、缺项清单」五段标题缺任何一段，且并非程序选择的「只出缺项」短路路径 → 不算成功。
- 只出缺项是成功的一种，条件是检索零命中或用户明确没有名单，并且正文出现「未取得」。

没有这条检查，`SUCCEEDED` 只表示「模型说完了」。书中的主张和本文的完成定义一致。

### 3.6 记忆能力

现状。单次运行的事件是追加日志（状态、技能 sha、工具 SOURCE、文本增量、产物 id）。用户原文不在 `ipd_agent_run`。长期记忆工具被内核关掉。跨运行能看见的是动作码、产物标题和正文、技能版本与摘要，不是提问原文。

书中原则。

- **3.1.2 记忆的层次结构**：一次运行的轨迹按时间追加、不改旧记录；发给模型的上下文可以压缩。长期记忆是跨会话提炼后的稳定条目，会合并和淘汰。另有开发者定义的任务状态（需要澄清、处理中、完成）。书强调原始轨迹是否全留取决于审计要求，不要求把用户原话永久放进提示词库。
- **9.2 将经验沉淀为知识**：原始轨迹是证据，可复用的是带来源和适用边界的知识文档。反思草稿在被环境和跨轨迹证据支持之前，不能当正式经验。

IPD 允许的做法。记下运行状态、产物版本、动作码、技能名与 sha256 / 清单版本。不要新增「提示词原文」列，也不要把 `inputDigest` 当搜索词。C02 若要把「上次缺了价格来源」留给下次，只允许写成产物里的缺项清单（人审核之后才可能被检索到），或写成技能版本的人工改稿。不要让模型把上一轮用户句子写进库。

技能版本有一处事实要对齐，否则「记住的版本」是错的：`capability-packs.json` 把 `competitor-analysis-ipd` 标成 `1.0.0`，`SKILL.md` frontmatter 写 `1.1.0`。`load` 采用清单上的版本。当前文件字节的 SHA-256 是 `f6f7d41621e897096980e338b4375256626672a25e8060f24d52cefaaf5f0ad2`，与 JSON 清单一致，所以技能能加载。种子 SQL 注释和 INSERT 里仍是另一枚 `28d695be…`。`INSERT IGNORE` 不会改已插入行。运行时不读那一列。

## 4. 下一期路线：只让一次 C02 更强

排序按「用户下一次做竞品分析时先看见什么」。每项都改现有类，仍走 `POST /api/v1/projects/{projectId}/agent-runs` 和现有 apply。不新开智能体。

1. **成功前自检（最先做）**  
   改 `ProjectAgentRunHandle`（落草稿之前）和 C02 技能里已写明的五段标题、未取得、禁 Gate。新增的是检查函数，不是 API。  
   验收：零命中夹具下，模型回复里的假价格不会变成 `SUCCEEDED` 产物；缺项路径可以看到标题含「未取得」的草稿；含 Gate 结论的全文不成功。测试放在现有 handle / apply 测试旁。用户看得见：失败运行有错误文案；成功的对比表或是缺项单，而不是一篇无来源的报告。

2. **技能第 1 步改成四次必做检索**  
   改 `ProjectAgentRunExecutor`：已绑定 C02 且 `toolIds` 含检索工具时，进内核前用现有 `KnowledgeRetriever` 查「竞品」「价格」「渠道」「技术方案」，SOURCE 照旧。用户没勾工具则不查，INTENT 或后续验证标明「未检索」。  
   验收：事件里有四条 SOURCE，再出现正文。用户看得见本次运行中间栏的来源卡，而不是只在文末声称检索过。

3. **步骤游标：做到哪一步可回放**  
   改 `ProjectAgentIntent` 已产出的 `steps`，执行器按条写入已有 `STEP`（新 kind，例如沿用「步骤状态」这一个 kind，六步重复它，不新增事件类型枚举）。对比步只有在检索有命中或用户原文点名竞品时才允许写表；否则标记该步跳过，原因是缺资料。  
   验收：单测断言 kind 序列包含六步或「检索后跳过对比」。用户看得见计划卡上每一步的完成或跳过，而不只是一段提示词。

4. **澄清选项改从 C02 技能来**  
   改 `competitor-analysis-ipd/SKILL.md`（增加固定选项，并同步 JSON 的 sha256 与版本号）和 `ProjectAgentIntent.questionsForVague`：套话时发出带「」的两个选项，例如只出缺项、按本项目已上传资料做四维。`clarification-choices.ts` 已能拆「」。不要改按钮组件来生成问题。  
   验收：现有意图单测增加一条套话，问题里出现技能规定的两侧原文；「我还是要做竞品的功能和价格」仍不走选择型澄清（现有负例保持）。用户看得见两个按钮，点下去的新运行 message 仍是现有 `已选：…` 短句。

5. **空检索原因分开（做完 2 再做）**  
   改 `ProjectKnowledgeSearchTool` 对 `retrieveContext` 空结果的用词，必要时让 `RetrievalContext` 多一个已有结构里的计数字段（审核稿数 vs 命中数），不新接口。  
   验收：项目无 `REVIEWED` 文档与「有审核稿但相似度为 0」返回不同句子，模型侧提示分别是「未取得」和「有文档但本次主题未命中」。用户在来源卡上看得到 hits 与原因。

定价、需求澄清后的外部检索、第二个能力包，排在这次 C02 自检之后。原因：包外技能现在根本不会进入这次运行，加它们不会让当前这一次竞品分析更有来源。
