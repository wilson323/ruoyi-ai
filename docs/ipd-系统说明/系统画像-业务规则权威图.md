### 5.4 前端镜像与两套闸

| 组件 | 位置 | 作用 |
|---|---|---|

**两套闸与后端注解闸的配合**（三层）：
1. **前端菜单/路由闸**（`meta.access`）—— 用户看不到入口。纯 UX 层，**不构成安全边界**。
2. **前端按钮闸**（`v-access:code`）—— 行内按钮显隐。同样纯 UX 层。
3. **后端注解闸**（`@SaCheckPermission`）+ **方法体对象级判定**（`IpdPermission.requireInternal/requireLeaderOrAdmin` / `IpdIdorGuard`）—— **唯一的安全边界**。

- 设计原则（L172-178 `IpdPermissionCode.java`）：注解层只把住「此类操作可被哪一类内部角色调」；**对象级（项目成员 / 双签人 / 申请人）仍由 service 的 `IpdIdorGuard` 二次校验**。
- **注解层有码、目录无码 ⇒ 连超管都 403**（2026-09-06 已发生，见 `IpdRolePermissionCatalog.java:40-41` 注释）。**新增权限码必须同时登记 catalog，否则端点死锁。**
- **R234 补登记的 3 个孤儿码**（`gate-review:add` / `gate-review:edit` / `handover:cancel`）：后端端点无 `@SaCheckPermission`，走 `requireInternal/requireLeaderOrAdmin` + Service 对象级判定，**登记目的只是让前端按钮闸能亮**（`IpdRolePermissionCatalog.java:28-34`）。不登记会导致功能不可达。

### 5.5 前后端镜像门禁

- 前端镜像对账由**后端仓** `scripts/check-permission-mirror-fe-be.sh` 承担（R234）。
- ⚠️ 前端单测 `ipd-permission-codes.test.ts:1` 自述「**与后端镜像对账由后端仓门禁承担**」，本用例只锁前端自身计数（92 keys / 91 distinct），**不宣称与后端一一镜像已验证**。引用「前后端权限码已对齐」前须跑门禁。

### 5.6 权限可见性矩阵（产品设计口径）

`docs/开发说明/spec/_导航地图.md:189-203`（BR-ORG-06）：游客 / 普通PM / 产品组长 / 超级管理员 四列 × 页面组。要点：
- 项目查看范围：普通PM 仅本人负责 / 组长本组全部 / 超管全部；项目编辑：普通PM 仅本人负责 / 组长**仅本人名下** / 超管全部。
- **权限不足时不隐藏入口**，展示禁用态 + Tooltip 说明原因（`:203`）——与前端 `meta.access` fail-closed 拦截**在体验上不一致**，需注意：`ipd-guard` 拦截是跳 `IPD_NO_ACCESS`（`router/ipd-guard.ts:15`），不是禁用态。**这是设计与实现的一处口径差，登记为待观察项。**
