**根因（修订）**：R25 9 大门禁**常态化跑过多次（docs/ipd-系统说明/lint-reports/ 现存 76 个 SSOT 报告，包含 doc-link / dynamic-loadable / duplicate-ssot / tenant-excludes-apply / entity-complete / i18n-unused-keys 等 8 类门禁的周期性输出）**，扫描+写报告机制 100% OK。**但 exit 阻断机制真失效仅 2/9**（tenant_excludes_apply 缺分支 + deletion_consistency exit 2 不标准）——**R119 原判 4/9 失效，其中 dynamic_loadable / duplicate_ssot 实测 EXIT=0 经 R120 落地后经验性证明是"无差异=健康"的正确状态**，属误判。本质是 R119 当时未跑 A agent ENV 自证分支可达就登记"机制失效"。R120 落地后 4 个脚本统一加 `if [ "${DIFFS:-0}" -gt 0 ]; then exit 1; fi` 退出分支并自证能红。

## 教训沉淀（R119 系统性反思核心）

1. **机制失效 = 假绿的镜像（修订）**：R25 9 大门禁**扫+写报告跑常态化**（76 个 lint-reports/ 证明），但 **exit 阻断 4/9 失效**——本质是脚本作者只测了“扫+报告”对不对，没测“阻断”是否触发。
2. **shell pipe trap**：本会话修了 2 次同一类 bug（覆盖脚本 set -e + if DIFFS + shell `| tail; echo $?` 误判）。**根除建议**：所有脚本验证 EXIT 必须用 `bash X.sh >/dev/null 2>&1; echo $?` 模板，不带管道。
3. **R25 9 + R119 5 = 14 脚本正交覆盖**：R25 是症状层，R119 是机制层。**不是包含而是正交**，没必要重写 R25 已有脚本。
4. **撞车兄弟会话是最难根除的病根**：R118 首次发现 PID 34560 兄弟会话 ry-vue 后端跑 23306，R119 把"兄弟会话进程撞车"纳入 reconcile + 提交完整度脚本，但**根治需 R25 软化"完整接手兄弟在途" + 5 必查 chat 机制规范**，是治理层问题非脚本能解决。
5. **ahead commit 0 可救 = 14 天治理证据**：R114/R117 体检证明兄弟会话 ahead commit 全部被 main 吸收，证明**R25 治理轮以来 main 已收敛稳定**，未来 6 个月重点是根除机制常态化执行而非新代码治理。
6. **真活 E2E 是 R119 最大盲区**：R109-R118 10 轮治理没跑过真活 E2E（前端 vite + 后端 fat jar + 真库）。check-e2e-fe-be.sh 落地是 P0 优先级，但**当前撞车 0 状态无法常态化跑**——需先确认是否起 IPD 后端连 ipd_dev 库。
