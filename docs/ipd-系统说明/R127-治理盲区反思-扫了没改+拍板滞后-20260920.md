### 机制 M2：拍板时限红线

**问题**：R121 拍板 7 天未决，无时限红线、无升级机制、无看板标红。

**机制**：
- 默认拍板时限 = **7 天**（可由 owner 调整为 14 天）
- 超 7 天未决 → 自动：
  1. 标红看板（SSOT 镜像对应行加 ��）
  2. 升级到 owner 邮件 / 飞书 / 钉钉（按团队配置）
  3. 自动派单 worktree（取默认整改方案，撞车 0 让路表 → owner wt）

**落地清单**：
- `scripts/check-decision-deadline.sh` 每日 cron 检查拍板项清单

- 看板镜像对应行加 `🔴` 标红

### 机制 M3：整改派单序列化

**问题**：当前 worktree 累计 8 个（含 R125 D1B/D3B/R119/R120/R121/R126 共 7 个未合并 + R127 wt），派单堆积无序列化。

**机制**：
- 每次派单**只发一个 wt**，闭环（merge 到 main）后才发下一个 wt
- `scripts/check-wt-stacking.sh` 巡检 worktree 堆积数：> 5 触发告警
- 累计闭环率（已 merge / 总派单）纳入 SSOT 镜像周报

**落地清单**：
- `scripts/check-wt-stacking.sh` 巡检脚本（每周日 02:00 跑）
- `docs/ipd-系统说明/开发计划-看板镜像.md` 新增"worktree 累计表"

### 机制 M4：跨仓 cd 绝对路径强校验

**问题**：R91 §5 必查项规定"跨仓命令必 `cd /Users/mac/Documents/<repo> &&` 开头"，但无 pre-commit hook 强制校验。

**机制**：
- `pre-commit` hook 检查 git command 中 `cd /xxx-绝对路径 &&` 模式
- 未带绝对路径前缀的 `cd` 命令 → commit 阻断 + 提示修正

**落地清单**：
- `.husky/pre-commit` 或 `.git/hooks/pre-commit` 新增 `check-cd-absolute-path.sh`
- 触发条件：commit msg 含 `cd ` 字符串但不含 `cd /`

**问题**：`check-e2e-fe-be.sh` 写好且自证能红，但 CI/CD 未接入，**不能 merge 阻断**。
