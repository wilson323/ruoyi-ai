## 二、假绿类型描述

### 2.1 现象

Maven Surefire 配置按 profile 过滤测试组：

```xml
<configuration>
  <groups>${profiles.active}</groups>
</configuration>
```

- dev profile 启 `groups=dev` → 只跑 `@Tag("dev")` 的测试
- 新写的测试**忘记加 `@Tag("dev")`** → Surefire 静默跳过
- CI 报 `Tests run: 0, Failures: 0, Errors: 0, Skipped: 0` → 全绿
- 实际新代码 100% 没测试覆盖，但 CI 假装"全绿"

### 2.2 根因

- Surefire `<groups>` 过滤 + 新测试默认 `@Tag("integration")` / 无 tag
- `mvn test -P dev` 跑 0 个新测试 → exit 0 = "全绿"
- 治标不治本：CI 全绿 = 没有意义的假绿（0 测试 = 0 失败 = 100% 通过率）

### 2.3 影响

- ✅ CI 全绿（0 测试 0 失败）
- ❌ 新代码 100% 无测试覆盖
- ❌ 反脆弱指针 #133 F-GREEN 假绿改造：测试全绿毫无意义 = 飞轮失活
- ❌ owner 拍板 #1 解锁后 E2E 跑下来 → 新代码全部未验证 → 500

## 三、修复方案（docs-only — 不实装）

### 3.1 设计目标

强制所有测试必须有 `@Tag`，且 dev profile 必须跑全部测试：

| Surefire 配置 | 当前 | 目标 |
|---|---|---|
| `<groups>${profiles.active}</groups>` | 过滤 tag | 删除（默认跑全部）|
| `<excludedGroups>integration,e2e</excludedGroups>` | 无 | 显式排除耗时集成测试 |
| `<failIfNoTests>true</failIfNoTests>` | 无 | 强制至少跑 1 个测试 |
| `<trimStackTrace>false</trimStackTrace>` | 默认 true | 改为 false 保留完整堆栈 |

### 3.2 实现路径（待 owner 拍板 #4 + #6 后由后续 R 轮实装）

1. 修改 `pom.xml` 中 `surefire-plugin` 配置：删除 `<groups>${profiles.active}</groups>` + 新增 `<failIfNoTests>true</failIfNoTests>` + 新增 `<excludedGroups>integration,e2e</excludedGroups>`
2. 新增 `scripts/check-test-coverage.sh` 实跑 `mvn test` → 必须有 `Tests run: ≥ 1`
3. 新增 git-hook pre-commit：禁止提交无 `@Tag` 的测试类（`grep -L "@Tag" src/test/java/**/*Test.java` 应为空）
4. 在 CI pipeline 加 `mvn test -P dev` + `Tests run: ≥ 1` 检查

### 3.3 自证能红（FAIL_SEED 双向触发）

```bash
# 正常态：删除 <groups> 过滤 + failIfNoTests → 所有测试必跑 → PASS
$ TEST_MUST_RUN=1 bash scripts/check-f-green-type3.sh
✅ Surefire <groups> 过滤已删除 + failIfNoTests=true → Tests run: ≥ 1
EXIT=0

# 注入 FAIL_SEED：故意恢复 <groups> 过滤 → FAIL
$ FAIL_SEED=1 bash scripts/check-f-green-type3.sh
🔴 Surefire <groups>${profiles.active}</groups> 过滤仍存在 → 新测试被静默跳过 → 假绿
EXIT=1（PASS — 双向触发）
```
