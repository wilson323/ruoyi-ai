## 1. 架构总览

新增包 `org.ruoyi.ipd.service.aiexec`，5 组件，全部复用既有基础设施：

```
触发源（人点按钮 / 对话填表 / 业务状态变更事件 / 定时扫描）
   │
   ▼
AiExecutionTrigger          ← 统一触发入口（唯一写 ai_agent_tasks 的地方）
   │  落任务行 PENDING + afterCommit 立即派发
   ▼
AiExecutionEngine           ← 编排核心：抢占任务 → 查 exec_mode → 路由 → 收尾
   │
   ├─ AI_DIRECT   → LightDirectExecutor / DeepDirectExecutor
   ├─ AI_GENERATE → GenerateExecutor（产物挂 ai_documents）
   └─ HUMAN_GATE  → GatePrepExecutor（只备料 + 发人审待办，不签字）
   │
   ▼
执行结果 → 既有业务 Service 写库（executor=AI 系统身份）
        → IpdAudit 同步审计（AI_EXEC，aiAssisted/aiModel/aiRole 三件套）
        → 任务行翻 SUCCEEDED / FAILED（退避重试≤3）/ DEAD（通知人接管）
```

**核心接口**（接 69 动作 = 写适配器 + 填矩阵，引擎零改动）：

```java
public interface AiActionExecutor {
    Set<String> supportedActionCodes();               // 与矩阵对账，哨兵守护
    AiExecResult execute(AiAgentTask task, AiExecContext ctx);
}
```

**四条纪律**：
1. 任务行状态机 `PENDING→RUNNING→SUCCEEDED/FAILED/DEAD`，抢占用条件 UPDATE 乐观守卫（复制 outbox 先例），多实例安全。
2. 业务写入一律经既有 Service（canonicalizeAction / validateCompletion / DefaultStateMachineGuard 防线对 AI 同样生效），执行器禁止绕过直写 mapper。
3. `Clock` 注入缝（测试三禁·禁一）。
4. 重试 3 次指数退避（30s/2m/10m）→ DEAD 发通知人接管；AI 失败不静默，人始终可走原手工路径（AI 是快车道不是唯一车道）。

## 2. 数据模型

### 2.1 ActionDef record 扩展

`domain/ActionDef.java` 新增第 11 字段 `String execMode`，三档：

| execMode | 语义 |
|---|---|
| `AI_DIRECT` | 确定性执行：直接填状态/归集/测算/预检，写业务表 |
| `AI_GENERATE` | 生成式执行：异步产出交付物草稿挂 ai_documents，再回填动作 |
| `HUMAN_GATE` | AI 只备料 + 发待办，等人签（gate 非空动作强制此档） |

`ActionCatalog.ALL` 69 行逐行补 execMode（定案全表见附录 A）。哨兵断言三条：
- execMode ∈ 三档白名单；
- `gate≠"" ⇒ execMode=HUMAN_GATE`；
- AI_DIRECT/AI_GENERATE 动作码必须被某 `AiActionExecutor.supportedActionCodes()` 覆盖（防"登记了没人实现"假绿；分批接线期用「已接线清单」显式豁免未接批次，豁免名单进哨兵常量，不许静默漏）。

### 2.2 新表 ai_agent_tasks（任务队列 = 持久化事实源）

```sql
CREATE TABLE ai_agent_tasks (
  id              BIGINT       NOT NULL PRIMARY KEY,
  tenant_id       VARCHAR(20)  DEFAULT '000000',
  project_id      BIGINT       NOT NULL,
  action_code     VARCHAR(10)  NOT NULL COMMENT '对应 ActionCatalog',
  stage_action_id BIGINT       NULL COMMENT '挂接动作实例（被动触发必填）',
  trigger_type    VARCHAR(16)  NOT NULL COMMENT 'PASSIVE/CHAT/EVENT/SCHEDULE',
  exec_mode       VARCHAR(16)  NOT NULL COMMENT '触发时矩阵快照，防目录变更语义漂移',
  status          VARCHAR(16)  NOT NULL COMMENT 'PENDING/RUNNING/SUCCEEDED/FAILED/DEAD',
  dedup_key       VARCHAR(128) NOT NULL COMMENT 'actionCode:stageActionId:triggerType',
  attempt         INT          DEFAULT 0,
  next_retry_at   DATETIME     NULL COMMENT '指数退避 30s/2m/10m，>3 次翻 DEAD',
  input_digest    VARCHAR(64)  NULL COMMENT '入参指纹（不存 prompt/敏感原文）',
  fill_payload    JSON         NULL COMMENT 'CHAT 触发的结构化填表载荷（§3.5）',
  result_summary  VARCHAR(1024) NULL COMMENT '业务写入摘要，供通知/审计消费',
  ai_doc_id       BIGINT       NULL COMMENT 'AI_GENERATE 产物挂 ai_documents',
  error_msg       VARCHAR(512) NULL,
  triggered_by    BIGINT       NULL COMMENT '被动/对话触发的真人 ID；主动触发 NULL',
  version         INT          DEFAULT 0 COMMENT '乐观锁（条件 UPDATE 抢占）',
  create_time     DATETIME, update_time DATETIME,
  del_flag        CHAR(1) DEFAULT '0',
  KEY idx_scan (status, next_retry_at),
  KEY idx_dedup (dedup_key, status),
  KEY idx_project (project_id, action_code)
) COMMENT='AI 代理执行任务队列（R221 闭环设计）';
```

幂等定案：**触发前查询守卫**（同 dedup_key 且 status ∈ PENDING/RUNNING 存在即跳过返回既有任务 ID），不用唯一索引+生成列。极端并发双写的残余风险由执行器幂等兜底（状态机 + 乐观锁拒绝非法二次流转，重复任务空跑标 SUCCEEDED(no-op)）。

### 2.3 建表配套三件套（两个已知坑前置登记）

1. DDL：`docs/script/sql/update/20260926-ai-agent-tasks.sql`（人工 apply；SQL commit ≠ 已生效，验收前跑 apply 核验）。

## 3. 触发链路（事件 + 定时双轨 + 对话）

**总原则**：不引入 Spring 内存事件总线（ipd 模块无先例、审计刻意同步）。"事件轨"= 显式 hook 调用 + 任务行落库，任务行本身就是持久化事件。

### 3.1 PASSIVE 被动（人点按钮）

动作详情页「AI 执行」按钮 → `POST /api/v1/stage-actions/{id}/ai-execute` → `triggerPassive()`：同事务写任务行 PENDING（triggered_by=当前真人）→ `TransactionSynchronization.afterCommit` 提交引擎线程池立即跑。人不等待，页面轮询任务状态。

### 3.2 EVENT 事件（业务状态变更自动触发）

业务事务内一行显式调用（回滚则任务同灭，无幽灵任务），首切片埋 2 个 hook：
- `ProjectBootstrapService.bootstrap` 批量插入成功后（L128-130 位置）→ 对 dueDate 最近的 AI 档动作建任务（AFTER_COMMIT 语义派发，不拖长 bootstrap 事务）；
- `AiDocumentService.review` 审核通过后 → 若该文档挂接着 AI 任务的产物 → 自动 `addDeliverable` + `transit(DONE)` + 唤醒同阶段后继动作（**人只审核，不操作**的闭环点）。

### 3.3 SCHEDULE 定时兜底（两扫描器分工）

- `AiTaskFallbackScanner`：`fixedDelayString 30s`（outbox 口径，错峰表豁免登记）——扫 PENDING 滞留超 60s + FAILED 退避期满 → 重新入池。
- `AiProactiveScanScheduler`：cron `0 55 9 * * ?`（09:55，登记 IpdSchedulingConfig 错峰表，哨兵断言 B 自动守护）——每日扫「7 日内到期、未完成、AI 档、无未完成任务行」的 stage_actions → 建 SCHEDULE 任务。这是 AI 主动性的日常来源：不等逾期，提前备货。

### 3.4 派发与并发

`AiExecutionEngine.dispatchCycle(limit=50)`：扫 PENDING/到期 FAILED → 条件 UPDATE 抢占（`WHERE id=? AND status='PENDING' AND version=?` → RUNNING）→ 路由 executor → 收尾。引擎专用小线程池（core 2，AI_GENERATE 长耗时不占 Tomcat 线程），异步降级范式抄 `embedAsync`（守护线程池 + 异常只 WARN 不炸主链）。

### 3.5 CHAT 对话即填表（owner 2026-09-26 补充拍板）

**用户故事**：作为页面主角色，我要在全局 AI 副驾浮钮里用自然语言说"帮我把这个动作的基准值填了/把这份表单按调研结果填好"，AI 生成结构化字段值直接回填当前页面表单，以便不手动逐项录入。

**链路**：
```
前端表单页注册 fillContext（scene + 字段 schema 白名单 + 当前值）
→ 副驾对话带 pageContext 发 POST /ai-copilot/chat（或 stream）
→ AiCopilotService 新意图 FILL_PAGE（对齐既有 TASKS/ADVANCE 确定性意图分支）
→ AiGateway.chat 生成 JSON 字段值（RAG 注入项目上下文）
→ 后端 schema 白名单校验（schema 外字段一律丢弃并记审计）
→ SSE done 帧携带 fillPayload {scene, fields, mode}
→ ai-assistant.vue 经全局注册表把 fillPayload 投递给宿主页面
→ 页面表单自动填充 → 人目检
   ├─ mode=suggest（默认）：人点既有「保存」走原端点落库
   └─ mode=auto：仅 AI_DIRECT 档且无敏感字段时，转 PASSIVE 任务直接落库
```

**安全红线**：
- 字段白名单由页面 schema 声明，AI 永不触碰 schema 外字段（后端强校验，非仅前端）；
- 敏感字段（金额/绩效评分/贡献度系数/删除/移交类）**永远 mode=suggest**，只填不自动提交；
- 填表动作落审计 `AI_FILL`（aiRole=agent_exec，input_digest 指纹，不存对话原文）；
- CHAT 触发同样落 ai_agent_tasks 行（trigger_type=CHAT，fill_payload 列存载荷），全程可追溯可重放。

**首切片接线**：动作详情页 C08 四项基准值表单支持对话填充（suggest 模式）。

## 4. 执行器族与首切片

### 4.1 矩阵定案原则与缺口处置

存疑动作按**主产物形态**裁决：产物是文档/报告/方案 → AI_GENERATE；产物是结构化字段/状态/数值 → AI_DIRECT。全 69 行定案见附录 A（HUMAN_GATE 5 / AI_DIRECT 40 / AI_GENERATE 24）。

**4 个"评审/审批语义但 gate 空"缺口**（D03/D06/V06/LC04）：不改 ActionCatalog 的 gate 字段（产品圣经动作目录工程侧无权补挂 Gate），人审语义由各自领域既有人签点承载（ADR-4）：D06→变更域审批链；LC04→ContributionService.confirm 组长终裁；V06→AI 备评审材料、人页面登记结论；D03→AI 仅登记样机状态（物理动作不伪造完成）。

### 4.2 执行器族（4 适配器覆盖三档）

| 执行器 | 覆盖 | 行为 |
|---|---|---|
| `LightDirectExecutor` | LIGHT+AI_DIRECT | `recordFields` 写日期/数值 → `transit(DONE)` 全自动 |
| `DeepDirectExecutor` | DEEP+AI_DIRECT | 归集/测算 → 测算单落 ai_documents → `addDeliverable` 挂接 → `transit(DONE)`（满足 BR-IPD-03 深管证据 ≥1 交付物） |
| `GenerateExecutor` | AI_GENERATE | `AiGenerationService.generate`（RAG/SSRF/预算/限流防线全复用）→ 草稿 GENERATED → `transit(IN_PROGRESS)` → 通知人看；人审核通过 → §3.2 hook 自动挂交付物 + DONE + 唤醒后继 |
| `GatePrepExecutor` | HUMAN_GATE | `judge` 要素判定草稿 + 评审材料/纪要生成 + `submit` 开启签署期 → 通知双 PM；`sign/arbitrate/finalRuling/reopen/extendDeadline` 保留真人 |

系统身份：执行器构造 `IpdActor`（systemOperatorId=0 通道，KPI 扫描器先例）；`AiGenerationService.generate` 要求 actor.id() 非空，系统 AI 账号 ID 定为常量 `AI_SYSTEM_PERSON_ID=0L`。

### 4.3 首切片（阶段动作推进链，三档各一 + 人审备料 + 对话填表）

**接线 4 动作**：C01 市场调研（AI_GENERATE）、C08 四项基准值归集（DEEP AI_DIRECT + 对话填表）、P08 计划排期核对（LIGHT AI_DIRECT）、C11 Charter 评审会（HUMAN_GATE 备料）。

**闭环验收剧本（三证律）**：
```
主动链：bootstrap → EVENT 建任务 → 引擎跑 C01 调研 → 草稿 GENERATED
        → 通知市场PM → 人审核通过 → EVENT 自动挂交付物 + transit(DONE) → C02 被唤醒
被动链：动作详情页点「AI 执行」→ PASSIVE 任务 → 同上
对话链：副驾说"填 C08 基准值" → fillPayload 回填表单 → 人点保存落库
人审链：C11 到期 → GatePrepExecutor 备料 + submit → 双PM 收待办 → 真人盲签 → settle
```

## 5. 审计留痕与最小人审集面

### 5.1 最小人审集（8 类人签点，角色硬校验全部内置于 Service，AI 结构上无法代签）

| 域 | 人保留（不可代理） | AI 备料（全自动） |
|---|---|---|
| Gate | `sign`（盲签）、`arbitrate`/`finalRuling`、`extendDeadline`、`reopen` | `judge` 草稿、材料+纪要生成、`submit`、超时/催签扫描（既有） |
| 绩效/金额 | `ProjectScoreArchiveService.submit`、`ContributionService.saveSelf`（本人）、`confirm`（组长终裁）、`BonusPoolService.freeze`+`distribute` | 评分草稿+依据、五维自评预填、分配方案试算、门禁预检 |
| 删除 | `leaderDecision`、`adminDecision`（超管逾期仅提醒不自动通过——保守原则保留） | 实体快照、删除影响清单、`submit` 代发、终审核对单 |
| 移交 | `accept`（接手人）、`initiateOnBehalf`/`batchHandover`、`transferSuperAdmin`（确认短语级） | 移交清单、资格预检、批量干跑预演 |

**盲签遮蔽红线**：G1/G5 双签互不可见——AI 辅助材料必须复用 `rowView` 字段级遮蔽视图，揭示前不得把一方结论喂给另一方；执行器直查 mapper 视为违规（契约测试锁死）。

**通知缺口修补**（4 处，管道现成、eventType 自由字符串零基建改动）：贡献度 SUBMITTED、奖金池 DRAFT 就绪、删除 submit/初审后、移交 createDraft 后各补一个 `NotificationService.publish`（KIND_ACTION + actionUrl 深链）；`Types` 登记 `AI_PREPARED_*` 常量；删除域 `DEL_*` 三常量"已定义零调用"死账一并接线。

### 5.2 审计

- 新 action：`AI_EXEC` / `AI_EXEC_FAILED` / `AI_FILL`（action 自由字符串无白名单阻碍）；`IpdEntityType` 登记 `ai_agent_task`。
- `AuditEventData.AI_ROLES` 追加 `agent_exec`（requireAiTrail 门禁强制三件套，天然合规）。
- 审计与任务行都不存 prompt/响应原文——只存 `input_digest` 指纹 + `result_summary`（对齐 L0-5 审计规约）。
- 双留痕：ai_agent_tasks = 执行台账（谁触发/几档/重试/成败），audit_logs = 合规台账；操作人走 systemOperatorId=0。

## 7. ADR（决策记录）
