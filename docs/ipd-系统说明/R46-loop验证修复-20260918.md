## 三、4 项未修真异常的修复路径(owner 审批)

### A1 P0 — 工作台删除审批 `not_a_real_table` 污染

**现象**:`/ipd/workbench` 删除审批列表 25 项中至少 22 项标题为 `删除终审:not_a_real_table #999999999`,数据时间在 2026-09-07 22:13 ~ 19:07 区间集中爆发。

**根因诊断**:后端 `deletion-requests` 表存在非法 target_table='not_a_real_table' + target_id=999999999 的测试种子数据。

**修复路径**(二选一):

**路径 1 — 数据清理**(快速闭环,owner 拍板即可执行):
```sql
-- 删除测试种子污染(target_table='not_a_real_table' 全部)
DELETE FROM deletion_requests WHERE target_table = 'not_a_real_table';

-- 删除 unsupported_probe 测试探针
DELETE FROM deletion_requests WHERE target_table = 'unsupported_probe';

-- 复核
SELECT target_table, COUNT(*) FROM deletion_requests GROUP BY target_table;
```

**路径 2 — 前端过滤**(不改数据,前端兜底):
- 工作台删除审批组件加 `target_table` 白名单过滤(已知表名枚举)
- 删除项必须能在数据库 `information_schema.tables` 查到对应表

**owner 决策点**:选路径 1 还是 2?建议路径 1(根因清理)。

### A3 P1 — 项目移交 Mock 接任人污染

**现象**:`/ipd/handover` 接任人下拉最后一项是 `Mock-QA-SYNC-20260910B`(6 个真实候选人 + 1 Mock)。批量移交原负责人下拉也含 Mock。

**根因诊断**:后端 `persons` 端点(GET `/api/v1/persons` 或 `/api/v1/handover/candidates`)未过滤 Mock 标识(`is_mock=1` 或 `username='Mock-QA-SYNC-20260910B'`)。

**修复路径**(前端 + 后端双管齐下):

**后端过滤**:`PersonsController#listActive` 加 Mock 过滤条件:
```java
.eq(Persons::getIsMock, 0)  // 排除 Mock
.eq(Persons::getStatus, "ACTIVE")  // 仅在职
```

**前端兜底**:接任人下拉加 Mock 标识(后续统一处理)。

**owner 决策点**:先修后端(根因),前端兜底可在前端仓统一治理。

### A4 P2 — 超级管理 `allowance.L3` 配置漂移

**现象**:`/ipd/admin/config` 参数表 `allowance.L3` 当前值 1500,默认值 2000。L1/L2/L4/L5 当前值都等于默认值,只有 L3 漂移。

**根因诊断**:运营手动修改后未恢复(或测试时调整未回滚);后端无审计钩子,无法追溯何时何人改的。

**修复路径**(超管可自助修复):

**路径 1 — 直接调整配置**:超管登录 `/ipd/admin/config`,编辑 `allowance.L3` 从 1500 改回 2000。
**路径 2 — 加审计钩子**:后端加 `parameter_change_log` 表,所有 PUT 参数写日志,前端显示差异警告。

**owner 决策点**:先做路径 1(快),再做路径 2(治本)。
