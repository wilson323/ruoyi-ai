### 4.3 签名算法（HR 文档 §1.2.3，已实现于 HrSignatureUtil）

```
src = JSON.stringify(data) + "&secretKey=<secretKey>"  // key 字典序拼接非必要，data 整体 JSON 后追加
src 排序: key 字典序(参数级) → 再 append secretKey
sign = MD5(src).toUpperCase(16)  // BigInteger(1, bytes).toString(16).toUpperCase()
```

测试用例：HR §1.3.6 示例 → sign = `74B5DB3238B324C1A9EA99D94EE22934` ✅
另有 md5("a") = `CC175B9C0F1B6A831C399E269772661` ✅

### 4.4 token 自动续签

| 触发 | 动作 | 日志 |
|------|------|------|
| 缓存命中 + 未过期 | 直接返缓存 | — |
| 缓存缺失或 TTL 已过 | `synchronized` 调 `zkteco.token.get` | `ipd_hr_token_refreshed expiresIn={n}s` |
| HR 业务返 code=1006（token 过期）| `tokenClient.refresh()` + 重试 1 次 | `ipd_hr_token_invalid method=… code=1006 retrying` |
| HR 业务返 code=1007（token 不匹配）| 同上 | `… code=1007 retrying` |
| 5xx / 1002（签名错）/ 1003（时间戳过期）| **不重试**，抛 HrApiException | — |
