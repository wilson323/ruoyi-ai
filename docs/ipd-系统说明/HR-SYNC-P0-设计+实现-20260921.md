**防双轨核心约束**：
1. `hr/` 子包**只做**真源 HTTP 客户端层，不做人员落库/事件联动
2. 既有 `HrSyncService` 继续承担"HR 事件联动适配器"，**不重写不迁移**
3. 后续 `RealHrSyncAdapter implements PersonSyncService.SyncProcessor`（FA-HR-Sync-v1-D1）只补"如何把 PersonRow 落 persons"那一段，**不复刻业务规则**
4. persons 表不 ALTER；HR 扩展字段（phone/email/hire_date 等）暂不存——按用户决策"person_type 不动 + HR 标识"

### 2.3 字段映射（HR BASIC_INFO → persons，**最小变更**）

| HR 字段 | persons 列 | 写入策略 | 备注 |
|---------|-----------|----------|------|
| PERNR | `employee_no` (UNIQUE) | upsert | 业务键 |
| BASIC_INFO.NACHN | `name` | upsert | 姓名 |
| BASIC_INFO.STAT2 / LEAVE_DATE / LEAVE_FLAG=X / DEL_FLAG=X | `employment_status`+`account_status` | 联动 | 3→ACTIVE；任一命中→employment=RESIGNED + account=DISABLED |

## §4 配置契约（ipd.hr.*）

```yaml
ipd:
  hr:
    enabled: ${IPD_HR_ENABLED:false}                # 默认关闭（prod 必须显式开 + 真实凭据）
    app-id: ${IPD_HR_APP_ID:}
    secret-key: ${IPD_HR_SECRET_KEY:}
    base-url: ${IPD_HR_BASE_URL:}
    http:
      connect-timeout-ms: ${IPD_HR_CONNECT_TIMEOUT_MS:5000}
      read-timeout-ms: ${IPD_HR_READ_TIMEOUT_MS:30000}
      retry-count: ${IPD_HR_RETRY_COUNT:2}
```

**真凭据放置**（owner 操作）：
```yaml
# .codex/ipd-dev/config/application-ipd-local.yml （gitignored）
ipd:
  hr:
    enabled: true
    app-id: "<真实 appId>"
    secret-key: "<真实 secretKey>"
    base-url: "https://ehr.zkteco.com/api"
```

**签名算法**（HR §1.2.3，HrSignatureUtil）：
```
src = "<ASCII 字典序 k=v&>" + "secretKey=<k>"   // 跳过 sign/serialVersionUID
sign = MD5(src).toUpperCase(32 位 hex)           // JDK MessageDigest + %02X 保留前导 0
```

**token 自动续签**：
| 触发 | 动作 |
|------|------|
| 缓存命中 + 未过期 | 直接返缓存 |
| 缓存缺失/TTL 已过 | `synchronized` 调 `zkteco.token.get`，缓存 expiresIn-300s |
| HR code=1006/1007（token 过期/不匹配） | `tokenClient.refresh()` + 重试 1 次 |
| 1002（签名错）/ 1003（时间戳过期）/ HTTP 5xx | **不重试**，抛 HrApiException |
