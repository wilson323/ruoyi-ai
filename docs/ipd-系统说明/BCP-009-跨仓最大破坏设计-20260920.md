## §2 4 类跨仓最大破坏场景设计

### 2.1 场景 1（S1）：跨仓 commit 误提交

**描述**：agent 不带 `cd /绝对路径` 前缀直接 `git commit` → 提交到错误仓（如在 ruoyi-ai 工作目录误执行 `cd ../ruoyi-ipd-web && git commit`，commit 提交到 ruoyi-ipd-web 而非 ruoyi-ai）。

**根因**：
- cwd 漂移：shell session 上下文未保护（终端复用、sub-shell 嵌套、脚本子进程）
- 跨仓 cd 相对路径未拦截（`cd ../zk-ipd` 而非 `cd /Users/mac/Documents/ZK-IPD` 绝对路径）

**影响**：
- 双仓并行 commit 撞车风险极高（OPS-09 单写者纪律不允许）
- commit 历史混淆（ruoyi-ai 的变更误归到 ruoyi-ipd-web）
- 跨仓 BCP 自动同步失败（SSOT 三源对账失效）

**修复方案**：
- scripts/check-cross-repo-cd-guard.sh（R132 cb5ba74c 落档 43 行，CRC_FAIL_SEED=1 自证能红 exit 2）
- 所有 Bash 命令前缀严守 `cd /Users/mac/Documents/ruoyi-ai &&`
- pre-commit hook H6（cross-repo-cd-guard）拦截跨仓相对路径 cd

**撞车 0 让路位（R138 pm 严守边界）**：
- ✅ 仅 docs 落档设计文档（本设计文档 §2.1 段）
- ❌ **不实装跨仓 commit**（不在 ruoyi-ai 仓实跑任何 `git commit` 命令到错误仓）
- ❌ 不跨仓（不动 ruoyi-ipd-web / ZK-IPD 任一文件）

### 2.2 场景 2（S2）：跨仓 DDL apply

**描述**：agent 在 ruoyi-ai 仓跑 DDL apply（Flyway / Liquibase / 手动 SQL），结果 DDL 应用到错库（如 IPD 后端配置多源指向 `ipd_dev` 库，但 DDL apply 到 `ipd_prod` 库 = 数据治理灾难）。

**根因**：
- database client 误连（连接串配置错误或环境变量错配）
- 后端 additional-location 配置漂移（`application-ipd-local.yml` 内容被错误修改）
- DDL apply 命令未指定目标库（直接 `psql -f schema.sql` 未指定 `-d ipd_dev`）

**影响**：
- 数据治理 C 类最大破坏（14d SLA = R132 §三 拍板机制 C 类）
- 字符集整改 / 表名单数 / kpi_rules 表等 DDL 应用到错误库 = 不可逆数据丢失
- owner 必拍位 #4（571 字符集整改）+ #15（DDL SRE apply 元规则）解锁后才能执行

**修复方案**：
- pre-commit hook H7（ssot-drift-guard）拦截 SSOT 三源对账漂移
- DDL SRE apply 元规则（paiban-15 = owner 必拍位 #15）约束 DDL apply 必带 `--target-db=ipd_dev` 显式参数
- docs-only 落档 paiban-02/03/04/15（12 项 C 类决策包已 R137 E docs-only 准备完毕）

**撞车 0 让路位（R138 pm 严守边界）**：
- ✅ 仅 docs 落档设计文档（本设计文档 §2.2 段）
- ❌ **不实装跨仓 DDL apply**（不在 ruoyi-ai 仓实跑任何 Flyway / Liquibase / psql 命令）
- ❌ 不修改 application-ipd-local.yml 内容（仅 docs 引用路径）
- ❌ 不触发 D+14 重审（D+14 = 2026-10-04，未到重审触发日）

### 2.3 场景 3（S3）：跨仓端口抢占

**描述**：agent 在 ruoyi-ai 仓启动服务占用端口 16039（IPD 后端默认端口），结果导致前端仓（ruoyi-ipd-web / ZK-IPD）服务因端口冲突无法启动。

**根因**：
- 端口资源无边界（16039 / 23306 / 8080 / 15666 多仓共享）
- 兄弟会话占用检查缺失（未实跑 `ps aux | grep port-16039` 撞车 0 让路预检）
- 端口分配表 SSOT 缺失（无 docs/port-allocation.md 登记各仓端口分配）

**影响**：
- 跨仓服务启动撞车（前端仓 + 后端仓并行启服务失败）
- 飞轮转速监控盲区（wheel-stuck-detector.sh 仅扫 markdown 表格，不扫端口）
- owner 必拍位 #6（DTO 后缀收口 + 跨仓 commit 授权）解锁后才能跨仓并行

**修复方案**：
- 端口分配表 SSOT（docs/port-allocation.md 待 R138+ 落档）
- pre-commit hook H5（pre-commit smoke test）启 Java + Vitest + 编码前端口预检
- scripts/check-cross-repo-cd-guard.sh 扩展端口预检（`lsof -i :16039` 撞车 0 让路）

**撞车 0 让路位（R138 pm 严守边界）**：
- ✅ 仅 docs 落档设计文档（本设计文档 §2.3 段）
- ❌ **不抢端口**（端口 16039 / 23306 / 8080 / 15666 兄弟会话占用 100% 保持，本 R138 任务全程未启任何服务）
- ❌ 不实装端口分配表 SSOT 脚本（仅 docs 设计层落档）

### 2.4 场景 4（S4）：跨仓 PID 互杀

**描述**：agent 在 ruoyi-ai 仓杀进程（如 `kill -9 PID` 或 `pkill -f java`），结果误杀前端仓（ruoyi-ipd-web / ZK-IPD）的 PID（进程名冲突，如多个仓都有 java / node 进程）。

**根因**：
- 进程名冲突（`java -jar ruoyi-ai.jar` 与 `java -jar ruoyi-ipd-web.jar` 进程名都含 java）
- 杀进程命令未限定进程启动目录（`pkill -f java` 不区分仓）
- PID 归属识别缺失（无 `ps -o pid,command | grep "/Users/mac/Documents/ruoyi-ai"` 过滤）

**影响**：
- 跨仓服务突然中断（前端仓 / 后端仓任意一方被杀）
- 兄弟会话占用崩溃（PID 34560 / 70554 / 29607 / 65576 任一被误杀）
- 飞轮转速监控盲区（wheel-stuck-detector.sh 仅扫 markdown 表格，不扫 PID）

**修复方案**：
- scripts/wheel-stuck-detector.sh（R132 cb5ba74c 落档 80 行）扩展 PID 归属预检
- pre-commit hook H5（pre-commit smoke test）杀进程前 `cwd` 校验
- docs-only 落档 PID 归属登记表（docs/pid-allocation.md 待 R138+ 落档）

**撞车 0 让路位（R138 pm 严守边界）**：
- ✅ 仅 docs 落档设计文档（本设计文档 §2.4 段）
- ❌ **不杀 PID**（PID 34560 / 70554 / 29607 / 65576 兄弟会话占用 100% 保持，本 R138 任务全程未触碰任何 PID）
- ❌ 不实装 PID 归属预检脚本（仅 docs 设计层落档）
