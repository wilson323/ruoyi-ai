## 一、怎么量的（可复现，且写了踩过的坑）

**前置**：根 `pom.xml` 的 `<compilerArgs>` 已于同日补上 `-Xlint:deprecation`。

### 1.1 四个陷阱——不写下来，复现者会得到一份假的「干净」

本次实测踩过全部四个，每一个都会让结果**看起来是 0**：

1. **Maven 增量编译**：`target/classes` 新鲜时源码根本不会重编，javac 不执行 → 0 告警。
   必须先把源码时间戳推新（或 `clean`），否则量到的是「没编译」而不是「没违规」。
2. **不能加 `-o`（离线）**：`maven-clean-plugin:3.2.0` 的依赖
   `org.apache.maven.shared:maven-shared-utils:jar:3.3.4` 不在本地缓存，
   离线模式下 `clean` 会在第一步直接失败（37 个模块全部 SKIPPED）。
3. **本机 javac 是中文 locale**：输出 **「已过时, 且标记为待删除」**，
   **不是** 英文的 `[deprecation]`。按英文标签计数会得到 0。
   `forRemoval=true` 的会多出「且标记为待删除」这一句，可据此区分两类。
4. **单文件模块输出 `Compiling 1 source file`（单数）**：
   按 `source files`（复数）统计模块数会漏掉只有 1 个源文件的模块
   （本次即 `ruoyi-common-job`，漏掉后模块数 32 被少报成 31）。

### 1.2 复现命令

```bash
cd /Users/mac/Documents/ruoyi-ai

# ① 推新主源码时间戳（只改 mtime，不动内容；排除归档目录）
for d in ruoyi-common ruoyi-modules ruoyi-admin ruoyi-extend; do
  find "$d" -path '*/src/main/java/*' -name '*.java' -exec touch {} +
done

# ② 全仓重编（必须经构建互斥锁；不要加 -o）
bash scripts/mvn-locked.sh compile -DskipTests -o > /tmp/dep-scan.log 2>&1

# ③ 提取（注意中文文案）
grep '已过时' /tmp/dep-scan.log
```
