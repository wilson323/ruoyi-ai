## 2. 根因判断

### 假设 ①：脚本设计错（要求所有 BCP 都有对应 wt，但很多 BCP 就是 docs-only 闭环）
- **证据强**：BCP-014 在 Registry 写 ✅ CLOSED，在 Closure Log 写 docs-only 闭环，根本不需要 worktree
- **结论**：✅ 成立

### 假设 ②：BCP-Registry 与实际执行确实脱钩
- **证据弱**：14 个 BCP 全部 docs-only 闭环，不存在"脱钩"
- **结论**：❌ 不成立（脱钩的判定标准本身错）

### 假设 ③：wt 命名约定与 BCP 编号本就两套维度，门禁不该强配对
- **证据强**：worktree = 治理轮 P/R 命名空间，BCP = 独立编号空间，两者不同维度
- **结论**：✅ 成立（核心根因）

## 3. 根因结论

**脚本设计缺陷**：把"BCP 编号"与"worktree 命名"两个独立命名空间强行配对。

实际语义应该是：
- **worktree 是给 Java/SQL/yml 代码改动隔离用**（治理轮 P/R 任务派单）
- **BCP 是飞轮反脆弱闭环单元**（docs-only 设计 + 门禁脚本实装）
- 两者**不需要一一对应**：很多 BCP 是纯 docs-only 闭环（如 BCP-014），不需要 worktree
