## 四、R131 派单飞轮设计清单（10 条）

### 4.1 飞轮核心定义

```
飞轮 = 一个持续转动的 BCP 加工流水线
  轴 = 业务变更包（BCP）
  齿 = 5 步（盘点/派单/落地/验证/同步）
  转速 = 每 BCP 独立生命周期（不依赖 R 轮次）
  监控 = wheel-stuck-detector.sh（48h 升级）
  约束 = 5 钻撞根因（每 BCP 必 grep 5 反复根因证据）
```

### 4.2 飞轮 5 齿定义

| 齿 | 智能体 | 脚本 | 入口 | 出口 |
|---|---|---|---|---|
| ①盘点 | `ioedream-pm` | `wheel-bcp-discover.sh` | 新需求/拍板/SSOT 漂移信号 | BCP-DRAFT |
| ②派单 | `pm + agency` | `wheel-bcp-assign.sh` | BCP-DRAFT + 撞车 0 校验 | BCP-PENDING_OWNER |
| ③落地 | 领域专家（283） | wt 内执行 | owner 拍板 + worktree 创建 | BCP-IN_BUILD |
| ④验证 | `qa-gatekeeper` | `wheel-bcp-verify.sh`（5 钻撞根因）| 落地完成 + 自证能红 | BCP-IN_VERIFY |
| ⑤同步 | `evolver` | `wheel-bcp-sync.sh`（看板 PUT + log.md append）| 验证 PASS + SSOT 三源对账 | BCP-SYNCED → CLOSED |

### 4.3 飞轮转速监控（`wheel-stuck-detector.sh`）

- **监控点**：每个 BCP 在每齿停留时间
- **升级触发**：任一 BCP 在任一齿停留 > 48h
- **升级动作**：看板卡标 🔴 / 自动派单 worktree / 飞书 webhook 通知 owner + PM
- **根除**：M-Root-2（拍板单向无升级）+ M-Root-6（治理轮不收敛）

### 4.4 飞轮关键约束 — 5 钻撞根因

每个 BCP 必须满足「5 钻撞根因」——wt 内必须能 grep 到 5 个反复根因的修复证据：

| 根因 | BCP 必含字段 |
|---|---|
| R-1 shell pipe trap | `verification_command: bash X.sh >/dev/null 2>&1; echo $?`（非 pipe）|
| R-2 additional-location | `backend_args: --spring.config.additional-location=...` |
| R-3 Sandbox 回收 | `background_mode: is_background=true` |
| R-4 撞号撞车 | `commit_strategy: 整点错峰 + git fetch + log -5` |

### 5.1 拍板机制总览

**问题诊断**：R128 把 18 项拍板写成「等 owner 拍」清单，R130 派单序列中 11/13 wt 依赖 owner 拍板 → **派单变成拍板的奴隶**。

1. **不破坏性原则**：让路边界内不动（Java 源码 / SQL apply / 端口 / PID / 兄弟会话）

4. **自动升级原则**：7 天未决 → T2 升级 → PM-OWNED 接管 / 低风险自动通过 / 高风险重申请
