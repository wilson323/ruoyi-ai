# BCP-015 — 门禁分级与误报抑制机制（docs-only 设计，等 owner 拍板实装）

## §一 背景（来自 R168 深扫）

R168 系统性反思深扫识别出 R142 9 大门禁中 **4 个 FAIL 实为误报**：

| 门禁 | 误报语义 |
|---|---|
| check-reflection-convergence.sh | 命名空间生命跨度 ≠ 根因复发 |
| check-bcp-unit-mismatch.sh | BCP 编号与 wt 命名独立维度 |
| check-gep-running.sh | failures.jsonl 空 = 健康 |
| check-three-source-hash.sh | 三源详略不同 ≠ 不一致 |

**共同根源**：门禁实装但缺 2 个机制：
1. **FAIL 信号分级**（CRITICAL / WARNING / INFO）
2. **KNOWN_FALSE_POSITIVE 抑制清单** + SUPPRESS_UNTIL 时间戳

## §二 设计目标

把 9 大门禁从「一视同仁 FAIL」升级为「分级 FAIL + 抑制项」：
- 🔴 CRITICAL = 真阻塞（必须修才能 commit）
- 🟡 WARNING = 值得注意（commit 通过但需登记）
- ⚪ INFO = 设计预期（commit 通过，登记备查）

## §三 FAIL 分级协议（设计）

### 3.1 三级定义

| 级别 | 含义 | CI 行为 | 登记要求 |
|---|---|---|---|
| 🔴 CRITICAL | 真阻塞（数据丢失 / 安全风险 / commit 引用 untracked / SQL 未 apply）| exit ≠ 0 阻断 | 必须修 |
| 🟡 WARNING | 值得注意（详略不同 / 反思持续 / 命名空间跨度大）| exit 0 通过 | commit message 透明披露 |
| ⚪ INFO | 设计预期（无失败 = 健康 / 三独立维度详略不同）| exit 0 通过 | 不要求登记 |

### 3.2 改造点

每个门禁脚本需在输出前缀加级别标签：

```
🔴 CRITICAL: <message>
🟡 WARNING: <message>
⚪ INFO: <message>
```

CI/pre-commit hook 读取级别：
- 见 🔴 → exit ≠ 0
- 见 🟡 / ⚪ → exit 0，但 WARNING 输出到 commit message

### 3.3 本轮 4 个 FAIL 重分级（设计目标）

| 门禁 | 原行为 | 改后行为 |
|---|---|---|
| check-reflection-convergence.sh | FAIL 11/11 | ⚪ INFO（命名空间生命跨度 = 健康）|
| check-bcp-unit-mismatch.sh | FAIL 14/14 | ⚪ INFO（两套独立维度 = 设计）|
| check-gep-running.sh | FAIL 0 数据行 | ⚪ INFO（无失败 = 健康）|
| check-three-source-hash.sh | FAIL hash 不一致 | 🟡 WARNING（详略不同 = 健康但记录）|

## §四 KNOWN_FALSE_POSITIVE 抑制清单（设计）

### 4.1 文件位置

新增 `scripts/KNOWN_FALSE_POSITIVE.txt`，每行格式：
```
<gate_name>|<pattern>|<reason>|<added_by>|<added_date>|<suppress_until>
```

### 4.2 示例（设计）

```
check-reflection-convergence.sh|M-Root-.*|命名空间生命跨度=健康，由 R168 §七登记|R168-main|2026-09-21|2099-12-31
check-bcp-unit-mismatch.sh|BCP-.*|BCP 编号 vs wt 命名独立维度，由 R168 §七登记|R168-main|2026-09-21|2099-12-31
check-gep-running.sh|failures-jsonl-data-rows-zero|空=健康，由 R168 §七登记|R168-main|2026-09-21|2099-12-31
check-three-source-hash.sh|.*|三源详略不同=健康，由 R168 §七登记|R168-main|2026-09-21|2099-12-31
```

### 4.3 读取机制

门禁脚本末尾统一逻辑：
```bash
if [ -f "$WORKSPACE/scripts/KNOWN_FALSE_POSITIVE.txt" ]; then
  if grep -qE "^${GATE_NAME}|${FAIL_PATTERN}|" "$WORKSPACE/scripts/KNOWN_FALSE_POSITIVE.txt"; then
    echo "⚪ INFO: $FAIL_PATTERN 已登记为已知误报（抑制项）"
    exit 0
  fi
fi
```

### 4.4 抑制项生命周期

- `suppress_until` 过期 → 自动失效（CI 重新报警）
- 季度治理轮复审抑制项（删过期 / 续期 / 转正为正式规则）

## §五 自证能红（设计）

```bash
# 1. 故意登记错抑制项 → 脚本应拒绝并报错
echo "check-fake-gate|fake-pattern|noreason|noone|2020-01-01|2020-12-31" >> scripts/KNOWN_FALSE_POSITIVE.txt
bash scripts/check-known-fp.sh
# 期望：exit 1 + 输出"抑制项格式错"

# 2. 故意登记过期抑制项 → 应自动失效
echo "check-fake-gate|fake-pattern|reason|by|date|2020-01-01" >> scripts/KNOWN_FALSE_POSITIVE.txt
bash scripts/check-fake-gate.sh
# 期望：exit 1（不被抑制）

# 3. 故意让门禁触发 FAIL → 应输出级别前缀
REFLECT_CONVERGE_FAIL_SEED=1 bash scripts/check-reflection-convergence.sh
# 期望：exit 1 + 输出"🔴 CRITICAL:"（FAIL_SEED 不在抑制清单）
```
