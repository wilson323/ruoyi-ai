## §三 深度反思：4 个 FAIL 的共同根源

### 根因 1：把"设计预期状态"误判为"异常状态"
- 治理轮元根因持续出现 = 反思持续在做 = **设计预期**
- GEP failures.jsonl 空 = 当前无失败 = **设计预期**
- 三源描述详略不同 = 三源独立维度 = **设计预期**
- BCP 与 wt 不同命名空间 = 两套维度 = **设计预期**

### 根因 2：把"独立维度"强行拉平
- 反思源（log.md）/ 登记源（BCP-Registry）/ 闭环源（BCP-Closure-Log）= 三独立维度
- worktree 命名（P/R 治理轮）vs BCP 命名（独立编号）= 两独立维度
- **强行要求维度对齐 = 信息丢失**

### 根因 3：FAIL 信号没分级（CRITICAL vs WARNING vs INFO）
- 当前所有 FAIL 一视同仁 = 都是 CRITICAL
- 实际应当分级：
  - 🔴 CRITICAL：真阻塞（哈希碰撞 / SQL 未 apply / commit 引用 untracked）
  - 🟡 WARNING：值得注意（详略不同 / 反思持续）
  - ⚪ INFO：设计预期（无失败 = 健康）

### 根因 4：门禁实装但缺"白名单 + 抑制项"
- 9 门禁全实装但每个都有 FAIL_SEED 自证能红
- **没有反向机制**：当 FAIL 是误报时如何标记抑制？
- 缺 `KNOWN_FALSE_POSITIVE` 抑制清单 / 缺 `SUPPRESS_UNTIL` 时间戳
