# 第一部分：AI 能力用户故事全集

## 0. 角色与 AI 能力总览

系统共 4 类登录身份 + 1 类外部参与者，AI 能力对所有角色按「建议+人审」双层防线开放（AI 不写业务表、不代签名，BR-AI-05）：

| 角色 | 日常场景 | 可用 AI 能力 |
|---|---|---|
| 市场PM | 需求、Charter/PRD、GTM、Gate 主答、生命周期 | 副驾问答、文档生成、AI 帮写/总结/建议、健康度 Agent |
| 研发PM | 技术方案、排期、测试证据、Alpha、BioCV | 同上（按项目可见范围） |
| 产品组长（市场/研发） | 复核、定标、KPI 评定、删除初审、共担归集 | 评审材料汇总、KPI 解读、贡献度分析、异常检测 |
| 超级管理员 | 配置、终裁、人员/参数/模板治理 | 审计异常检测、配置影响分析、绩效 Agent |
| 游客/需求提交人 | 提交需求、查进度 | **不使用内部 AI 副驾**；仅间接触发需求分类 AI |

AI 能力分四层递进（与 20260923 完整方案对齐）：
- **L0 基础**：模型配置真活、RAG、SSE 真流式、副驾接 RAG
- **L1 模板**：8+1 类 docType 结构化文档生成
- **L2 每页入口**：19 个页面的「AI 帮写/总结/建议/问答」
- **L3 Agent**：3 个多步推理 Agent（纯读/建议性，写操作必须人审）

每个故事带：编号、角色、场景、验收标准（AC）、证据要求。AC 全部可测；标 ⚠ 的 AC 依赖 owner 拍板或 Layer 前置完成。

## 1. L0 · 基础能力（US-L0-01 ~ 05）

### US-L0-01 AI 模型配置真活启用
**作为** 超级管理员，**我要** 在「AI 模型配置」页（P48）配置 provider/endpoint/apiKey 并启用一个生效模型，**以便** 全系统 AI 功能有可用底座。
- AC1：保存后 `ai_model_configs` 表 `is_active=1` 全局唯一（新启用自动取消旧行）。
- AC2：apiKey 加密存储，任何查询接口/日志/审计不回显明文。
- AC3：endpoint 通过 SSRF 黑名单校验（localhost / 169.254.* / 内网段拒绝），`ssrfBlockReason` 返回明确原因。
- AC4：`budgetTokens` 月度预算生效，超限后 AI 调用返回降级错误码而非静默失败。
- 证据：HTTP 真活响应 + `ai_model_configs` DB 回读 + 负向 SSRF 拒绝案例。

### US-L0-02 文档审核通过自动向量化（RAG 真活）
**作为** 市场PM，**我要** AI 文档审核归档后其内容自动进入向量库，**以便** 后续生成/问答能引用本项目历史知识。
- AC1：`POST /ai-documents/{id}/review` 通过后异步写入 `ai_doc_embeddings` ≥1 行，`project_id`/`docType` 正确。
- AC2：向量化失败不阻塞审核流转，失败可重试且落审计。
- AC3：检索只在同项目内进行，跨项目检索返回空（越权防线）。
- 证据：真库 `SELECT COUNT(*) FROM ai_doc_embeddings WHERE project_id IS NOT NULL` > 0。

### US-L0-03 AI 副驾流式输出（SSE 真流式）
**作为** 任意登录用户，**我要** 在工作台副驾收到逐 token 流式回答并可随时点「停止」截断，**以便** 长回答不用干等。
- AC1：`GET /ai-copilot/chat/stream` 经 IpdSseController/AiChatStreamController 真流式推送 ≥3 段 `data:` 事件（非同步结果切片）。
- AC2：客户端断开后服务端立即停止生成，不计超额 token。
- AC3：流式会话完成时整 session 落一行 `audit_logs`（AI_STREAM_CHUNK 按完成落审计，非每段落审计）。
- 证据：Playwright 端到端事件时序 + 审计回读。

### US-L0-04 副驾问答带 RAG 上下文
**作为** 市场PM，**我要** 副驾回答时自动注入本项目已归档文档片段（top-3），**以便** 回答贴合项目事实。
- AC1：`retrieveContext` 按 docType 分路检索，prompt 含 ragCtx 块。
- AC2：无相关片段时优雅降级为无 RAG 回答，不编造引用。
- AC3：TASKS/ADVANCE 意图命中时仍走确定性路径不调 AI（现状保持）。
- 证据：单测断言 ragCtx 行数 = 入参 docType 对应真库行数（mock 须遵守 mock 合法性规约）。

### US-L0-05 AI 审计三件套合规
**作为** 超级管理员/审计者，**我要** 每一次 AI 调用都带 `aiAssisted=true + aiModel + aiRole` 落 `audit_logs`，**以便** 满足欧盟 AI 法案式留痕要求。
- AC1：五类 action（AI_COPILOT_CHAT / AI_GENERATE / AI_REVIEW / AI_SUGGEST / AI_AGENT_*）全部带三件套。
- AC2：审计**绝不含** prompt 原文、模型响应原文、API key（只有短指纹 PromptLenBucket）。
- AC3：`aiModel` 值必须在已批准模型名白名单内。
- 证据：真库抽样审计行字段断言 + grep 负向验证（审计表中不含敏感字段的全文扫描）。

- **出**：所有 AC 有证据 + 无未处理 S0/S1 + 文档/看板同步 → 判 PASS。
- **入（阻塞上线）**：任一 Ph5 链路节点无真实回读证据 → 判 PARTIAL，不得翻 done。
