# IPD AI 工作界面（六阶段小阶段化 + pm-skills 引导 + CopilotKit 画布）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 IPD 六大阶段（真实 69 个标准动作）细化为 22 个可依次执行的小阶段，每个动作绑定 pm-skills 的具体技能/命令，由 CopilotKit AI 副驾引导用户在画布上完成工作并结构化写入现有表；同时保留传统 UI 与 AI UI 双模式切换。

**Architecture:** 后端（ruoyi-ai / Java）新增小阶段与技能映射两张元数据表 + 扩展 `StageActionService` 查询面 + 复用已落地的 AG-UI Java 桥（`org.ruoyi.ipd.copilotkit`）下发新的卡片工具调用；前端（ruoyi-ipd-web / Vue 3 + Ant Design Vue）在**已挂好的** `CopilotKitProvider`（P3-01 单轨融合）之上，按 CopilotKit Vue 官方 API 面纠正标注、注册新卡片类型，画布与文档能力**全部复用仓库已装的成熟库**（Vue Flow / TinyMCE / ECharts / iframe srcdoc / CopilotKit A2UI + Open Generative UI），零新增运行时依赖。

**Tech Stack:** Spring Boot 3.5.8 + Java 17 + MyBatis-Plus（后端）；Vue 3.5 + Vben 5.5.9 + Ant Design Vue + `@copilotkit/vue@^1.74.0`（`/v2` 子路径）+ `@vue-flow/core@^1.46.5` + `tinymce@7.9.1` + `echarts@^5.5.1` + `zod`（前端）；AG-UI 事件协议（`RUN_*` / `TEXT_MESSAGE_*` / `TOOL_CALL_*` / `STATE_DELTA`）；pm-skills marketplace（9 插件 / 69 Skills / 42 命令）。

**Spec:** 本文档 §0（事实基线，全部带取证命令与时间戳）+ §2（22 小阶段拆解）+ §3（69 动作 × pm-skills 映射）+ §4（CopilotKit Vue API 纠正）+ §5（成熟方案选型）+ §6（数据模型）即为 spec。执行者须同时读：
- `ruoyi-ipd-web/docs/copilotkit单轨融合契约-20260928.md`（300 行，5 条单轨红线 + 四帧→AG-UI 映射对账表，**硬约束**）
- `ruoyi-ai/docs/ipd-系统说明/外部资源/IPD系统_六阶段标准动作清单_v3.md`（307 行，业务权威）
- `ruoyi-ipd-web/AGENTS.md` + `ruoyi-ai/AGENTS.md`（雷区：假红/假绿陷阱、单一写入者、vite 直起）

## Global Constraints

以下每条对**所有 Task** 生效，任何 Task 的要求都隐含包含本节：

1. **单轨红线 5 条**（源：`ruoyi-ipd-web/docs/copilotkit单轨融合契约-20260928.md` §1.1）：① 不开第二个聊天 UI（只在 `ai-assistant.vue` 内挂 Provider + renderless 渲染宿主）；② 不建平行卡片体系（渲染器 = `card-registry.ts` 组件原样复用，`(type, version)` 查表走 `getCardType`）；③ 不删文本降级路径（未命中注册表/信封非法一律纯文本降级）；④ 不加新写入端点（C08：卡片层零直写，`confirm` 只收组件 emit 转发）；⑤ 不复制校验逻辑防双轨（R2/R3 过检留在 `ai-assistant.vue` 四帧通道）。
2. **agentId 锁定 `ipd_copilot`**（源：同上 §3.1，`CopilotKitRuntimeController.AGENT_ID`）。
3. **零新增前端运行时依赖**：画布/文档/图表能力必须复用 `apps/web-antd/package.json` 已装依赖（实测清单见 §5）。确需新增（如 A2UI catalog 依赖）必须在 Task 内先出 ADR 并获批。
4. **CopilotKit 一律从 `/v2` 子路径导入**（`import { ... } from '@copilotkit/vue/v2'`；源：官方 `pages/vue.md` + 现有 `copilotkit-render.ts:31`）。
5. **`useRenderTool` 渲染器必须 guard-on-status**：`status !== 'complete'` 只出占位（`ipd-cpk-card-pending`），不得提前读 `parameters` 字段（流式期间是 `Partial<T>`）。
6. **两种渲染器 props 不通用**：`useRenderTool`/`useDefaultRenderTool` 收 `parameters` + 字符串 status（`'inProgress'|'executing'|'complete'`）；`useFrontendTool` 的 `render` 收 `args` + `ToolCallStatus` 枚举。共享组件必须包装，不得直接复用。
7. **数据库动作数以真实库 69 个 `action_code` 为准**（概念 C01-C12=12 / 计划 P01-P13=13 / 开发 D01-D11=11 / 验证 V01-V12=12 / 发布 L01-L08=8 / 生命周期 LC01-LC09=9 / KPI K01-K04=4）。原型 v2 顶栏的 `8/8、6/8、0/7、0/6、0/5、0/4`（`ipd-product-space-prototype-v2.html:494-509`）是**演示假数据，禁止进入实现**。库中另有 4 条脏数据 `A01/A02/A1/A2`（各仅 3 个项目），不属 69 动作，实现须排除。
8. **构建命令铁律**（源：两仓 AGENTS.md）：后端只在 `ruoyi-ai` 仓根执行 `mvn`，先 `export PATH="$HOME/tools/maven/bin:$PATH"` 与 `export JAVA_HOME="$HOME/tools/jdk-17/Contents/Home"`；复核用**错峰 + 单模块 + 不带 `-am` 不带 `clean`**：`mvn -o -pl ruoyi-modules/ruoyi-ipd -Dtest=Xxx test`。新测试类**必须加 `@Tag("dev")`**，否则 Surefire `<groups>` 静默跳过（假绿）。
9. **前端验证三件套**（仓根执行）：`pnpm run check:type` + `pnpm exec vitest run --config vitest.ipd.config.mts` + `pnpm run build:antd`；本地起服务必须 `node node_modules/vite/bin/vite.js` 直起（pnpm 包装的 vite 在 macOS 会锁死 event loop）；前端只监听 `127.0.0.1:15666`，后端只代理 `127.0.0.1:16039`。
10. **提交纪律**：用户未明确要求前不执行 git commit / push / 建业务分支。所有 Task 的 "Commit" 步骤在获批前一律替换为「暂存 + 输出 diff 摘要待批」。
11. **看板同步**：每完成一个 Task 必须更新 SSOT 镜像 `ruoyi-ai/docs/ipd-系统说明/开发计划-看板镜像.md` 与本地看板（`http://127.0.0.1:62250`）对应卡面状态；证据不足标 `PARTIAL`，不得提前标 done。SSOT 镜像与看板由主协调会话**串行写**（OPS-09 单一写入者），子智能体只提交证据。

13. **`demo.enabled` 默认 false**：若被改回 true，所有写操作被拦截返回"演示模式，不允许操作"。
14. **引用配置用键名不用行号**（yml 行号分钟级漂移）。
15. **渐进式引入**：长文件按需分段读，不整读；派单给子智能体只附必要片段或行号范围。
16. **21st 产物只作设计参照，禁止直入源码**：`21st get/generate/add` 的输出是 React + TS + Tailwind/shadcn（`installCommand` 实测为 `npx shadcn@latest add "https://21st.dev/r/<author>/<slug>?api_key=$API_KEY_21ST"`）。任何情况下不得把 React/shadcn 代码写入 `apps/web-antd/src/**`；参照产物只落 `ZK-IPD/开发说明/UI原型-*/`，再由人翻译为 Vue SFC + Ant Design Vue（呼应约束 3）。
17. **`.21st/design.json` 是设计上下文 SSOT，但 `--refresh` 会整体覆盖手动富化**：该文件由 `21st init --design-context --refresh` 生成，手动补写 `constraints/decisions/tokens` 后 `--check` 会报 "Design context drift detected"（实测）。规约：① 该文件纳入 git 跟踪（实测**未被 .gitignore 忽略**，可恢复）；② 任何人跑 `--refresh` 前必须先 `git stash`/commit 手动块，刷新后重新贴回；③ 项目级红线一律同时写进本文档 Global Constraints，不得只存在于 `.21st/`。

19. **MCP 凭据 write-only：后端已做对，前端必须跟上（Track E 交互红线）**：后端已以 `@JsonIgnore` + `@ExcelIgnoreUnannotated` + `applyWriteOnlyConfigPolicy` 三层保证不回显、不导出、留空即保留（§0.6）。因此任何 MCP / Skill 配置 UI 必须：①密钥类字段用 `type=password`；②**不得把"编辑时字段空白"当成 bug 去"修好"**（不得为了让表单预填而去掉 `@JsonIgnore`）；③编辑态必须用空态卡 + 「替换配置」+ "留空提交保留原值"文案把不回显讲清楚（§0.6 结论 2 方案 a）；④列表/详情/导出任何新增渲染不得尝试展示原值。
20. **不得在前端实现"绕过后端契约"的配置项**：连接表单字段集必须与后端**真实读取**的键一致（§0.6：LOCAL=`command`+`args`，REMOTE=`baseUrl`）。`env`/`headers` 字段在当前后端**不生效**，前端提前放出等于制造"填了没用"的假成功界面；须等后端 Task E-A1 落地后才可出现。
