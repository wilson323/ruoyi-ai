## 2. 修复内容（2 文件 + 2 测试）

1. **`ApiV1ErrorCode`** 新增 `METHOD_NOT_SUPPORTED(10002, "请求方式不支持")` → `getHttpStatus() = 405`（additive，既有码零改动；`fromCode` 自动覆盖）。
2. **`IpdNotFoundAdvice`** 新增 `@ExceptionHandler(HttpRequestMethodNotSupportedException.class)` 分支（D2 L207 指定修法）：
   - IPD 域（`/api/v1/` 前缀）→ `ResponseEntity.status(405).body(ApiV1Response.fail(METHOD_NOT_SUPPORTED))`；
   - 非 IPD 域 → `R.fail(HttpStatus.BAD_METHOD, "请求方式不支持")`（复刻基线，含 traceId 管理 ensureTrace/clearOwnedTrace 同款）。
3. **新增 `Contract01MethodNotAllowedEnvelopeTest`**（`@Tag("dev")` 2 例）：IPD 域 405 + 五字段包络形状；非 IPD 域基线 R 包络不误伤。
4. **`IpdNotFoundBaselineParityTest`** 补第 3 例：非 IPD 405 分支与基线 `handleHttpRequestMethodNotSupported` **实际输出**双侧对照（code/msg 逐字比对，防基线改文案时复刻点静默漂移）。

## 4. 语义决策

- **业务码 10002**：D2 判据只钉「HTTP 405 + code/message/data/timestamp/traceId」形状未指定 code 值；取 `METHOD_NOT_SUPPORTED(10002)` 归入 1xxxx 参数/请求段（与 10001 PARAM_INVALID 同段），additive 不动既有码。前端契约检查（check-ipd-contract）无 10002 冲突（实测无引用）。
- **非 IPD 域零变化**：`/chat` 等旧通道继续收基线 R 包络（HTTP 200 + code/msg），与 Qa07「不误伤」设计一致。
