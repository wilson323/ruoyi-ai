### 3.2 逐表内容一致性（CHECKSUM TABLE，InnoDB 精确校验）

172 表逐表 checksum 两边比对：**169/172 完全一致**，3 表 MISMATCH 全部归因为 **dump 时点后源库持续活跃写入**（非恢复缺陷）：

| 表 | 现象 | 归因证据 |

| `audit_logs` | src 7,179 行 vs restored 7,174 行（min 同、max 略小） | **前缀证明**：src 中 `id ≤ restored_max` 恰 **7,174 行** = 恢复库行数 ⇒ 恢复库是源库严格前缀，无丢失无篡改，+5 行为 dump 后新增审计行 ✅ |

## 4. 过程中识别并纠正的假绿（防伪记录）

首轮 CHECKSUM 比对脚本用 `GROUP_CONCAT` 拼 172 表清单，被默认 `group_concat_max_len=1024` **截断** → SQL 1064 语法错 → 两边输出均为空文件 → `diff` 空 vs 空输出"IDENTICAL"。**当场识破不可采信**（行数门 0≠172），改为 `SET SESSION group_concat_max_len=1024000` 重跑后得到真实结果（169 一致 + 3 归因）。证据文档保留此记录以证校验非恒绿。
