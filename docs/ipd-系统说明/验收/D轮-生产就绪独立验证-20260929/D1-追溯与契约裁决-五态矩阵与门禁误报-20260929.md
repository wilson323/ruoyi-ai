### 1.1 `/api/v1/auth/platform-token` 的裁决过程（示范"扫描器只作线索"）

这条最值得记录，因为它**先被判真孤儿、再被证伪**，且证伪过程暴露了 HTTP 探针的局限：

```
① 扫描器判定：前端 auth.ts:256 有真实调用 requestIpd('/auth/platform-token')，后端 ruoyi-modules 0 命中 → 真孤儿
② HTTP 探针：POST /api/v1/auth/platform-token → HTTP 401 {"code":20001,"message":"未认证或凭证失效",...}
   对照组 GET /api/v1/auth/me（已知存在）→ HTTP 401 {"code":20001,...} 完全相同
   ⇒ Sa-Token 拦截器在路由匹配**之前**就拦掉，401 无法区分"端点存在但未认证"与"端点不存在"
   ⇒ 前端 ipd-guard.ts 注释「后端端点实测存在（POST … → 401/20001）」的推断方式**不成立**，属假证据
③ 全仓 grep：IpdPlatformAuthController.java 命中 .harness/.backup/**（备份）与当前主树
   ruoyi-admin/src/main/java/org/ruoyi/ipd/controller/IpdPlatformAuthController.java  ← 存在
   ⇒ 裁决：**假孤儿**，根因是扫描范围漏 ruoyi-admin（缺陷 4①）
```

**结论**：HTTP 状态码不能作为路由存在性的判据；必须用源码映射 + 已认证探针双重确认。本轮因此**未把任何"401/404"升级为"权限拒绝成功"或"端点缺失"**。
