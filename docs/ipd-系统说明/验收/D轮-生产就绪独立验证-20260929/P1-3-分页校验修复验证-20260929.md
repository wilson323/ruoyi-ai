| 未提供/空白分页参数 | — | 不干预（缺省语义由各端点自定，与 `@RequestParam defaultValue` 对空串的绑定语义一致） |

## 2. B-2 分页入参校验契约（交付 D2 负例重测用）

| 项 | 值 |
|---|---|
| 参数名 | `pageNum` \| `pageNo`（当前页）、`pageSize`（每页条数） |
| 约束 | pageNum\|pageNo ≥ 1（且 ≤ Integer.MAX_VALUE）；pageSize **1~200**（@Min(1)/@Max(200)） |
| 超限/非法返回 | **HTTP 400 + `code=10001`（PARAM_INVALID）** + message（"分页参数非法：…"）+ data/timestamp/traceId 标准包络 |
| 域 | `/api/v1/**` 全域（含不消费分页参数的端点与公开端点——成本放大防护不设豁免） |
| 未提供参数 | 不干预；空白值视为未提供 |
| 非整数/Long 溢出 | 同判 10001，不落绑定层 500 |

## 3. 修复内容（2 文件 + 1 测试）

1. **新增 `org.ruoyi.ipd.security.IpdPageParamGuardInterceptor`**（HandlerInterceptor）：preHandle 统一校验三参数，违规抛 `IpdBusinessException(PARAM_INVALID)`，由既有 `IpdServiceExceptionAdvice` 映射 400/10001（复用现成链路，不另造响应分支）。
2. **`IpdWebSecurityConfig.addInterceptors`** 注册：`addPathPatterns("/api/v1/**")`、**不 exclude 任何路径**、`order(HIGHEST+2)`（登录/注解鉴权之后——未登录请求先撞 401，不向匿名方泄漏校验行为）。
3. **新增 `IpdPageParamGuardTest`**（`@Tag("dev")` 10 例）：D3 判据重放、pageNum/pageNo 双拼写、Long 溢出、pageSize 边界（200 放行/201 拒绝）、非整数不回显、放行面三例。

## 5. 语义决策与残留

- **双层防御不冲突**：拦截器层对非法值 400 拒绝（权威口径），AuditLogController 等既有 `Math.min(pageSize, 200)` 静默夹取保留作纵深防御（代码不回退）。
- **200 上限值**：取判据 @Max(200) 明示值，与既有 `PAGE_SIZE_MAX`/`Math.min(...,200)` 硬约束同值，无行为迁移。
- **残留**：① `stage_actions`/`audit_logs` 的 `pageSize=99999` 实际负载复现（D3 推论非实测）需隔离环境，本轮以参数闸阻断入口，不再触达 DB；② D2 负例重测（B-2 契约消费方）待 D 路下一轮验收执行。
