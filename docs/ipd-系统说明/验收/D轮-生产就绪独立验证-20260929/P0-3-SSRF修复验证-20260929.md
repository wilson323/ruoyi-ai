## 2. 修复内容（3 文件 + 1 测试）

1. **新增 `org.ruoyi.ipd.service.ai.EndpointUrlValidator`**——SSRF 黑名单**唯一实现**（D2 建议命名）：
   - `blockReason(endpointUrl, allowedHosts)`：B 路保存入口闸（URL 形态 + userinfo 拒绝 + allowlist 豁免 + 黑名单）；
   - `blockReasonForHost(host)`：host 黑名单（解析失败 **fail-open**——保存不依赖 DNS，出站 C 路 fail-closed 兜底）；
   - `isBlockedIp(byte[])`：字节级 fail-closed 判定，供 `AiChatClient` 出站前置复用；
   - 黑名单范围（两套旧实现取并集）：loopback 127/8+::1、链路本地 169.254/16（含云元数据 169.254.169.254）+fe80::/10 显式断言、RFC1918（10/8、172.16/12、192.168/16）+fec0::/10、CGN 100.64/10、0.0.0.0/8（含 0.0.0.1 等非零尾，JDK `isAnyLocalAddress` 不覆盖）、fc00::/7 ULA（JDK 谓词不覆盖）、组播、IPv4-mapped IPv6 解包。
2. **`AiModelConfigService`**：`validate()`（create/update 共用）尾部接 B 路闸（endpoint + embedEndpoint 同口径）；`ssrfBlockReason` 委托唯一实现（签名保留）；新增 `@Value("${ai.allowed-hosts:}")` 字段（R184-A/R212 豁免语义，AiGenerationService 同款字段注入）。
3. **`AiChatClient.isBlockedIp`** 委托 `EndpointUrlValidator.isBlockedIp`（黑名单不复制，防两套名单漂移）。
4. **新增 `AiModelEndpointValidatorTest`**（D2 P2 判据命名，`@Tag("dev")` 18 例）：黑名单段位/IPv6/数字字面量/IPv4-mapped/userinfo/allowlist 双向/保存入口 create+update+embedEndpoint 负控/公网正例/unresolvable fail-open。

## 4. 语义决策（与既有契约对齐）

- **allowlist 豁免**：`ai.allowed-hosts` 命中 host 字符串等值豁免（R184-A 语义），默认空串严格拒绝（R212「生产默认空串 ⇒ loopback 仍被拒」）。dev/mock 场景保存 127.0.0.1 端点需配置 `ai.allowed-hosts: 127.0.0.1`（**迁移注意**：存量 mock 行再编辑同理）。豁免不覆盖云元数据（`allowlistDoesNotExemptMetadata` 反例钉扎，防豁免口变 SSRF 开口）。
- **保存侧 fail-open / 出站侧 fail-closed**：解析不到的域名可保存（P421 既有 `https://a.b` 用例不破坏），出站前 `AiChatClient` 抛 "endpoint host unresolvable"。
- **未纳入本轮（残留）**：① `enable()` 不加闸——存量行（含 D2 探针行 2104855400313536513）仍可激活，但出站 C 路必拦（P421 `connectFailNoLeak` 已证 loopback 端点 testConnect fail），激活面收紧待运营口径确认后补；② D2 B8「SSRF 实际外发验证」仍需隔离环境（探针行 is_active=0 未触发调用）；③ 存量探针行清理走 D4 §L535 流程整改的批量清理约定（`d-probe-` 前缀识别）。
