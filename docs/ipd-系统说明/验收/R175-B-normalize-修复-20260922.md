## 一、问题诊断

### 真库数据分布（apply 前基线）

| status | enabled | 条数 | 备注 |
|---|---|---:|---|
| `PUBLISHED` | `Y` | **33** | **老格式**（被前端 normalize 误识别为已停用） |
| `published` | `1` | 33 | 新格式 |
| `draft` | `0` | 1 | 草稿 DT1790084411 |
| **合计** | | **67** | |

### 根因

`apps/web-antd/src/api/ipd/gate-element.ts` 第 79-99 行的 normalize() 函数：

```typescript
// 改造前（不兼容老格式）
const statusRaw = row.status;
if (statusRaw === 'draft' || statusRaw === 'published' || statusRaw === 'archived') {
  status = statusRaw;  // ← 'PUBLISHED' 直接丢失，status 字段 undefined
}
return {
  enabled: row.enabled === '1' ? '1' : '0',  // ← 'Y' 不是 '1'，归为 '0'
  ...
};
```

**前端展示链路**：
- normalize 把 `enabled='Y'` 错归为 `'0'`（已停用）
- 管理视图列表（`listGateElementsForManage`）的 33 条 PUBLISHED/Y 全部被识别为"已停用"
- 业务视图（`listGateElements`）后端 SQL 过滤 `enabled='1'`，所以 PUBLISHED/Y 根本看不到 → 33 条"幽灵数据"只在管理视图里

**真实停用数**：根据 R175-A 真活验证的人工核对，真实停用数 = **10 条**（来自其他 SQL 查询通道，含归档 + 真 disabled，详见 R175-A 报告）。本任务不 apply SQL，无法直接 SELECT 验证，但前端 normalize 修复后会让"已停用"统计等于真停用数，不再出现"误判 33"。

**normalize 模块实现**（按任务原文）：

```typescript
// apps/web-antd/src/api/ipd/gate-element/normalize.ts
export function normalizeStatus(status: string | null | undefined): string {
  if (!status) return 'draft';
  return status.toLowerCase();
}
export function normalizeEnabled(enabled: string | boolean | number | null | undefined): '1' | '0' {
  if (enabled === true || enabled === 'true' || enabled === 'Y' || enabled === 'y' || enabled === '1' || enabled === 1) return '1';
  return '0';
}
```
