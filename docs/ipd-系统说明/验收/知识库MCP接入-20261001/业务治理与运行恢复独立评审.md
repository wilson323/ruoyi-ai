## 关键缺口与具体影响

### 1. 普通项目事实未成为模型输入（P1，源码直接证据）

agent/kernel/ProjectAgentPrompt.java:25-61 仅加入当前动作、本轮输入、技能和可选需求分拣目录。ProjectAgentRunSpec.java:29-32 没有项目名称、项目目标、产品、产品线、阶段或已审核业务摘要。Kernel:111-143 用 projectId 构造隔离键与绑定工具，但 projectId 本身不是项目语义事实。普通项目运行不能仅凭选定项目准确分析应调用哪条产线 MCP；要求用户为未指定产品线手选服务会把设计缺口转给用户。

最小建议：业务端构造受授权、版本化的 ProjectContext（项目/产品/产品线/当前阶段/目标/现有证据/不确定项），作为独立可信上下文注入。模型可以在获授权候选服务中提出路由和理由；服务端仍验证项目、Person、候选库权限。产品线未知时，以项目信息、任务意图和目录描述形成候选，证据不足才澄清，不能凭语义推断扩权。上下文版本与路由候选应留在本次运行审计里。

### 2. 历史持久化不等于恢复执行（P1，源码直接证据）

ProjectAgentRunSpec.java:11 明示完整输入仅内存传递；RunService:494-499 只落配置快照和 inputDigest/inputChars，不落可重建的任务输入。Kernel:191 调用 disableSessionPersistence，但经 2.0.3 源码复核该方法是 no-op，不能据此声称关闭会话持久化；Executor:143-145 的 handles 是本机句柄，153-164 用本机 scheduler，等待超时也在本机 schedule（348-361）。cancel:309-324 依赖本机 handle；agent 目录针对 recover/lease/heartbeat/stale 的检索未发现恢复扫描。

因而进程中断后的 RUNNING/WAITING_APPROVAL/CANCEL_REQUESTED 没有在当前范围发现可靠接管或失败收口。不能把事件回读、浏览器刷新恢复或框架支持 session persistence 写成已具备 durable execution。本次没有杀进程故障试验，具体遗留行数量未查库。

最小建议：先明确短运行中断时“失败并保留证据”还是“恢复”。前者可以现有库做 owner/lease、启动协调扫描与超时收口，避免幽灵运行；后者还需要安全保存可重建输入、模型/提示/工具版本、已完成步骤与工具结果，并区分可重试读操作和未知副作用。无需先引入 Temporal；其持久化语义仅用于验收对照。

### 3. 产物应用不是完整原子闭环（P1，静态并发风险，待实证）

RunService:200-239 无外层事务，219 先创建文档，222 再 markApplied。store/MybatisArtifactVersionStore.java:61-70 用 DRAFT 条件 CAS。两个并发请求可能都创建文档，CAS 败者返回胜者 documentId，自己创建的文档却已经存在；文档创建成功而 CAS 前崩溃也存在相同孤儿窗口。现有幂等成功路径只能覆盖已经 APPLIED 的重试，不能覆盖这个窗口。

最小建议：在现有库事务中锁定/认领产物应用，文档生成与关联统一提交，并以产物版本为业务幂等键保证至多一个正式文档关联。对已发生未知结果应查询关联事实再重试。验收应包含双请求并发和创建后异常，核对 ai_documents 行数及 artifact.document_id，不靠 mock 判断。

另外 RunService:211-214、226-232 的已应用回放硬编码 GENERATED 与 NOT_INDEXED。若文档后来被人工审核/向量化，重复应用响应会倒退到陈旧状态。应回读同一 documentId 的实际状态与索引状态；文档不存在应报冲突，不能继续回放一个假事实。

### 4. 配置快照不足以可复核重放（P2）

Planner:148-151 保存包版本、modelConfigId、技能哈希和 toolIds；RunService:494 写入该快照。没有当前项目事实版本、模型配置内容摘要、提示词版本、工具实现版本、MCP 服务/库选择版本或完整检索证据快照。Kernel:285-300 SOURCE 留 query/hits/chars/截断 preview，仍不足以严格验证最终每个数字对应哪段来源。

最小建议：优先保存脱敏模型参数和配置摘要、ProjectContext 摘要及版本、工具和服务清单版本、实际 SOURCE 的稳定文档/片段ID、原文哈希和定位。不得把凭据加入快照。历史结果可以复核，不要求随机模型逐 token 重现。

### 5. 完成检查只是窄安全栏（P2）

agent/service/ProjectAgentCompletionGate.java:50-63 只拦截若干 Gate 宣称，以及检索零命中却没写“未取得”；任一 SOURCE hits>0 就 anyHit=true。它没有检验最终数字、单位、年份、出处和引用对应关系，也不能证明整个动作需求完成。此次海康威视 12.83% 命中事实仅闭合检索切片，不能闭合 MCP 路由或 C02。

最小建议：引用用稳定 sourceId 结构化绑定到产物，关键数值采用可确定检查，按动作检查必要字段/缺失说明；无法验证即保持草稿与人工审核。独立评估需要混合来源、同名文件不同版本、工具部分失败、年份/金额/百分比扰动、零命中以及越权库负例。普通短答不必套复杂多代理流程。

### 可确定缺口：先成功、后产物落库失败被吞掉（P1）

IPD `ProjectAgentRunHandle.java:250-291` 先 CAS 迁移 SUCCEEDED，再调用 `persistArtifactDraft()`；落库异常只 warn，继续写成功终态。`onSucceeded` 需求绑定异常也仅 warn。这不是官方框架提供的“业务完成”保证：官方 `AgentRun.java:65-95` 的 COMPLETED 仅是 Flux 正常结束，不能说明本项目 Artifact 或需求回写已成功。

确定最小改法：把正式成功提交与必需产物落库放进业务事务/协调提交；文本回答可以定义不要求产物，但动作生成任务不得成功无交付物。禁止简单把产物预先落库后忽略取消竞态。可新增 store 的 `finishSucceededWithArtifact` 原子接口（终态 CAS、产物、事件一起事务提交），失败时收口 FAILED 或显式持久化失败待协调。需求绑定若是该任务验收条件，应纳入结果或独立明确可回补状态，不能只日志。测试：artifactStore 抛错、终态event落库抛错、CAS被取消抢占、绑定失败；断言没有 SUCCEEDED 且缺必需产物/终态证据组合。

### 跨版本差异：runId 同源不能直接套新版

官方 `RuntimeContext.java:75-81、124-130、403-410` 若未指定 runId 则生成 UUID，并支持 builder.runId；`AgentRun.java:112-116` 支持与 context 同源。IPD `KernelScopeKey.java:39-41` 只设置 userId/sessionId，业务 runId 仅折到 sessionId。新源码可用于设计链路 ID 同源，但本机 **2.0.3 sources.jar RuntimeContext 未发现 Builder.runId 方法**，不能直接提交新版调用导致编译不兼容。最小策略是 2.0.3 用 RuntimeContext 已有属性写业务 runId 供自有 hook/trace 读，业务事件继续认原 runId；是否升级 SDK 另评估并做 API 编译探针。

### 取消和权限：保留业务控制，不盲目换协议

官方 `AgentRun.java:28-32、145-158` 明确单次句柄拥有取消信号，订阅取消会取消句柄；`InterruptControl` 是运行期信号，不是持久化审批/取消记录。因此 IPD Handle dispose 本机订阅用于当前读操作可成立，但 Executor 当前仅本机句柄不能覆盖重启后的 CANCEL_REQUESTED，仍需业务协调收口。官方 `PermissionEngine.java:35-47` 指明工具规则与只读/危险路径检查存在独立顺序，不能用 Prompt 替代权限；本项目自有 READ_ONLY governance 与运行工具白名单应保留，具体 MCP 候选授权必须在业务适配器再核验，不能仅相信 MCP 描述标注 readonly。

### 必须删除或纠正的错误/过度设计

- **PlanMode 双权威不成立**。Kernel.buildAgent 没有 enablePlanMode，并关闭动态能力；当前使用 INTENT/AWAIT_USER（Executor:269-344）。附件一面写SDK计划不启用，一面把它列为实际双权威根因，内部矛盾。保留“未来不得引入第二权威”规则即可，不能虚构已发生冲突。
- **同一终态 Run 返工违反当前合同**。`AgentRunStatus.java:18-21、59-67` 明确 SUCCEEDED/FAILED/CANCELLED 不可再迁移。审核退回是 `AiDocumentService.reject:393起` 对已有版本改REJECTED；`revise` 新版回GENERATED。返工可新建相关联的执行尝试并保留原终态，通过原文档版本链管理正文，不应强制回退已终态 Run 或让旧 PlanVersion“复活”。处于 WAITING_APPROVAL 的同 run 确认可设计结构化承接，但这是待实现的独立续行协议，不能用它改所有终态语义。
- **新运行承接确认不自动等于历史断裂**。问题是父运行/确认内容/版本关联不足；可先在现有事件建立来源run和确认摘要关联，校验问题与步骤，避免无依据新增 plan_version 表。是否同run续行要核现有前端和任务合同，不先作产品决策。
- **SDK session persistence 关闭结论错误**。已用2.0.3 sources.jar证实 disableSessionPersistence 是no-op，默认文件状态仍存在；必须纠正文档图和恢复推断。
- **失败不能标成无命中**。附件T9把向量断网归EMPTY_NO_HITS，与其自身PARTIAL/ERROR/TIMEOUT语义冲突。全路失败应ERROR/TIMEOUT；成功查询零行才EMPTY；部分成功显示各路状态，不隐去故障。
- **断开查看连接不必取消任务**。ProjectAgentRunService.create 返回稳定runId并异步submit；events:287起是增量查询，cancel:311起是独立显式动作。浏览器断线应支持任务继续与重放，附件T3“SSE EOF后模型必须停止”不能泛用项目run。副驾交互流是否断线取消应单独按该产品合同验证。
- **迟到事件无需写新OBSOLETE枚举**。当前 AgentRunStatus/Handle 合同是取消后迟到帧不进入业务主链。可增加审计计数，但不要求记录每一帧、不为测试新增事件协议。
- **大字符串ID门禁不应禁止Long.parseLong**。前端JSON必须字符串是合理规则；服务端对十进制ID用Long.parseLong（如RunService:373起产品线）是合法解析。应禁止浏览器Number造成精度丢失和响应数字化，而非全仓无Long.parseLong。
- **假设Schema的SQL不是独立证据**。附件 ai_documents.createdByRunId/idempotencyKey、effect_intent、plan_version、run_manifest、project_stage_artifact 等查询不能当当前可运行验收脚本。应使用当前mapper/domain确认的真实字段及关联写验收，再决定最小Schema变更。
- **一律真实模型会过度测试**。状态CAS、事务失败、超时、解析/大ID等确定性测试应使用可控故障与本地真实存储；真实Person/模型/检索/浏览器用于端到端产品验收。全套测试必须真实模型会让故障注入不稳定，并不能增加确定性正确性的证明强度。
