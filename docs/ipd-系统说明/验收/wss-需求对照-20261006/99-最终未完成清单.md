## 0. 先反思：本轮补查找出了九域报告的盲区

owner 2026-10-07 指令「每个阶段的产物都应该有模板及规范要求（SOP），门禁清单要完」点中了两处此前九域报告**没有作为独立维度系统盘点**的缺口：

1. **SOP 体系空壳**：A7 只核对了「深管动作行有没有 SOP 字段/通道」，没有盘「SOP 内容体系是否真的建了」。本轮现查：`sop_templates` 全库仅 **2 行**、`sop_template_instances` **0 行**、`stage_actions.sop_id` 在 **1130 行动作实例里填充 0 个**——wss 要求 42 个深管动作「强制展示绑定的 SOP 富文本」，实际**没有一个动作绑上 SOP**。
2. **门禁要素数量漂移**：A3 逐项核对了「需求 33 项要素是否建库」（结论：已建），但没有盘「库里比需求多出多少」。本轮现查：`gate_review_elements` 现有 **87 项**（G1=25 / G2=20 / G3=10 / G4=16 / G5=16，其中否决项 38）vs 需求 **33 项要素 / 14 项否决项**——多出的 54 项 / 24 项否决**来源未核对**，属自创拆分还是子项展开，须逐条溯源后对齐。

教训一：**「有表、有字段」不等于「体系建成了」，比对必须下钻到行数与填充率**。
