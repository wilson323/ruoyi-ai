## 0. 裁决

**未闭环。**

wss 原始需求与正式系统之间存在**大面积、跨全部业务域的实质性偏离**，不是零星遗漏。约 2700 条比对项中，判定「一致」的仅约 510 条（≈19%）；「不一致」587 条、「缺失未实现」1022 条（其中约 124 条属 owner 已授权退役，见 §1）、「过度设计」566 条（其中 282 条为框架公共列，业务性过度设计约 284 条）。

更关键的不是数量，而是**四条主干链路整体断裂**：

1. **Gate 链路从未真跑过**：`gates` / `gate_reviews` / `gate_arbitrations` / `gate_waivers` 四张表全 0 行；且「条件通过」判定值前后端断裂、遗留项关闭接口字段错配、Gate 否决不阻断阶段推进 —— 三者叠加使五大 Gate 在工程上不可用。
2. **双PM 组队链路失锚**：`dual_pm_assignments` 表不存在，双PM 绑定关系散落在 `project_members`；存量导入不指定双PM；招标流程倒置（项目先建再招标，300 项目仅 29 行 RD_PM）。
3. **多项目备案链路「表在码缺」**：`multi_project_capacity_approvals` 32 列 0 行、Java 零引用、前端无路由；备案被降维成 `project_members.approval_ref` 无校验自由文本 —— 填 `"1"` 即可绑第 3 个项目。原型的两级审批流转完全未实现。
4. **算钱链路一半被授权拆除、一半是死代码**：奖金池/回款/业绩窗口三域已由 owner 于 2026-10-03 授权退役（§1）；但**月度津贴不在退役范围**，其封顶计算函数零生产调用、负反馈零作用、写路径校验全是死代码、台账全员可读 —— 这些是真实缺陷，不能用退役解释。

**因此：不能以「wss 需求已实现」对外声明。** 若 owner 认可退役范围，则须先做 §7 的口径重定（动作 69→67、验收 AC 237→192、Gate 要素 5 处失效引用），再按 §5 的 P0 清单修复；否则缺失面还要更大。
