## 四、新发现：gate 值域与 qa04 结构漂移（三项，建议机制化而非客户端兜底）

- **R-1 无 DB 级值域约束**。`ipd_dev.gate_review_elements` 列定义
  `status varchar(16) NOT NULL DEFAULT 'published'`、`enabled/is_veto/veto_dual_required char(1) NOT NULL`，
  `TABLE_CONSTRAINTS` 只有 PRIMARY + `uk_gate_element_code`，**零 CHECK、零 ENUM**。
  值域目前只由服务层「写时归一 + 校验」守护，**读路径原样返回存储值** → 人工 SQL / 外部灌数
  绕过服务层即可让老格式回流，且 API 会照原样吐出。
  建议：按 ADR 评估加 CHECK 约束（DDL 变更属高风险，需 owner 授权 + DBA apply；
  本仓无 Flyway/Liquibase，「SQL 已 commit」≠「约束已生效」）。
- **R-2 `ipd_qa04` 落后 6 列 + 缺唯一键**。dev 22 列 vs qa04 16 列，缺
  `threshold_json`、`sign_due_at`、`sign_extension_count`、`veto_dual_required`、`status`、`version`，
  且 `ipd_qa04` 无 `uk_gate_element_code`。该库在 `治理轮/R9c-D4-孤儿库裁决提案-20260905.md`
  属「4 个在用库」之列（非孤儿，不在归零范围），若 Qa04 并发测试覆盖到 gate 要素链路会直接
  `Unknown column`；现表 0 行故暂未暴露。建议：在 R9c-D4 在册口径下二选一——补列对齐，或明确降级为只读快照。
- **R-3 DDL 核验器存在覆盖缺口**。今日产物 `验收/ddl-apply-check-result-20260929.json`
  含 `ipd_qa04` 但**不含 `gate_review_elements`** → 上述漂移不会被现有哨兵喊出来。
  建议把该表纳入 `p1-ddl-apply-check.py` 的 D1/D2 清单。
