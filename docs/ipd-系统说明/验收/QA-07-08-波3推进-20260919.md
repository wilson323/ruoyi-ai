## 1. QA-07：后端错误码覆盖检查（前端只读边界下的可做部分）

**口径**：QA-07 卡面主体是前端 49 页错误/空态出口（前端仓只读，无法本轮实施）；本轮检查**后端 code 包络非 0 的错误路径是否有定义**，产出缺口清单供前端联调与后端修复排期。

### 1.1 正面确认（覆盖到位）

`ApiV1ErrorCode`（`org.ruoyi.ipd.common`）枚举体系完整：0 / 1xxxx 参数 / 2xxxx 认证 / 3xxxx 权限 / 4xxxx 业务规则 / 5xxxx 资源与状态（含 P3 系列专项码）/ 90002 配置冲突；`IpdServiceExceptionAdvice` 有专用 handler 链（本轮真活 15 项探针全部返回规整包络，见 SEC-04 报告）。

### 1.2 缺口清单（3 项，均本轮真活复现）

| # | 触发方式 | 实测响应 | 期望 | 严重度 |
|---|---|---|---|---|
| G1 | GET 不存在的端点 `/api/v1/nonexistent-endpoint-xyz`（带合法 token） | **HTTP 200** + `{"code":404,"msg":"No endpoint GET ..."}` | HTTP 404 + `code=50001` + `message` 字段 | 中：RuoYi 框架层兜底未走 IPD 包络（字段名 msg≠message、码 404∉枚举），前端统一解析会漏 |
| G2 | GET 路径变量类型错 `/api/v1/demands/abc/triage`（abc→Long） | **HTTP 500** + `code=90001`"系统内部错误" | HTTP 400 + `code=10001` PARAM_INVALID | 中：`MethodArgumentTypeMismatchException` 无专用 handler，被 `Exception.class` 兜底压制语义 |
| G3 | 空路径变量 `/api/v1/demands//triage` | **HTTP 200** + 纯文本"非法请求：/api/v1/demands//triage"（非 JSON） | HTTP 400/404 + JSON 包络 | 低（前端不产空 id URL，但代理/重试链路可能触发） |

建议：G1/G2 各补一个 `@ExceptionHandler`（NoHandlerFoundException / MethodArgumentTypeMismatchException）映射进 ApiV1ErrorCode 体系即可关闭；登记为后端小修卡候选，**本轮不改代码**（授权范围不含代码修复）。
