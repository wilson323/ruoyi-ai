## Part B：权限断链修复（p1/p2）

### B1 症状

1. 超管访问 `/system/menu` 显示「访问被拒绝——您没有菜单管理的访问权限」（整页 403 Fallback）。
2. **更严重（可逆实验暴露）**：任何一次完整登录把 `accessCodes` 覆盖为 IPD 语义后，**46 个页面**（含 AI 平台约 15 个）的全部 `v-access:code` 按钮（新增/编辑/删除/导出/导入…）静默消失。

### B2 根因链（浏览器 pinia + localStorage + DB 三方实锤）

| 层 | 事实 |
|---|---|
| vben 遗留语义 | `hasAccessByRoles(['superadmin'])` 期望小写角色 key；`hasAccessByCodes` 中 `'*:*:*'` 为超管全通码，否则逐码判定 |
| IPD 通道写入 | `person.personType` 为**大写**枚举（`SUPER_ADMIN` 等），三处身份安装点写 `roles=[personType]`、`accessCodes=[scope, 'personType:xxx']` |
| 脱节后果 | ① `roles=['SUPER_ADMIN']` 不含 `'superadmin'` → `/system/menu` 整页 403；② accessCodes 无 `'*:*:*'` 也无功能码 → 46 页按钮全判否 |
| 为何此前未暴露 | 本机 localStorage 残留着 9-10 前旧 RuoYi 通道（`/system/user/getInfo`）写入的 `['*:*:*']`（accessStore `persist.pick` 含 accessCodes），掩盖了缺陷 |

**可逆实验（决定性证据）**：将 localStorage 中 accessCodes 改为 `['FULL','personType:SUPER_ADMIN']` → 刷新 → `/system/user` 按钮从「重置/搜索/导出/导入/删除/新增/编辑…」缩为「重置/搜索/启用禁用/更多」——所有 `v-access:code` 按钮消失；恢复 `['*:*:*']` 后全部回归。

**影响面盘点**：`v-access:code` 用于 46 个页面；`v-access:role` 仅 system/menu 5 处按钮（同根因）。
**后端权源头核查**：`IpdRolePermissionCatalog`（personType → Sa-Token 权限码）仅被 `IpdStpInterfaceBridge` 后端消费；`/auth/me` 只返回 `{person, scope, mustChangePwd}`——**权限码从未下发前端**（非超管码下发为在案 V1 路线图项，本次不扩面）。
