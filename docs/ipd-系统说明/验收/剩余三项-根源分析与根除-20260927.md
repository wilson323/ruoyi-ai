## 2. 根源剖析

### 2.1 共同根源：挂账台账自身成了无对账机制的第 N+1 事实源（病根⑤变体）

### 2.2 ②的三层深根源（唯一真技术遗留）

1. **结构性缺失**：个人绩效系数没有持久化点。`bonus_pools` 无该列，distributions JSON 只存团队拆分（且 171/174 为 NULL）；计算时实际入参**不可从存储复原**——审计永远无法单路还原 finalPool 的系数因子。
2. **文档失真**：`Lc03SettlementReconcileService` 注释与 DIFF 文案称「仅入 distributions JSON」，指向一个实际不含该数据的位置（真库实测证伪）。审计方照注释去查 distributions 会一无所获。
3. **伪绿面（病根①变体：行为无测试锁）**：`reconcileFinalPool` branch2——存储值命中中性路即判 MATCH「系数按中性复算一致」，**即使 kpi_records 推导系数≠1.0 也不披露**。审计方看到 MATCH 无从得知「kpi 说 0.6、账按 1.0 入」的分歧；MATCH 只证明公式自洽，不证明系数业务正确，原实现把两者混同。
