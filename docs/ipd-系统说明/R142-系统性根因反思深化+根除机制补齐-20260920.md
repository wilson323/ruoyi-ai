## 二、R142-A 元根因深化穿透结果

### 2.1 新增 4 元根因（M-Root-8~11）

#### M-Root-8：反思主体缺乏自我应用约束（认知失真悖论）
- **描述**：AI 能精准写出根因描述，但自身行为不必然遵守自己写出的根因清单——**写根因 ≠ 守根因**
- **证据**：
  - R131 §三.4 R131-D2 = R121/R122/R123 三轮共享 commit `3df19c34`，反思链本身违反 R-4 同分钟多 commit 撞 hash 根因
  - R131 §三.6 R131-D4 = 本会话上一轮 `cd ruoyi-ipd-web` 无绝对路径前缀开头，违反 R-5 跨仓 cd 根因
  - R131 §三.7 R131-D5 = 18 项拍板挂着，反思提议 ≠ 反思执行
- **根除方向**：自我应用约束钩子（pre-commit 强制对比「行为日志 vs 根因清单」，发现违反即拒绝提交）；每份 R 报告末尾必加「本会话自检段」（撞号/跨仓 cd/决策包版本号现查）

#### M-Root-9：跨会话身份隔离盲区（共享资源假设失效）
- **描述**：避让约定下默认假设「对方不动 = 我也不动」，但对方可能让共享资源（端口/PID/DB 表/Redis 缓存）处于未知状态，AI 主体探测不到对方意图
- **证据**：
  - R129 §八.8.2 三仓分仓只约定整点分批 commit，没探测兄弟会话是否占用共享资源
  - R131 §一.1 让路边界列出 11 项「不动」事项，但「对方是否也按相同约定让路」无探测机制
- **根除方向**：preflight 加「兄弟会话共享资源快照」（PID 列表 + 端口列表 + DB 锁等待列表 + Redis key 列表）；让路信号显式化（兄弟会话必须写让路信号文件，写明让路时长）

#### M-Root-10：拍板契约信息衰减（owner 阅读疲劳 + 决策包版本漂移）
- **描述**：拍板是异步动作，从「AI 出决策包」到「owner 拍板」之间存在时间窗，期间决策包上下文在 owner 心中衰减，决策包本身可能升级版本，引用方没同步
- **证据**：
  - R128 18 项拍板 → R129 §七.1 拍板优先级矩阵 → R130 派单序列 → R131 §五.4 6 项自动通过 → 决策包版本多次升级
  - R121/R122 拍板包 7 天未决 = owner 阅读疲劳导致拍板挂死（R131 §三.7 D5）
- **根除方向**：决策包重读机制（owner 拍板前必须确认决策包版本号 = 当前最新版本）；拍板窗口期策略（决策包 N 天后强制失效需重提）；「拍板摘要卡片」机制（决策包落档时同步生成 5 行摘要卡片，写到看镜像）

#### M-Root-11：AI 工具链假设漂移（环境假设与运行时错位）
- **描述**：AI 在沙箱内跑命令时假设进程/文件/网络/权限可用，但实际可能受 sandbox 回收、超时截断、权限不足、依赖未装、版本不一致影响
- **证据**：
  - R-3 Sandbox 回收 java 是工具层表现，元根因是 AI 没探测 sandbox 假设
  - R129 §五 H-2 PID 30s/60s/120s 三次巡检 = 已经识别一半，但更深一层是「工具可用性假设」未在脚本头部显式声明
  - R130 §2.4 提到 cron 任务写了未注册 = 工具假设错误
- **根除方向**：脚本头模板必含「前置依赖声明段」（必须声明需要的进程/文件/网络/权限/版本）；preflight 加「工具可用性探测」（跑命令前先 dry-run）；超时显式化（每个命令必须设 timeout，否则 sandbox 30min 后回收）
