## 二、注意事项（撞车 0 严守 6 红线 + 反复根因 5 条）

### 撞车 0 严守（6 红线）

1. **不杀兄弟会话进程**：PID 34560 ry-vue 后端（连 `23306/ry-vue` 库不撞 ipd_dev）、PID 70554 vite 15666
2. **不抢兄弟端口**：16039 闲置 = IPD 后端可用，但**撞车 0 让路下默认不起**，需 owner 拍板
3. **OPS-09 单一写入者**：主仓 docs/ 是例外白名单；Java/SQL 改动必须 worktree 隔离
4. **跨仓 cd 绝对路径开头**：所有命令 `cd /Users/mac/Documents/ruoyi-ai &&` 绝对路径（实测 shell cwd 漂是反复根因）
5. **DDL 不擅自动**：撞车 0 严守下 AI 不 apply DDL，由 SRE apply
6. **不在前端仓跨仓直写 docs**：报告统一写后端仓 `docs/ipd-系统说明/`

### 反复根因（5 条，撞车 0 让路下要刻意避免）

1. **shell pipe trap**：`bash X.sh | tail; echo $?` 测的是 tail EXIT 不是脚本 EXIT（必须用 `bash X.sh >/dev/null 2>&1; echo $?`）
2. **额外-location 静默回落**：启后端必须带 `--spring.config.additional-location=file:.codex/ipd-dev/config/application-ipd-local.yml`
3. **Sandbox 回收后台 java**：必须 `is_background=true` 终端 + `exec java ...` 前台化
4. **撞号撞车根因**：commit 前必 `git fetch && git log --oneline -5`（同分钟多会话响应同指令会撞号）
5. **五必现查规约**：hash / 端口字段 / 段号 / 看板回读 / 跨仓 cd 必须现查现写

### 看板操作纪律（5 条）

1. 看板只认 ruoyi-ai 项目（`01dcf15c-86bb-4c7b-957c-8fe44bddd10d`），禁止 ZKER-staff 污染
2. 做完一件事立即同步看板，不等收尾批量
3. 每次 PUT 后必须独立 GET 读回复核落档（PUT 偶有静默失败）
4. 看板 PUT 是整体替换语义，单卡 GET 可能返回空描述
5. 看板总账数字严禁推算，必须 fresh 拉 API 验证

## 五、最佳实践（M1-M5 长期根除机制）

### M1 拍板项看板化

- **做法**：扩展 SSOT 镜像 `开发计划-看板镜像.md` §X 拍板项追踪表 + 登记 16 份拍板包
- **目的**：撞车 0 让路下拍板项不丢、不漏、可追踪
- **落地**：30 min

### M2 拍板时限红线

- **做法**：`scripts/check-decision-deadline.sh` + cron 每日 02:00 + 看板标红
- **红线**：拍板项默认 7 天未决 → 升级到 owner 邮件 + 看板标红 🔴 + 自动派单 worktree
- **落地**：1 hr

### M3 整改派单序列化

- **做法**：`scripts/check-wt-stacking.sh` + 每周日 02:00 cron
- **目的**：避免 wt 堆积（当前 11 个 wt），每派单只发一个 wt，闭环后才发下一个
- **落地**：1 hr

### M4 跨仓 cd 绝对路径强校验

- **做法**：pre-commit hook `check-cd-absolute-path.sh`
- **目的**：避免 shell cwd 漂（实测反复根因）
- **落地**：30 min

### M5 真活 E2E 阻断门禁

- **做法**：`.github/workflows/e2e-gate.yml` + `check-e2e-fe-be.sh` 接入
- **目的**：5 项业务契约不过不能 merge
- **落地**：2 hr

**核心结论**（来自 R127 治理盲区反思）：

> **扫了 ≠ 改了 ≠ 闭环了** — R25/R109/R118/R119/R121/R122/R126 反复出脚本/报告/拍板包，但**没有一项是"脚本→报告→派单→整改→验证→闭环"全链路自动化**
>
> **撞车 0 严守 ≠ 拍板可以无限期挂着** — 撞车 0 是治理铁律，但**铁律之上没有"何时必须解铁律"的退出机制**
>
> **底座二开 ≠ 可以偏离底座规范** — 65 Service 无 Impl / 39 Mapper 缺注解是底座核心约定，不是偏好
