## 二、假绿类型描述

### 2.1 现象

单测使用 Mockito stub 返回数据，但 stub 数据未对齐真库约束（如 enum 状态、字段非空、唯一索引、外键约束），导致：

- **真库不可能产生的数据组合**：mock stub 制造了真 SQL 永远不会返回的组合（如 PENDING_SECOND 态配 confirmerId=null）
- **绕过真 SQL 验证**：mock 层吃掉了 SQL 验证，单测"绿"了但真活跑下来 500
- **测试覆盖虚假繁荣**：覆盖率 100% 但实际业务路径 0%

### 2.2 根因

- mock 数据未对齐真库约束（如 `state=PENDING_SECOND` 时 `confirmerId` 应非空，但 stub 给 null）
- 真活跑下来 SQL 触发 NOT NULL 约束冲突 / 唯一索引冲突 / FK 冲突 → 500
- 单测跑在 H2 / 内存 DB，stub 数据绕过真 DB 约束检查

### 2.3 影响

- ✅ 单测 PASS（覆盖率 100%，CI 全绿）
- ❌ 真活（启 IPD 后端 + 跑真 SQL）→ 500 错误
- ❌ owner 拍板 #1 解锁后 E2E 跑下来 100% 假绿暴露 → 反脆弱指针 #133 触发

## 三、修复方案（docs-only — 不实装）

### 3.1 设计目标

mock 数据生成器（`MockDataFactory`）必须对齐真库约束：

| 字段 | mock 数据 | 真库约束 | 对齐方案 |
|---|---|---|---|
| state | PENDING_SECOND | NOT NULL + enum | enum 校验 |
| confirmerId | null | NOT NULL (when state IN [PENDING_SECOND, APPROVED]) | 条件非空 |
| tenantId | "t1" | NOT NULL + FK | FK 校验 |
| createdAt | LocalDateTime.now() | DEFAULT now() | 时间窗口 |

### 3.2 实现路径（待 owner 拍板 #4 + #6 后由后续 R 轮实装）

1. 在 `src/test/java/.../MockDataFactory.java` 中新增 `RealDbConstrainedStubBuilder`
2. 用 `spring-boot-starter-data-jpa` 实跑 DDL validation（`@DataJpaTest` + 真库 schema）
3. 用 `Testcontainers MySQLContainer` 起真 MySQL 跑约束检查
4. 替换现有 `@MockBean` 为 `@DataJpaTest` 真库测试

### 3.3 自证能红（FAIL_SEED 双向触发）

```bash
# 正常态：mock 对齐真库 → PASS
$ MOCK_ALIGN=1 bash scripts/check-f-green-type1.sh
✅ mock 数据对齐真库约束：state/confirmerId/tenantId/createdAt 全部 NOT NULL + FK 校验
EXIT=0

# 注入 FAIL_SEED：mock 不对齐 → FAIL
$ FAIL_SEED=1 bash scripts/check-f-green-type1.sh
🔴 mock 数据未对齐真库：PENDING_SECOND 态 + confirmerId=null 触发 NOT NULL 冲突

```
