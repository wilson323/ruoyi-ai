## 6. R34 R33 已知 pattern 反查

### 6.1 `/auth/platform-token` 端点缺失 — **已修** ✅

- R34 报告:`auth.ts:222` 调用 `/auth/platform-token`,但当时后端无对应 Controller
- 当前状态:`IpdPlatformAuthController` 物理路径在 `ruoyi-admin/src/main/java/org/ruoyi/ipd/controller/IpdPlatformAuthController.java`,`@PostMapping("/platform-token")` + `@RequestMapping("/api/v1/auth")`,于 ruoyi-admin 模块编译进 `ruoyi-admin.jar`
- 实测 POST `/api/v1/auth/platform-token`:返回 HTTP 401 + `{"code":20001,"message":"未认证或凭证失效"}`,**路由真实存在**(无 token 时被 Sa-Token 拦截在认证层)
- **结论:R34 病根已修**,但 Controller 物理位置在 ruoyi-admin 模块(不在 ruoyi-ipd 模块),**R25 病根 ④ 扫描漏报**——应将 IPD Controller 扫描范围扩展到 `ruoyi-admin/src/main/java/org/ruoyi/ipd/controller/`。

### 6.2 McpMarketTool 字段缺口 — **不在本批次扫描范围** ℹ️

- 本任务扫描的是 `apps/web-antd/src/api/ipd/*.ts` 与后端 `org.ruoyi.ipd.controller/*.java`
- `McpMarketTool` 属于 AI 平台/MCP 工具模块,**不在本次契约扫描的 56 个前端文件 + 52 个后端 Controller 之内**
- **建议**:下一轮契约扫描扩展到 `apps/web-antd/src/api/*` 全量 + 后端 `org.ruoyi.system.controller` / `org.ruoyi.chat.controller` 等模块

## 7. 闭环建议

### 7.1 P0 必修(本次扫描结果)
**0 条**。前端 56 个 api 文件 + 后端 52 个 Controller 的路径契约**完全对齐**(剔除测试桩与变量名差异)。

### 7.2 P1 字段名错位(10 处)
- 集中在 4 个 Controller(`AiDocument`、`Bid`、`ProjectCircle`、`Project`)
- 建议:FE 侧把 `documentId`/`invitationId`/`postId`/`projectId` 等语义变量名改为 `id`,统一与 BE `@PathVariable` 名一致
- owner:**前端 / 后端任选一边**,建议 FE 改(向后兼容成本更低)

### 7.3 P2 孤儿端点(101 条)
- 约 30 条是 admin 专用,可标注为 P3
- 约 70 条业务流程端点未对接,需 PM 评估是否本迭代要补前端
- 风险:`BidController` 的 `/admin-assign` `/select` 等关键业务端点前端未调,可能存在流程断点

### 7.4 门禁脚本可加固

建议在 `scripts/quality/` 下新增 `check-api-contract-fe-be.mjs`:

1. **扫描源扩展**:`ruoyi-modules/ruoyi-ipd/` + `ruoyi-admin/src/main/java/org/ruoyi/ipd/controller/`(避免漏掉 `IpdPlatformAuthController`)
2. **路径归一规则**:
   - FE:`${var}` / `${encodeURIComponent(var)}` → `{VAR}`
   - BE:`{var}` / `{var:.+}` → `{VAR}`
   - query string 忽略
   - 前缀统一加 `/api/v1`(FE 经 `requestIpd` 自动加)
3. **三类漂移检测**:
   - **真孤儿 FE** → P0 阻断
   - **变量名错位** → P1 警告,提示命名约定
   - **孤儿 BE** → P2 警告,定期巡检
4. **CI 集成**:作为 `run-e2e-quickmode.mjs` 的前置步骤

### 7.5 R25 病根 ④ 评估
- 病根 ④(前后端契约无门禁)**部分消除**:本扫描结果显示 0 真 P0,但**没有自动化门禁**,下次变更可能重现 R34 的 platform-token 漏报。
- **根因**:`IpdPlatformAuthController` 物理位置在 ruoyi-admin 模块但包名 `org.ruoyi.ipd.controller`——**模块边界与包名约定不一致**,扫描脚本容易漏报。
- **建议**:在 `UNIFIED-RULES.md` 增补一条:**所有 `org.ruoyi.ipd.controller.*` 的 Controller 必须物理位于 `ruoyi-modules/ruoyi-ipd/`,不得散落到 ruoyi-admin**。
