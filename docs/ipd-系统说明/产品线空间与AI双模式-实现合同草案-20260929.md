# 产品线空间与 AI 双模式实现合同（草案，2026-09-29）

状态：`PARTIAL`。本文件记录用户本轮确认的业务口径与当前源码差异；事项状态仍以《开发计划-看板镜像》为准。本机开发库 `ipd_dev` 已执行空结构迁移，后端已有空间/成员/归属接口；尚未做产品线归属回填、前端接线或智能体切换。

## 一、业务对象与不变量

1. `ProductLine` 是稳定的产品线团队大工作空间身份，独立于 `ProductGroup` 组织架构；组织调整不改变空间 ID、项目历史与智能体任务归属。
2. 一个 `ProductLine` 可包含多个 `Product`，每个 `Product` 与 `Project` 保持既有 1:1 合同。由此一个产品线空间可有 N 个项目。项目未绑定产品时不得凭产品组、项目名称推断产品线。
3. 空间级页面展示该产品线团队可见项目的聚合；每个项目是团队大工作空间下的小工作空间。进入项目 AI 模式后，所有引导、知识、技能、工具、审批、产物与任务状态均绑定所选项目。切换项目须建立或恢复该项目自己的任务上下文，不沿用上一项目的会话或未提交卡片。
4. 浏览器提交 `productLineId + projectId` 仅作选择；后端从 Person 会话取得用户身份，验证项目的产品归属、产品线归属、租户及在职项目成员权限后才执行。跨空间项目、已退出成员、未归属产品线必须拒绝，不能降级到全局查询。
5. 其他 Person 可加入产品线空间；空间成员关系独立于组织 `ProductGroup` 和项目 `ProjectMember`。管理员指定某一空间成员为产品线组长，任免均须留下操作者、时间与前后值审计。空间成员身份不自动授予全部项目的查看、写入或 AgentScope 工具权限。

## 二、两种 AI 模式

| 模式 | 用户入口 | 执行语义 | 当前事实 |
| --- | --- | --- | --- |
| 传统界面 AI 副驾 | 现有右侧抽屉 | 在传统页面中问答、建议、辅助填表；业务提交仍由真人在现有页面确认 | `streamCopilot → AiCopilotService → AiGateway` 已接线 |
| AI 工作界面智能体 | 切换按钮进入产品线空间，再选项目 | 以项目任务为单位引导 22 小阶段/69 动作，调用受控知识与技能，产生待审产物，支持审批、恢复和回读 | 当前按钮只切 CSS 布局，发送仍调用 `streamCopilot`；AgentScope 正式 IPD 入口未接通 |

可复用卡片组件、AG-UI 帧翻译和视觉壳，但两个模式须有独立执行入口、会话标识和任务状态。切换按钮不能把传统副驾请求重新命名为智能体执行。旧 `ipd_copilot` AG-UI agentId 维持传统副驾语义；新增产品设计智能体需独立 agentId 与服务端执行适配口，不能在 `AgUiCopilotRun` 内偷偷复用 `AiCopilotService.chatStream`。
两种模式最终均使用 AgentScope 的模型/会话能力，但 Agent Contract 不同：传统副驾只做受控问答与建议，AI 工作界面智能体才承担项目任务编排、工具执行和产物闭环。迁移期应逐入口互斥切换，不能一次请求同时调用旧内核与 AgentScope。

## 三、待审结构与接口

- 结构方案：新增独立 `product_lines`（稳定 ID、编码、名称、状态、租户及审计字段），在 `products` 增可空 `product_line_id`；`projects.product_id` 和现有 Product–Project 唯一约束保持。先建立归属映射，确认所有有效项目能通过 `Project → Product → ProductLine` 回读；未映射行显式列入待迁清单，不根据 `product_groups.group_name` 猜测。
- 成员方案：`product_line_members(product_line_id, person_id, status, joined_at, exited_at, ...)` 成员对唯一；`product_lines.leader_person_id` 表示当前组长，设置/更换仅管理员可做且目标须为在职空间成员。用户确认加入流程采用“本人申请、组长或管理员审批”；无论何种方式都不得靠前端角色快照授权。
- 查询接口：产品线列表只返回当前 Person 可见空间；空间项目列表按项目成员/角色过滤并返回字符串 ID。产品线选择、项目选择、当前任务 ID 分别持久化，前端切换时清理或恢复各自作用域。
- 智能体执行接口：请求携带选定产品线与项目、任务/会话标识及用户意图；服务端完成身份与归属校验后调用 AgentScope。四维推理隔离统一经 `KernelScopeKey.of(projectId,userId,agentId,sessionId)`，产品线身份是业务授权与聚合维，不由前端拼入内核键。
- AgentScope 能力：`ai_model_configs` 是 IPD 模型权威；知识先过 `KnowledgeAccessGate` 并按项目硬隔离；工具在真正执行前过既有 `PolicyDecision`，写操作走审批与幂等账本；任务状态、预算、审计和产物验收由 IPD 业务层持有。会话快照不能冒充任务完成。

## 四、顺序与验收

1. 空结构已在本机开发库落地。下一步先确认每个现有产品的真实产品线归属清单、空间创建者与初始组长，再单独审查数据回填、权限与回滚；不凭组织产品组自动归属。
2. 后端已提供空间列表/项目列表与目录范围过滤；还需验证正例同空间在职成员，负例跨空间、退出成员、未映射产品和租户不符，以及实际项目 AI 执行的产品线归属守卫。不得返回未经授权的项目计数或名称。
   空间成员可看空间级获授权信息；项目级 AI 操作仍需在职项目成员或既有明确豁免。管理员设置组长应有“非成员拒绝、跨租户拒绝、重复设置幂等、更换后旧组长失权”的正反例及审计回读。
3. 前端切换按钮选择两种执行模式；空间内选项目后，AI 模式调用独立 AgentScope 入口；传统副驾仍保持原入口。切换/刷新/取消时分别恢复会话与任务，不串项目。
4. 单个项目的一条纵向链须证实：小阶段目录 → 项目进度/门禁 → AgentScope 引导与受控动作 → 真人审批/业务写入 → 业务表及产物回读 → 审计/失败恢复。再推广到全部 22 小阶段、69 动作及产品设计交付物。
