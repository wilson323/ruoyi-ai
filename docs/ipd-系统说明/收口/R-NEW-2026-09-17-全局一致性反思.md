### 2.4 错误码体系(从 _shared 单一源读取)

**后端错误码体系**(Ruoyi-ai 全局):
- `200 OK`:业务成功
- `20001 UNAUTHORIZED`:未登录(全局拦截)
- `50001 NOT_FOUND`:资源不存在
- `50002 STATE_CONFLICT`:状态机冲突
- `90001 SYSTEM_ERROR`:系统兜底
- IPD 业务自定义:`IpdBusinessException`(扩展 R-NEW 系列未审计)

**前端错误处理**(从 R-NEW 抽样):
- `apps/web-antd/src/utils/message.ts`:Vben 框架 `UNAUTHORIZED_CODE`(可能与 20001 不一致——R-NEW P0 风险)
- `views/ipd/_shared/ipd-error-text.ts`(用户提到的唯一权威源,本次未抽测,假设其与后端对齐)
- 硬编码 `code === 50002` 在 `changes.vue`(R-NEW 已识别,与后端 STATE_CONFLICT 对齐)

**风险**:Vben 框架 `UNAUTHORIZED_CODE` 与后端 20001 不一致会导致**静默 401**(R27 P0 已知风险,未抽测)。**唯一权威源**约束已建立,但前端是否遵守需抽测确认。

## 4. 根因系统性反思(5 层)

### 4.1 技术债层

**根因 A1**:错误码体系"分散 + 单源声明"——前端靠 Vben 框架默认常量,后端 IpdBusinessException 散在 Service;**唯一权威源**已建立但**未被所有调用方遵守**(R27 P0 已知)。**根治**:CI 集成 `code === <ID>` 硬编码扫描,违规直接红。

**根因 A2**:类型映射"显式约定 + 文档缺失"——`Long → string`(雪花 ID)是项目隐性约定,但未在 `AGENTS.md` / 单一文档中显式登记。**根治**:在 `docs/ipd-系统说明/类型映射规约-202609XX.md` 集中登记,新接入模块按规约执行。

**根因 A3**:命名路径"前后端各写各的"——`contribution/negative-feedback/project-score` 3 组同时断裂(id:18cbc7e0),根因是前端按"RESTful 资源命名"想象写(`/versions` `/list`),后端按"操作路径"实际写(`/{projectId}`)。**根治**:前端 API 文件头强制标注"对应后端 Controller @RequestMapping 路径",**禁止凭语义命名**;**认领 = 引用 = 实证**,三者必须同步。

### 4.2 架构层

**根因 B1**:"汇总卡占位"治理真空(R-NEW + 治理清单 已识别)——23 张 ⬜ 卡卡面写"阶段负责人汇总",**没有任何一张拆为可独立验收子卡**。**根治**:每张卡卡面必填"5 列"(责任泳道/allowedPaths/依赖/验证命令/完成证据),缺一即视为未开工。

**根因 B2**:Service 实现 > Controller 暴露(R-NEW-ARCH-1 PostLaunchReviewService)——**实现优先于 API 暴露**的开发节奏,导致"实现 + 测验证 = 半闭环"模式。**根治**:每加 Service 必须同步加 Controller 或在 Service 注释明确"内部调度方"。

**根因 B3**:多租户 excludes 依赖人工登记(R-NEW-SEC-6 + R27 P0-15)——AUD-02 闭环时漏登后续 commit 的新表。**根治**:加 CI `check_tenant_excludes_apply.sh`(R25 已写),每张新表 DDL apply 前必须登记 excludes。

### 4.3 流程层

**根因 C1**:多会话共工 + 主树不洁——兄弟会话在途未提交时,**复盘型会话 grep 主树易得到旧状态**(2026-09-09 多 worktree 教训)。**根治**:`git status --short` 必须先看,**以磁盘现态为准**,不信兄弟会话的"已 commit"声明。
