## 0. 表职责与防双轨原则

| 表 | 职责 | 与登录体系关系 |
|---|---|---|
| `persons` | IPD 登录与人员主数据（既有） | username=PERNR，**唯一登录源** |
| `hr_person_mirror` | HR 人员档案 xlsx 全字段快照（本次新增） | 软引用 `persons.employee_no`，**非登录体系** |
| `hr_organizations` | HR 全公司组织树（R149-v1 已有） | orgeh 编码树，与 product_groups 业务语义不同 |

- 入表前置过滤（`HrSyncRules.isEligible`）：EMPCATEGORY ∈ {Regular, Probation, Relationship}（正式工/试用/退休返聘）；劳务/实习/外包不入任何表。
- 离职口径（`HrSyncRules.isResigned`）：LEAVE_FLAG=X **或** STAT2=0。
- HR 侧 DEL_FLAG 不消费（镜像表只归档）。

## 3. HrResponse.BasicInfo @JsonProperty 覆盖（33 字段）

HR 出参为全大写下划线键名，Jackson 按字段名匹配会**静默丢值**，故逐字段显式注解：
RUFNM / NATIO / FAMST / LIVE_ADRESS / WORK_ADRESS / PHONE / EMAIL_PER / SERVICESTARTDATE /
REGULARDATE / EFFECTDATEMOVENT / BUKRS / CONTRACTSUBJECT / PERSG / DEPTNAME / EXTERNALPOSITION /
ORGPATH / EMPCATEGORY / ZZWTPDJ / POSITIONGRADE / LANGUAGECODE / BANKN / BANKL / LEAVE_FLAG /
KOSTL / KOSTL_T / SUPERVISORNO / SUPERVISORNAME / LIFNR / FILEURL / CERTIFICATE / INSITUTE /
LINE_OF_STUDY / QUALIFICATIONLEVEL。
（其中入库镜像的 15 个见 §1；其余为 HIRE_DATE/LEAVE_DATE 归一映射或本期不落库备用。）

## 4. 传输与签名口径（实现端）

- 网关单端点：baseUrl 即 `/api/router`，POST JSON `{appId, format, method, timestamp, signType, sign, token?, data?}`，业务 method 在 body。
- 签名：参数按字典序拼 `k=v&`（**空值整条跳过**；Map/Collection 值 JSON 序列化后参与）+ `secretKey=` 后缀 → MD5 → **去前导 0 大写**（对齐 HR 文档 getMD5Value 的 `BigInteger(1,bytes).toString(16).toUpperCase()`）。
- 增量：`INPUT_TYP=NEW` + `BEGDA/ENDDA=当天 yyyyMMdd`；全量 `INPUT_TYP=ALL`。
- 调度：每日 0 点 cron `0 0 0 * * ?`，scope 默认 INCREMENTAL；手动口 `POST /api/v1/hr-sync/sync-now?mode=ALL|NEW`。
