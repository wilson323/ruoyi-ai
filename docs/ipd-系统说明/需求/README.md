## 四条硬规则（违反任何一条，这条需求就是坏的）

1. **`source` 和 `implementation` 必须写到行号**，不能只写文件名。
   行号一变就会自然暴露，靠人记是记不住的。

2. **`status` 只有三种值。** 退役必须同时有 `decided_by` + `decided_at`，
   这是为了堵住「待拍板事项全局梳理-20260927.md:97 那个『否决项 14 vs 15 拍 15』永不销号」的漏洞。

3. **正文里不许写统计数字。** 动作数、页面数、端点数这类数字全部去
   [`治理/退役口径基准值-20261007.md`](../../治理/退役口径基准值-20261007.md) 查，
   那里的数字有实测命令。需求文档写数字必然过期。

4. **一条需求一个文件。** 不许把几十条挤在一份「总表」里——挤在一起就必然只改一半。
