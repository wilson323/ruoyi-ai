# R232-LC03 终算对账执行者 · 设计与复用说明

> marker: `r232-lc03-settlement-reconcile` ｜ 日期: 2026-09-27 ｜ owner 指令: 「实施计划」+沿袭「尽可能应用成熟解决方案，避免过多自定义代码，确保全局一致，文档先行」
> 定位：本文是 W14 样板（《W14-智能体节点执行者样板-设计与复用说明-20260927.md》）的**第二个接入者**——严格按 W14 §1 复用矩阵接入，唯一自定义 = 终算对账领域逻辑。后续接入者继续照 W14 矩阵，不另起引擎。

## 0. 方向锚点（为什么这样做）

既定路线 = **完整产品生命周期端到端工作流 + 高质量智能体作为节点执行者嵌入工作流内部**。W14 已证该范式可落地（共担 KPI 对账样板入库）。本任务是第二个样板：**LC03 上市后 6 个月终算对账**——上市 6 个月后，奖金池 finalPool 与回款达成率进入终算敏感区，任何公式漂移、源表改动、配置变更都会直接影响真金白银的分配。由执行者做**只读复算**（stored vs recomputed）产出台账，裁决权 100% 留真人签署链。

四判据选样（同 W14 口径）：
1. **产出可独立验收**：对账台账 md，含六项 stored vs recomputed 逐项比对表 + 公式行 + 免责声明，真人可直接核。
2. **失败可降级不污染下游**：只读复算，**不改任何业务表**；OSS 失败抛异常交引擎退避 → 终 DEAD 转人工，不写脏数据。
3. **可被同岗真人复算**：复算公式与落库公式同源（同一 `BonusPoolService`/`ReceiptLedgerService`），组长用同一口径即可复核，无「AI 专用黑箱算法」。
4. **不改流程天花板（裁决权留人）**：执行器**不 transit、不 recordFields**，只 `addDeliverable` 挂台账 + 知会产品组长；是否采纳由真人签署链决定。

## 2. 六项对账与四判据判定

对账项（stored= `bonus_pools` 落库值，recomputed= 生产公式类现算）：

| 项 | 复算口径 | 不等时判定 |
|---|---|---|
| `RECEIPTS_NET` 回款基数 | `ReceiptLedgerService.windowNet`（6 自然月窗口内回款−退款净额） | DIFF；窗口无行→PENDING_DATA（不按 0 伪判） |
| `POOL_RATE` 池比例 | `readPoolRateZk()`（配置实时读，缺省回退 0.0500） | DRIFT「配置变更后历史池保留原值属正常」 |
| `LEVEL_COEFFICIENT` 项目系数 | `Project.levelCoefficient`（G1 双签后改） | DRIFT |
| `ACHIEVEMENT_RATE` 达成率 | 窗口净额 ÷ `Project.targetSalesAmount`（4 位小数） | DIFF；缺分子/分母→PENDING_DATA |
| `TIER_COEFFICIENT` 阶梯系数 | `tierCoefficientOf(复算达成率)`（六档） | DIFF；上游缺值→PENDING_DATA |
| `FINAL_POOL` 终池 | §三.2.5 公式：回款基数 × poolRate × 项目系数 × 阶梯系数 × 个人绩效系数 | DIFF |

判定四值 = `MATCH / DRIFT（源已变更，历史值保留属正常）/ DIFF（公式或数据不一致，待人工核）/ PENDING_DATA（缺值，不按 0 伪判——W14-02 语义）`。

**个人绩效系数诚实处理（本样板核心难点）**：该系数**不落 `bonus_pools` 表**（仅入 distributions JSON），stored 侧无从比对。处理 = `FINAL_POOL` 双路复算（中性 1.0 / `resolvePersonalCoefficient` 经 kpi_records→projectScoreService 推导），命中任一即 MATCH 并注明命中路；均不符判 DIFF，note 如实披露「个人绩效系数不落 bonus_pools，待人工核」——**不假绿、不伪判**。

## 3. 关键设计决策与两条不变量落点

- **复用既有 LC03 码而非新增动作**：目录 69 数被 8 处测试锁死；LC03 原属 `AgentEvidenceExecutor`（LLM 证据路径），终算对账是**公式复算的硬对账而非 LLM 证据**，故让出该码改由本执行器接管（AgentEvidence 18→17 码、种子 SQL 42→41 行，见 §4 棘轮）。
- **不用 `terminalNoOp` 终态守卫**：对账 DONE 后再对账合法（复核场景），复用终态守卫会误吞复核（同 W14）。
- **缺值 PENDING_DATA 不按 0 伪判**（W14-02）：无奖金池行 → 全项 PENDING_DATA 的「待终算」台账仍是执行**成功**产出；窗口无台账行 → 净额/达成率/阶梯标待补，绝不按 0 伪造「一致」。
- **leadersOf 转发不拷贝**：直接委托 `KpiSharedReconcileService.leadersOf`（public），禁止第三份「成员→组长」解析拷贝。

**两条不变量落点（owner 钦定，测试+哨兵双钉）**：

| 不变量 | 落点 | 钉扎证据 |
|---|---|---|
| ① `supportsSchedule() = false`——只由自然人 PASSIVE 触发，防调度堆台账 | `Lc03SettlementReconcileExecutor.supportsSchedule()` 显式 false（接口 default=true） | 单测 `declaresLc03AndRejectsScheduleAutoDispatch` 断言；哨兵 `scheduleWired` 排除面加「Lc03 对账 1（同 Kpi，防调度堆台账）」，期望 38 不动 |
| ② 只 `addDeliverable` 挂证据，**绝不 transit、不 recordFields、不改业务表**——裁决权留真人签署链 | `execute` 全路径仅 `stageActionService.addDeliverable(id,name,ossId,"0")` | 单测 `producesLedgerAttachesDeliverableWithoutTransitAndReturnsDocId` verify never transit/recordFields |

## 5. 限制与待办（如实披露，不伪完成）

- **真活 HTTP 端到端（check5/6）SKIP**：在跑实例为旧 jar，重启打包会混入兄弟在途未评审批（违反 OPS-09 单一写入者/假绿纪律）。含新执行器的端到端 HTTP 证据待下一次统一部署轮补，不以此样板提前翻 done。
- **个人绩效系数不落库**：stored 侧永远缺该因子，FINAL_POOL 只能双路近判 + note 披露；治本 = 终算落库时把系数随池落字段（需业务拍板，另立卡）。
- **种子 SQL 需 DBA 人工 apply**（本仓无 Flyway）；`20260927-ipd-node-agents.sql` 已改 41 行制（LC03 零 LLM 不建行），未 apply 不阻塞本执行器（不依赖 agent_info）。
- **后续接入者**：继续复用 W14 §1 矩阵（SPI + 引擎 + ByteArrayMultipartFile + addDeliverable + 公式同源），**禁止**为单点需求新建引擎或复制公式；对账类执行者另须遵守本文两条不变量落点。
