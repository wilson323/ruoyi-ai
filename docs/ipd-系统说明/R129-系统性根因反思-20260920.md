## 二、5 个顶层元根因（综合 4 智能体输出）

> **元根因 = 不是"哪里出错了"，而是"为什么反复出错且没人能根治"。**

### 元根因 M-Root-1：**"扫了 ≠ 改了 ≠ 闭环了"是组织语言的失败**

- **4 智能体一致结论**：
  - pm 元根因 D：八轮治理只产"报告+脚本"，无一形成"脚本→报告→派单→整改→验证→闭环"全链路自动化
  - qa 反模式案例库：R25/R109/R118/R119/R121/R122/R126/R127/R128 九轮都是"扫了没改"集成
  - evolver 元根因 #1：R128 把 18 项拍板 + 5 项机制 + 5 根因都写齐了，但**写齐 ≠ 派单 ≠ 落地 ≠ 闭环**
  - agency 跨域根因 C1：E2E 真活从未跑 = 所有"接口齐了"都建立在**纸面声明**
- **证据**：8 轮 R 报告产出 13 个治理 commit（a34a0002/25bc9e87/5e77c3a8/752a8a48/7cbff099/7f0e0fc1/3df19c34/c7833943/80d993c1/b7f0131a/c6e84356/a1808ae9/4843b125）+ 16 门禁脚本 + 5 反复根因 + 18 项拍板 = 累计产出庞大，**但实际真活业务绿 = 0 项**
- **本质**：把"治理"当成"扫描任务"，没当成"流水线任务"。**PM 没有给"闭环"下可量化定义**，导致技术智能体只能交付"扫"
- **根除**：闭环定义（PM 口径）= `派单工单状态=已合并 AND 验证脚本 EXIT=0 AND 看板卡拖入"已完成"列`，三态全真才算闭环。每轮治理报告必给"闭环率"数字 `闭环数/派单数`，< 80% 打回重写

### 元根因 M-Root-2：**拍板机制单向无升级（M2 红线未落地）**

- **4 智能体一致结论**：
  - pm 元根因 A/F：18 项拍板挂着无 owner 反馈 + 11 个 wt 持续堆积 = 派单链路只跑"扫描→派单"，不跑"拍板→执行"
  - qa 隐藏根因 H-9：拍板项无时限红线（病根 #10 实证）— R127/R128 都写"M2 = 7 天红线"，但 `check-decision-deadline.sh` 实测**不存在**
  - evolver 反脆弱度 M2 = 1/5：M2 仅在 R127/R128 文档，撞车 0 让路下未拍板 = 永久失效
  - agency 元规则：拍板顺序（#17）/ 跨仓 BCP（#18）= **元规则未拍板，单仓派单会反复撞车 0**
- **证据**：R121/R122 拍板包已 7 天未决 = M2 红线完全失效实证
- **本质**：把"拍板"当成 owner 私人动作，没当成流水线闸门。把"7 天"当成建议期限，没当成 SLA
- **根除**：
  - 7 天红线落地：`scripts/check-decision-deadline.sh` + cron 每日 02:00 + 看板标红 🔴 + 升级通知（不是 owner，是 PM）

  - 红线豁免必须 PM 书面授权（写进决策日志），不可口头

### 元根因 M-Root-3：**撞车 0 严守无退出机制（人治红线无机治门禁）**

- **4 智能体一致结论**：

## 六、撞车 0 退出触发器（T1-T10）

> 撞车 0 是**默认红线**，退出必须**触发器驱动 + PM 授权 + 可回滚**，不允许"我先做了再说"。

### 6.1 触发器矩阵（来自 pm §四.2）

| Trigger | Condition | Action | Rollback |
|---|---|---|---|
| **T1 兄弟会话阻塞 P0** | IPD 真活 E2E 全卡 & 兄弟会话非工作态超 30 min | PM 拍板错峰启动 IPD 后端（占用端口 16049 备用）| 兄弟会话恢复后 kill -9 PID + 端口归还 |
| **T2 拍板超 SLA** | 任何拍板超 7 天未决 | 看板标红 🔴 + 自动派单 worktree + 标 `PM-OWNED` | 派单完成 → 卡拖入"已完成" → 摘红 |
| **T3 wt 堆积超 5** | `git worktree list \| wc -l` > 5 | 暂停新派单 + PM 召集 wt 评审 | 清理 wt → 计数 ≤ 3 → 恢复派单 |
| **T4 Sandbox 后台 java 回收** | `is_background=false` 启 java → 进程消失 | 必须 `is_background=true` 终端 + `exec java ...` 前台化 | 不适用（一次性纠正）|
| **T5 后端端口被占用** | 16039 端口被非兄弟会话占用 | 申请备用端口 16049 + 写 `.lock/port-16049.lock` | 释放后端口锁自动失效 |
| **T6 DB 锁表超 30 min** | `SHOW PROCESSLIST` 有 ipd_dev 锁等待 > 30 min | SRE 介入 `KILL` + 锁源记录到决策日志 | 不适用（事后记录）|
| **T7 拍板项互相冲突** | 同一 BCP 内多拍板方向矛盾 | PM 召集 owner 二次拍板 + 暂停该 BCP | 不适用 |
| **T8 跨仓 BCP 缺项** | BCP 模板 4 项清单任一缺 | 拒绝派单 + 看板卡打回"待补" | 补齐后重新派单 |
| **T9 兄弟会话主动让路** | 兄弟会话声明"本会话暂停 N 分钟" | IPD 会话可借机拍板 #1（启后端）| 时间到立刻归还 |
| **T10 P0 安全漏洞** | CVE / 鉴权绕过 / SQL 注入等 | 立即插当前波次 + 暂停所有其他派单 + 走 T1-T9 优先 | 漏洞修复后恢复 |

### 6.2 退出机制元规则

1. **任何退出必须 PM 拍板**（写决策日志），不允许 AI 智能体自行决定
2. **退出动作必须可回滚**（kill PID / 释放端口 / 删 wt），不留副作用
3. **退出超时**（如兄弟会话恢复超时）→ 升级到 owner 邮件 + 看板 🔴
4. **退出累计**（同一会话周内退出超 3 次）→ 强制降级（暂停所有 P0 派单 24h 反思）

### 6.3 撞车 0 让路下"必查 5 件套"（机制化）

```
preflight-check.sh 必跑 5 项：
1. 跨仓 cd 绝对路径（防 cwd 漂）
2. 端口/PID 锁（防撞号）
3. git fetch + log -5（防 commit 撞号）
4. 看板 fresh 拉 API（防推算失真）
5. 拍板状态校验（防越权派单）
```

5 项全过 = 允许派单；任一失败 = exit 1 拒绝。
