## 〇、结论先说（人话版）

把 IPD 全部 74 个页面和 161 个业务服务的"AI 协助"补齐**不是一次性大爆炸**，而是分四层渐进推进，每层都闭环收口、不阻塞业务：

1. **Layer 0（基础夯实，3-5 人天）**：把现有的 AI 文档助手、AI 副驾、RAG 真正打通；这一层做的就是当前打开文档里的阶段 1-3 + 把 IpdSseController 的 SSE 真接到 AI 副驾流式输出。
2. **Layer 1（AI 模板扩展，5 人天）**：把"AI 文档助手"从"只能生成全文文档"扩成"能按 docType 生成对应模板"——立项书、需求、招标、变更、Gate、KPI 月报、Handover 移交纪要、复盘报告全部走同一套入口。
3. **Layer 2（每页 AI 入口，10 人天）**：给 Project / Demand / Bid / Change / Review / KPI / BonusPool / Handover / Timeline / Report / Audit / Workbench 等关键页面在右下角加"AI 帮写 / AI 总结 / AI 建议"按钮，统一一个后端 AI Suggestion Service，按页面上下文拼 prompt，自动调用、不污染业务表。
4. **Layer 3（Agent 网关，15+ 人天）**：从 Copilot 升级为 Agent —— 真流式输出 + 多步推理 + 工具调用 + 任务打断恢复，做"项目健康度检查 Agent / 月度绩效自动 Agent / 风险预警 Agent"。

每层收口都走"代码 + 测试 + 真库验证 + 文档同步 + 看板翻卡"五件套，不允许假绿、不允许未验证翻卡。

## 六、Layer 3 — Agent 网关（Copilot → Agent 演进）

> 范围：从"AI 回答用户问题"升级为"AI 主动拆解任务、多步执行、工具调用、任务可打断恢复"。本层风险高，需 owner 拍板 + 走单独 worktree。

### 6.1 核心改动

- **新增** `AiAgentGateway` + `AiAgentTask` + `AiAgentTool` 抽象
  - Langchain4j Agent / Tool 抽象层
  - 工具白名单：所有 IPD Controller 方法需先在 `AiAgentToolRegistry` 登记才能被 AI 调用
  - 写操作工具必须标注 `requiresApproval=true`，调用前生成"建议执行计划"由用户手动批准
- **新增** `AiAgentTaskService`：
  - 任务持久化（`ai_agent_tasks` 表）
  - 上下文多轮持久化（`ai_agent_messages` 表）
  - 断点恢复（用户离线后再上线能续）
- **新增** `AiAgentSseController`：Agent 任务流式推送进度
  - 事件类型：`task_started` / `thinking` / `tool_call` / `tool_result` / `requires_approval` / `done` / `failed`
- **前端**：`AiAgentConsole` — 让用户像看 IDE 终端一样看 Agent 工作
  - 显示"思考"、工具调用、结果
  - "批准 / 拒绝 / 改写"每个工具调用

### 6.2 三个 Agent 实例

1. **项目健康度检查 Agent**（PM 触发）
   - 输入：projectId
   - 工具：拉项目摘要 / 拉待办 / 拉风险预警 / 拉 KPI / 拉变更历史
   - 输出：健康度评分 + 高风险点 3 条 + 建议 3 条
   - 风险：纯读，不写，owner 可放行

2. **月度绩效 Agent**（超管触发）
   - 输入：period（YYYYMM）
   - 工具：拉 KPI 原始 / 拉贡献度 / 拉奖金池 / 拉考勤
   - 输出：每月每位成员评分 + 奖金分配建议
   - 风险：建议性，写奖金池必须二次人审

3. **变更影响分析 Agent**（PM 触发）
   - 输入：changeId
   - 工具：拉变更单 / 拉受影响需求 / 拉项目计划 / 拉 KPI 关联
   - 输出：影响面评分 + 风险点 + 是否推荐批准
   - 风险：建议性

### 6.3 工作量与依赖

- 15-20 人天
- 依赖：Layer 0（真活 + SSE）+ Layer 2（统一 Suggestion Service）已完成

## 八、跨层关注点（每层都要做对的事）

### 8.1 审计（每层都要遵守 BR-AI-04 + 三件套）

- **现状**：`audit_logs` 表已有 `aiAssisted/aiModel/aiRole` 三件套，每条 AI 调用必带
- **必须新增的 action 类型**：
  - `AI_SUGGEST`（Layer 2 用，scene + entityRef 落 audit）
  - `AI_AGENT_TASK_STARTED/RUNNING/DONE/FAILED/APPROVED/REJECTED`（Layer 3 用）
  - `AI_STREAM_CHUNK`（避免每段都落审计，按"完成时整 session 落一行"）
- **绝对禁止**：prompt 原文 / 模型响应原文 / API key 入审计

### 8.2 越权防线（每层都要遵守 BR-AI-05）

- AI 写业务表必须通过"建议 + 人审"双层
- AI 读业务表必须按 actor.role() + projectMember 校验
- AI 不能跨项目读（即使是建议生成）

### 8.3 成本（每层都要遵守 BR-AI-01）

- 月度 token 预算（已实现 budgetTokens）
- Per-actor 每小时限额（需新增）
- SSE 流式可截断（用户点"停止"立即断）

### 8.4 评测（必须建立，每层交付都要跑）

- **新文件**：`qa/ai-eval/` 目录 + 评测脚本（基于真实对话/草稿样本）
- **指标**：业务采纳率（建议被点"采纳"的比例）/ 失败率 / 用户满意度（前端埋点）
- **badcase 自动归档**：每次评测不达标的对话落入 `ai_badcases` 表，供 fine-tune 用

### 8.5 安全合规（每层都要做）

- SSRF 黑名单（已实现，**不能绕过**）
- Prompt 注入防御：所有外部输入（用户消息 / 文档片段 / 邮件导入）必须 sanitize
- 标识：所有 AI 生成内容在 UI 上加"AI 生成"角标
- 输入审计：所有 prompt 进 DB 留指纹（已实现 PromptLenBucket）
