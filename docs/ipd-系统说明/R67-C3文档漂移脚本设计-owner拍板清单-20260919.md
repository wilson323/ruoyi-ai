## 三、C3 文档漂移检测脚本设计(撞号透明 + R50 剩余 1 项)

### 3.1 脚本目的

`scripts/check-doc-drift.sh` 用于检测 IPD 项目**三事实源**是否一致:

1. `docs/ipd-系统说明/log.md`(SSOT 项目日志)
2. `docs/ipd-系统说明/开发计划-看板镜像.md`(SSOT 看板镜像)
3. `kanban HTTP API /api/tasks`(看板实时数据)

**根因**(兄弟会话 R49 §三 根因 3):三事实源无强制对账 → 治理轮越长越长 → 失真风险累积。

### 3.2 设计要点(撞号透明 + docs only)

#### 3.2.1 三层对账架构

```text
Layer 1:总数核对(total / done / todo / inprogress / inreview)
   ├─ kanban total == mirror total
   └─ log.md R{N} 段 hash == git log --oneline

Layer 2:子卡状态核对(汇总卡 vs 子卡)
   ├─ 汇总卡 status="done" → 所有子卡 status="done"
   └─ 汇总卡 status="todo" 但标题写"全 done" → 卡面失真报警

Layer 3:commit hash 一致性
   ├─ log.md 提到的 commit hash 必须在 git log 真实存在
   └─ 镜像提到的 UUID 必须在 kanban 真实存在
```

#### 3.2.2 自证能红方法(撞号透明 + 门禁上岗前必跑)

按 memory **learned_skill_experience** "门禁自检方法论:门禁上岗前必须自证能红(三层哨兵+负向验证)":

```bash
# 哨兵 1:跑一个真实失真场景,确认脚本能红
$ ./check-doc-drift.sh --test-drift "fake-commit-hash"
🚨 Layer 3 FAIL: fake-commit-hash 在 git log 不存在

# 哨兵 2:跑一个真实汇总卡失真场景
$ ./check-doc-drift.sh --test-summary-mismatch "b9ab3425"
🚨 Layer 2 FAIL: P4-4 title="[子卡已全 done]" 但 P4-4.1 status="inprogress"

# 哨兵 3:跑一个总数失真场景
$ ./check-doc-drift.sh --test-count-drift 9999
🚨 Layer 1 FAIL: 镜像 total=???, kanban total=466, 差 9533
```

#### 3.2.3 输出格式

```
✅ Layer 1 通过:total 一致 (kanban=466 / mirror=466)
✅ Layer 2 通过:无汇总卡失真
🚨 Layer 3 FAIL:commit 157df0d6 不在 log.md R50 段
   → 修复:append log.md R50 段
```
