# IPD 生产部署 Runbook（2026-09-09，P0-7 迁移机制交付）

一句话：本仓无 Flyway/Liquibase，建库靠本文档的 runbook 人工执行一次 + 后续增量走
`docs/script/sql/update/` 顺序 apply + `p1-ddl-apply-check.py` 校验（"SQL 已 commit ≠ 约束已生效"）。已知滞后：主 SQL `docs/script/sql/ruoyi-ai.sql` 与本 Runbook 引用的
`docs/script/sql/schema/schema-snapshot-2026-09-09.sql` 均尚未回写 Part A 增量，回写前所有全量初始化通道必须补跑
`docs/script/sql/update/kb-partA-ddl-draft-20260928.sql`。

## 一、全新库初始化（首次部署）

1. **建库建账号**（DBA 执行，账号双账号分离原则）：
   ```sql
   CREATE DATABASE ipd DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   CREATE USER 'ipd_app'@'%' IDENTIFIED BY '<运行时账号-只给 CRUD>';
   -- 迁移/初始化用 DBA 账号执行 DDL，ipd_app 不给 DDL 权限
   ```
2. **全量 schema 快照**（从当前开发库导出，不含数据；快照随版本发布物走）：
   ```bash
   mysqldump --no-data --skip-lock-tables \
     --default-character-set=utf8mb4 ipd_dev > schema-snapshot-<日期>.sql
   # 在目标库导入后，按 runbook 内 GRANT 清单补表级授权（模板见
   # docs/script/sql/update/2026-09-09-ipd-grant-c-batch-4-dml.sql，逐表 CRUD 白名单）
   ```
   **强制后置动作**：若导入的是仓内归档快照 `docs/script/sql/schema/schema-snapshot-2026-09-09.sql`
   （Part A 之前的结构态），导入后必须紧接着执行
   `docs/script/sql/update/kb-partA-ddl-draft-20260928.sql`（12 列 / 8 索引），否则库会静默缺列且
   不报错；随后按第 4 步 apply-check 复核才算完成。
3. **种子数据**（顺序执行，全部在 `docs/script/sql/update/` 找同日文件）：
   - system_configs 54 键参数种子（P0-3，涉钱 6 开关 + 6 档阶梯 JSON）
   - 69 动作 Seed（P1-3）、Gate 要素定义种子（P1-6）
   - cert_templates / sop_templates / 贡献度五维权重等业务种子
4. **校验**：跑 `python3 docs/ipd-系统说明/验收/p1-ddl-apply-check.py --dbs <库名>`
   全 FULL/APPLIED 才算初始化完成；`select @@port` 确认连的是目标库。

## 二、增量变更流程（每次发布）

1. 开发者在 `docs/script/sql/update/YYYY-MM-DD-<主题>.sql` 写 DDL（幂等：CREATE TABLE IF NOT EXISTS
   + information_schema 列守卫，参照 `2026-09-08-ipd-c-batch-4-tables-draft.sql` 头部勘误注释）；
2. PR 内必须同步：实体类 + `application.yml` 的 `tenant.excludes` 登记（TenantExcludesConsistencyTest
   守卫会扫 DDL 文件强制）+ 表级 GRANT 登记件（漏 GRANT = 写链 UPDATE 静默 500，教训已实证）；
3. 发布时 DBA 按文件日期顺序 apply 到生产库 → 跑 apply-check 校验 FULL。

## 三、应用发布

1. 镜像构建：`docker build -t ipd-backend:<git-sha> .`（多阶段，构建参数见 Dockerfile 头注）；
2. 前端镜像在 ruoyi-ipd-web 仓根目录构建：`docker build -f apps/web-antd/Dockerfile -t ipd-frontend:<git-sha> .`
   （nginx 托管，容器内 5666；`/api/v1` 保留前缀直转、其余 `/api` 去前缀，与 vite 代理行为一致）；
3. 编排：`cp .env.example .env` 填真实值 → `docker compose up -d`；
   - 环境变量清单见 `.env.example`；DB URL/账号/密码、JWT secret、原模型加密主密钥、独立监控账号/密码、AI 查表只读账号均须填写。编排渲染遇缺值即失败，真实值禁入镜像与版本库。
   - **镜像标签须显式指定（2026-10-03 owner 拍板，修「手册构 `<git-sha>`、编排引用 `latest`、本机 latest 不存在 → up -d 必失败」的不一致）**：
     编排的镜像行已参数化，`.env` 里加 `IPD_BACKEND_IMAGE=ipd-backend:<git-sha>` 与
     `IPD_FRONTEND_IMAGE=ipd-frontend:<git-sha>`（即第 1、2 步构建时的标签）再 `up -d`。
     不设则回落 `latest`——仅限本机快速联调，生产禁用：`latest` 无法回答「跑的是哪次构建」。
     `upload-init` 与 backend 共用 `IPD_BACKEND_IMAGE`，天然同标签。
   - 本IPD根镜像与编排均显式设 `SERVER_PORT=16039`；`ruoyi-admin/Dockerfile` 是独立FFmpeg变体，不是本编排使用的根镜像。
   - 健康检查使用镜像内curl、容器本地 `/actuator/health` 和原Basic认证。监控凭据走 `IPD_MONITOR_USERNAME` / `IPD_MONITOR_PASSWORD`，映射到原 `MONITOR_USERNAME` / `MONITOR_PASSWORD`；不关闭鉴权、不把401视为健康。
     mail / ES 两个自动装配的健康检查已在编排里显式关闭（生产未部署这两项服务，探针连占位地址恒 DOWN，
     实测 `/actuator/health` 恒 503）；将来真部署后删除 compose 里对应两行即恢复探针。
   - 2026-10-03模板检查仅验证渲染、端口及缺变量失败；镜像构建和目标环境健康验收仍须实际完成。
4. **首次启动后必做**：admin 改密（首登强制改密链路 P0-10.2）；验证 demo.enabled=false
   （父 application.yml 默认已关，勿在 prod 覆盖为 true）。
5. **AI 查表只读账号（首次部署必做，2026-10-03 owner 拍板「补 agent 数据源 + 只读」）**：
   `@DS("agent")` 的 AI 查表路径（查表结构 / 查全表 / 执行 SQL）在生产走独立数据源，
   账号必须只读。在目标 MySQL 执行（密码替换为强口令，与 `.env` 的 `IPD_DB_AGENT_PASSWORD` 一致）：
   ```sql
   CREATE USER IF NOT EXISTS 'ipd_ro'@'%' IDENTIFIED BY '<强口令>';
   GRANT SELECT ON ipd.* TO 'ipd_ro'@'%';
   FLUSH PRIVILEGES;
   ```
   `.env` 填 `IPD_DB_AGENT_USER=ipd_ro` + `IPD_DB_AGENT_PASSWORD=<同上口令>`；
   `IPD_DB_AGENT_URL` 可不填（默认复用 `IPD_DB_URL` 指向的库）。
   该账号缺值时编排渲染即失败——宁可部署不下去，也不让 AI 拿可写账号直查生产库。

## 四、备份与恢复（QA-06 前置）

- 每日 `mysqldump --single-transaction ipd` 全量 + binlog 增量；保留 ≥30 天；
- 恢复演练一次通过后才允许录入真实绩效奖金数据（审计链 audit_logs 一旦有数据，
  恢复后必须跑审计 verify chain=OK 再对外服务）。

## 五、回滚

- 应用回滚：切回上一镜像 tag（DB 增量 DDL 原则向后兼容一版：只加列/表，不删不改）；
- 数据回滚：恢复最近备份 + binlog 重放到故障点前，恢复后必跑审计链 verify。
