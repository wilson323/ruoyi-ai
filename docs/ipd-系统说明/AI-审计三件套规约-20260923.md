## 一、规则定义

凡 IPD 后端调用外部 LLM(OpenAI 兼容 / 自建网关)的入口,产生的业务事件**必须**落 `audit_logs` 表,带"三件套"标识:

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `aiAssisted` | boolean | **是** | 是否本轮有 AI 参与生成;Copilot 关键字命中路径标 true(语义诚实:本轮 AI 不真调,但表明"系统具备 AI 能力") |
| `aiModel` | string | **是** | 实际调用模型名(如 `gpt-4o-mini` / `qwen3-max`);**关键规则**:Copilot intent_match 路径填 `"intent_match"`(白名单外的占位,门禁知道非真模型) |
| `aiRole` | enum string | **是** | AI 在本轮扮演的角色,**必须**是以下七值之一: |

### aiRole 白名单(7 值)

| 值 | 含义 | 使用场景 |
|---|---|---|
| `draft` | AI 起草文档 / 内容 | `AiGenerationService.generate`、`AiDocumentService.createGenerated` |
| `suggestion` | AI 给业务建议(不写业务表) | 新增 `AiSuggestionService`(Layer 2 引入) |
| `summary` | AI 总结文档 / 长文本 | Layer 2 `scene=*.summarize` |
| `copilot_answer` | AI 副驾在副驾对话里直接答 | `AiCopilotService.chitchatPath` |
| `copilot_intent` | AI 副驾命中意图关键字、不调 AI | `AiCopilotService.tasksPath` / `advancePath`(填 aiModel=`intent_match` 区分) |
| `tool_call` | Agent 工具调用 | Layer 3 Agent 网关 |
| `streaming` | SSE 流式输出的完成事件(避免每段都落审计) | Layer 0 L0-4 + Layer 3 AgentSSE |

### 不允许的取值

- `null` / `""` —— 门禁直接拦
- 任意不在 7 值白名单内的字符串 —— 门禁直接拦
- `gpt-4` 这种泛指(没指明 mini / nano / 32k) —— 警告但不拦(后续收紧)

## 二、每条 AI 路径的 audit 字段映射

### 2.1 `AiGenerationService.generate`(AI 文档助手)

| 落审计 action | aiAssisted | aiModel | aiRole | 必落字段 |
|---|---|---|---|---|
| **成功** `AI_GENERATE` | `true` | `config.getModelName()` | `draft` | `projectId`、`docType`、`promptLen`、`tokenPrompt`、`tokenCompletion`、`latencyMs`、`contextHits`、`contextChars`、`status` |
| **失败** `AI_GENERATE_FAILED` | `true` | `config.getModelName()` | `draft` | `projectId`、`promptLen`、`errorCode`、`latencyMs`、`contextHits`、`contextChars` |

**强约束**:`prompt` 原文**绝不**进 audit;只记长度 (`promptLen`);`tokenPrompt/tokenCompletion` 是 LLM 自身用量,允许入审计(已是事实,非隐私)。

### 2.2 `AiCopilotService`(AI 副驾)

| 路径 | aiAssisted | aiModel | aiRole | 必落字段 |
|---|---|---|---|---|
| `tasksPath`(命中"TASKS"关键字) | `true` | `"intent_match"` | `copilot_intent` | `projectId`、`status=ok \| FAIL:...`、`latencyMs`、`promptLen` |
| `advancePath`(命中"ADVANCE"关键字) | `true` | `"intent_match"` | `copilot_intent` | 同上 |
| `chitchatPath` **成功**(真调 AI) | `true` | `config.getModelName()` | `copilot_answer` | `projectId`、`intent`、`tokenPrompt`、`tokenCompletion`、`latencyMs`、`status=ok`、`promptLen` |
| `chitchatPath` **失败**(无 AI 配置) | `true` | `"intent_match"` | `copilot_intent` | `status=FAIL:AI_NOT_CONFIGURED`、`latencyMs=0` |
| `chitchatPath` **失败**(AI 调用失败) | `true` | `config.getModelName()` | `copilot_answer` | `status=FAIL:ERROR_CODE`、`tokenPrompt=0`、`latencyMs` |

**代码锚点**:`AiCopilotService.java:133`(tasks)、`AiCopilotService.java:157`(advance)、`AiCopilotService.java:170-176`(AI 未配置)、`AiCopilotService.java:190-197`(成功/失败 chitchat)。
**强约束**:`req.message()` 原文不入审计,只记 `promptLen`(=input)。

### 2.3 `AiDocumentService` 状态流转

| 状态流转 | action 命名 | aiAssisted | aiRole | 备注 |
|---|---|---|---|---|
| GENERATED → REVIEWED | `AI_DOC_REVIEWED` | `false` | `null`(不允许填) | 人工审核,无 AI |
| GENERATED → REJECTED(强制走 review 流后才可 reject) | `AI_DOC_REJECTED` | `false` | `null` | 人工拒绝,无 AI |
| REVIEWED → ARCHIVED | `AI_DOC_ARCHIVED` | `false` | `null` | 人工归档,无 AI |
| **AI 自动归档**(Layer 3 引入) | `AI_DOC_AUTO_ARCHIVED` | `true` | `tool_call` | Agent 网关在人工审批后写入归档 |

**代码锚点**:`AiDocumentService.java:87-104`(auditTransition)
**强约束**:三个 `AI_DOC_*` 流转**不允许**填 aiAssisted=true(因为这是人工操作);仅 Layer 3 Agent 网关的自动归档允许 aiAssisted=true。

## 四、aiRole 落审计的强制规则

### 4.1 写入侧

- Service 落 `auditLogService.append(...)` 时,**强校验**:`aiRole` 必须在 7 值白名单内(`AuditLogService.append` 入口前用 `requireArg` 卡;或前置 `AiAuditHelper.requireValidRole(role)`)
- `aiModel` 必非空(`null`/`""` 拒); Copilot intent_match 路径填 `"intent_match"` 是允许的特殊值
- `aiAssisted=true` 但 `aiRole=null` —— 禁止

### 4.2 读取/查询侧

- 任何 `audit_logs` 查询 SQL 必须带 `WHERE entity_type='AI_DOCUMENT' OR action LIKE 'AI_%'` 避免业务表与审计表混淆
- 看板/报告 SQL 显式过滤 `aiRole IN ('draft','summary','suggestion','copilot_answer','copilot_intent')` 排除人工状态流转
- SSE 流式完成事件 `aiRole='streaming'` 单 session 一行,不允许逐 chunk 落审计

### 4.3 校验实现位置

- **Service 入口校验**:`org.ruoyi.ipd.common.AiAuditHelper.requireValid(action, aiAssisted, aiModel, aiRole)` (待新建)
- **DAO 层 catch**:任何 audit_logs INSERT 违反 `chk_ai_role` 约束(DB 层)抛 `IpdBusinessException(AUDIT_INVALID)`
- **DB 层 chk 约束**(待 owner apply):`ALTER TABLE audit_logs ADD CONSTRAINT chk_ai_role CHECK (ai_role IS NULL OR ai_role IN ('draft','suggestion','summary','copilot_answer','copilot_intent','tool_call','streaming'))`

## 五、对齐外部合规要求(欧盟 AI 法案 / 等保 / CrowdStrike Falcon Shield 风格)

参考外部调研:
- 欧盟 AI 法案 要求 AI 输出必须带 `generated_by_ai: true` + `model_version` + `confidence` + `disclaimer`(API 响应层)
- CrowdStrike Falcon Shield ChatGPT Enterprise 集成要求"deeper audit logging + continuous activity monitoring"
- UiPath governance 平台要求 "tamper-evident audit trail"(防最高权限账号篡改)
- 微软 Copilot Cowork 要求 "内置预算上限、支出警报、使用量报告"(运行时控制台)

### 5.1 IPD 三件套与外部对照

| 外部要求 | IPD 对应 | 是否满足 |
|---|---|---|
| `generated_by_ai` | `aiAssisted` | ✅ |
| `model_version` | `aiModel`(精确到 mini/nano) | ✅(已要求非空) |
| `confidence` | 暂无(可选:加 `confidence` 字段从 LLM 输出解析) | ❌ Layer 3 引入 |
| `disclaimer`(系统层提示) | 前端 UI "AI 生成"角标 | ✅ 已实现 |
| `human_approval_required` | 不需要(我们走"AI 仅建议 + 人审决定"模式) | ✅ 天然满足 |
| tamper-evident | `audit_logs.hash_chain`(DEF-9,已知断裂待修) | ⚠️ 多实例断裂待补 |

### 5.2 IPD 未补齐的合规项

- ❌ Layer 3 引入 `confidence` 字段(让 LLM 输出含置信度)
- ⚠️ `audit_logs.hash_chain` 多实例断裂(P0-12,待 owner 拍板)
- ❌ prompt 注入防御:外部用户输入(用户消息 / 文档片段)未做 sanitize,Layer 3 Agent 必补
- ✅ apiKey 不入审计(已有 PromptLenBucket + SHA 短指纹)
