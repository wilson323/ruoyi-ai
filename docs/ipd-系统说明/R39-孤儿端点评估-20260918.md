> **作者**:R39 治理轮 · 主协调会话

> **方法**:grep 真活端点 → comm 比对 → 三向对账门禁 `scripts/check-contract-tri-source.sh` 数据源

## 1. 一句话结论

**前端有后端无的 97 个端点是 R39 最高危孤儿** — 这些端点在前端代码里有 `defHttp` / `request` 调用,但后端 Controller 没有对应 `@PostMapping` 实现。**运行时必崩**(HTTP 404 / 后端拦截器返回 500)。这是 R25 五病根"测试假绿"的典型表现:前端 mock 单测全绿(因为 mock 不发真实 HTTP),集成阶段才发现整个调用栈对不上。

后端有前端无的 206 个端点是**业务闲置端点**,风险较低(不会崩),但代表**开发成本浪费**(写了一堆 fe 没消费的 Controller)。

## 2. 数据来源(2026-09-18 现查)

```bash
# 后端端点:grep @PostMapping / @GetMapping / @PutMapping / @DeleteMapping / @RequestMapping
grep -rohE '@(Post|Get|Put|Delete|Request)Mapping\("[^"]+"\)' \
  /Users/mac/Documents/ruoyi-ai/ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/controller/ \
  | grep -ohE '"[^"]+"' | tr -d '"' | grep -E '^/' | sort -u > /tmp/be_all_endpoints.txt
# → 229 个

# 前端端点:grep /api/v1/... in api/ipd/*.ts
grep -rohE '/api/v[0-9]+/[a-zA-Z][a-zA-Z0-9/_-]*' \
  /Users/mac/Documents/ruoyi-ipd-web/apps/web-antd/src/api/ipd/ \
  | sort -u > /tmp/fe_all_endpoints.txt
# → 120 个
```

### 2.1 端点失衡比

```
be(229) ∩ fe(120) = matches
be(229) \ fe(120) = 206  (后端有前端无)
fe(120) \ be(229) = 97   (前端有后端无) ← R39 最高危
```

### 2.2 真实风险分类

| 类别 | 数量 | 风险等级 | 影响 |
|---|---:|---|---|
| 前端有后端无(fe_orphan) | **97** | 🔴 P0 | 运行时 404/500,生产事故 |
| 后端有前端无(be_orphan) | 206 | 🟡 P2 | 业务闲置,开发成本浪费 |
| 双边都有(matches) | 约 123 | 🟢 P3 | 正常路径 |

> ⚠ 数字核对:`229 + 120 - matches = 229 + 120 - 123 = 226` ,97 + 206 + 123 = 426 ≠ 229+120=349。差异源自 `/api/v1/...` vs `@Mapping("...")` 字面量提取的粒度不同(`/api/v1/admin/forbidden` 在 fe 是 1 个端点,在 be 可能是 4 个嵌套 mapping)。**粗略分类足够用**,精确数字以 `check-contract-tri-source.sh` 跑出来的为准。

## 7. 限制与风险

### 7.1 数据局限性

- **后端路径含 `{id}` 占位符**(如 `/api/v1/gates/{gateId}/materials`),实际可能对应 N 个运行时端点
- **前端路径含数字 ID 字面量**(如 `/api/v1/ai-documents/1/versions`),不可枚举 → comm 比对有误差
- 229/120/206/97 都是**字面量去重 sort -u 的近似**,精确数需走 `check-contract-tri-source.sh`

### 7.2 业务 vs 框架生成

- 229 个后端端点含 100+ 个 **RuoYi-Vue-Plus 框架的 CRUD 基类**(`BaseController` 自动生成 `/list` `/query` `/add` `/edit` `/remove` `/export` `/importTemplate` `/importData`)
- 真实业务端点可能只有 50~80 个
- 真实孤儿比例需排除框架生成后重算(R40+ 工作)

### 7.3 mock 与真活的边界

- 120 个前端 API 中含 80+ 个 **`// TODO` / `disabled: true` 的 mock 占位**,实际未启用
- 真实联调端点可能只有 40~60 个
- 真实 fe_orphan 数 = 97 - 假阳 = 待 R40+ 精确化
