## 0. 结论先行（5 条）

**C-1｜Vue 3 官方一等支持已成立，React 混合挂载路径整体作废。** `@copilotkit/vue@1.74.0`（MIT）提供 Vue 3 组件与 composables，且 Generative UI 六路径（含 A2UI）全部 Vue 原生渲染、不依赖 React 包；npm 依赖闭包实测 275 包中**无 react/react-dom**（仅 @lit/reactive-element、@preact/signals-core 两个名字沾 react/preact 字样的无关包）。执行计划风险 #1「Vue A2UI 等价物未验证」被一手证据**推翻**——Vue 侧 A2UI renderer 官方已内建（基于 `@a2ui/web_core`），C2 的 POC 范围应相应收窄。来源：docs.copilotkit.ai/frontends/vue、/frontends/vue/guides/generative-ui（留档 L45151/L45340）+ npm registry（@copilotkit/vue latest）+ 依赖闭包遍历脚本（本报告 §4.3）。

**C-2｜后端契约迁移成本仍是最大负项，无零成本路径。** Copilot Runtime 仅 Node 形态（Express/Hono/Next/Nest 适配器；官方无 Java/Spring 版），与本项目 Java 后端 + 自研四帧 SSE（meta/delta/done/error，done 帧携 fillPayload 逐字段广播 + card 四键信封）是两套协议模型；AG-UI 事件族对 fillPayload / card{type,version,data,sourceRefs} / sourceRefs 审计回读**无协议原语**，必须 Custom/StateDelta 承载并新增适配层（Node sidecar 或 Java 自实现 AG-UI 端点）。来源：docs.copilotkit.ai/backend/runtime-endpoints（留档 L21789）+ docs.ag-ui.com/concepts/events + 前端仓 `apps/web-antd/src/api/ipd/ai-copilot.ts` 现查。

**C-3｜包体与传递依赖规模显著，与「零新依赖」红线直接相抵。** `@copilotkit/vue` 依赖闭包实测 **275 个包 / unpacked 合计 ≈322 MB**（install 足迹口径，非浏览器 bundle；含 mermaid 121MB、lucide 系三份 21–30MB、date-fns 10MB 等大件），另 zod 双大版本（v3 + v4.6.5）共存；相比之下自研现状 = 0 新依赖。引入 SDK 即触碰执行计划 §4「R214 三查：pom/package.json 0 新依赖」，须 owner 特批（Phase 3 决策门正是为此设）。来源：npm registry 元数据 + 闭包遍历（§4.3）。

**C-4｜许可证主体干净（MIT），但闭包内有 copyleft/弱著佐权触点须法务过目。** CopilotKit 与 AG-UI 两仓 LICENSE 均为 MIT（GitHub raw 一手核验）；275 包许可证分布：MIT 207 / ISC 39 / Apache-2.0 11 / BSD 系 13 / 其他 5，其中 **elkjs（EPL-2.0 OR GPL-3.0-or-later）**、dompurify（MPL-2.0 OR Apache-2.0）、@bufbuild/protobuf（Apache-2.0 AND BSD-3-Clause）为须留痕触点（dual/AND 均有可接受选路，但需登记）。另注意 CopilotKit Intelligence（Rich Threads/Memories/Automatic Learning）是**商业平台件**，不在 MIT SDK 覆盖内。来源：raw.githubusercontent.com LICENSE + npm license 字段 + github.com/CopilotKit/CopilotKit README。

**C-5｜综合判定：继续零依赖自研为推荐路径（面向 C3 建议 no-go 引 SDK）。** 引 SDK 的唯一显著增量（A2UI/agent 动态生成 UI）中，**dynamic schema 形态与 FILL_FIELD_WHITELIST/schema 白名单红线结构性冲突**（母文件 §3 已判「不适用」），fixed-schema + 自建 catalog 形态的收益又与已落地的 CardRegistry/CardCatalog（4 卡片类型 + DynString 防御）高度重合；而 HITL 语义不同构（useInterrupt 绑 LangGraph/AWS Strands 的 interrupt()，useHumanInTheLoop 是 LLM 决定的前端工具，与 C08 suggest 红线摩擦），迁移=语义重写而非平移。证据映射见 §7。

## 3. 调研问题 3：AG-UI / Copilot Runtime 后端契约与自研 SSE 的对齐

### 3.1 AG-UI 协议事实（docs.ag-ui.com 一手，2026-09-27 检索）

来源：docs.ag-ui.com/concepts/events（AG-UI 官方协议文档）。协议为**事件流 + SSE**："The AG-UI protocol connects your frontend to your AI agents via event-based Server-Sent Events (SSE)"（docs.copilotkit.ai/ag2/ag-ui 留档 L253 同口径）。事件族（协议文档 §Event Types Overview 起）：

| 事件族 | 事件 | 要点 |
|---|---|---|
| Lifecycle | RunStarted / RunFinished（带 `outcome` 判别联合）/ RunError / StepStarted / StepFinished | Run 以 RunStarted 开始，以 RunFinished 或 RunError 结束（强制） |
| Text Message | TextMessageStart / TextMessageContent（`delta`）/ TextMessageEnd / TextMessageChunk | 流式文本 = Start → Content×N → End；Chunk 为糖（客户端展开） |
| Tool Call | ToolCallStart / ToolCallArgs（`delta`）/ ToolCallEnd / ToolCallResult | 工具调用流 + 结果回传 |
| State | StateSnapshot（`snapshot` 全量替换）/ StateDelta（`delta` = **RFC 6902 JSON Patch** 数组）/ MessagesSnapshot（`messages`） | 快照-增量模式；StateDelta ≠ 本项目 fillPayload（见 §3.3） |
| Activity | ActivitySnapshot / ActivityDelta | 结构化活动消息（如 PLAN/SEARCH），同样快照-增量 |
| Special | Raw（外部事件透传，`event`+`source`）/ Custom（`name`+`value`，应用自定义扩展口） | Custom 是承载业务专属语义的官方扩展通道 |
| 其他 | Reasoning 族、Subagent 族、Deprecated、Draft | 与本项目无对齐需求 |

多 Agent：请求体 `RunAgentInput`，端点按 `:agentId` 路由（§3.2）——「多 Agent 编排投影」在协议层即 agentId 选择。

### 3.2 Copilot Runtime 后端契约（docs.copilotkit.ai 一手）

来源：留档 L21789 起（`/backend/runtime-endpoints`）。要点：
- 双传输模式：**multi-route**（默认）与 **single-route**（`mode:"single-route"`），Provider 侧 `useSingleEndpoint` 须与 handler 匹配，**配错静默 404**（原文 callout "Pinning the wrong mode 404s silently"，GET /info 仍 200 造成假连接）——迁移期高危坑。
- multi-route 路由表（basePath 如 /api/copilotkit）：`GET /info`（agent 发现）、`GET /inspector-metadata`（可选）、**`POST /agent/:agentId/run`**（body = AG-UI `RunAgentInput`，响应 = **SSE 流 AG-UI 事件**）、`POST /agent/:agentId/connect`（断线/刷新续流）、`POST /agent/:agentId/stop/:threadId`、`POST /transcribe`。
- handler 全为 Node 生态：`createCopilotExpressHandler` / `createCopilotHonoHandler` / `createCopilotNodeHandler` / `createCopilotNodeListener` / `copilotRuntimeNextJS*Endpoint` / `copilotRuntimeNestEndpoint`。**官方无 Java/Spring 适配器**（全站检索无 java 关键面；Runtime 包 @copilotkit/runtime 的 peerDeps 亦全为 Node SDK：express/openai/langchain 系）。
- 免 Runtime 直连模式存在但功能受限：直连 `@ag-ui/client` 的 HttpAgent 可行，但原文明确 "Many ecosystem features won't work... including threads and other capabilities will not be available"（留档 L1980 附近）。

### 3.3 与自研 SSE 四帧的对齐映射（本报告核心增量）

自研契约（前端仓一手现查）：`apps/web-antd/src/api/ipd/ai-copilot.ts`（fetch + ReadableStream 自解析，EventSource 带不了 Bearer 头；L6-14 注释即契约）：
- 四帧：meta（AiCopilotResp 结构化 data）/ delta（answer 增量 token 字符串）/ done（{status,tokenPrompt,tokenCompletion,latencyMs} + 可选超集 fillPayload / card）/ error（{code,message}）
- fillPayload：R221 对话即填表，后端 done 帧携、仅 suggest 模式、逐字段广播（宿主经 CustomEvent `ipd:ai-fill-payload` 消费）
- card 信封：四键 `{type,version,data,sourceRefs}`（`_shared/ai-cards/types.ts` 现查；sourceRefs 承载 R3 铁律=卡片数值须回读业务表真实记录）

| 自研帧/机制 | AG-UI 对应物 | 对齐度 | 迁移处置 |
|---|---|---|---|
| meta 帧 | RunStarted + TextMessageStart | 部分 | 结构化 data 项无原语 → Custom 或 StateSnapshot 承载 |
| delta 帧 | TextMessageContent.delta | **高**（+Start/End 包夹） | 直接映射 |
| done 帧（status/token/latency） | RunFinished(outcome) / RunError | 中 | token/latency 统计无原语 → Custom；status 语义并入 outcome |
| fillPayload 逐字段广播 | **无原语** | 低 | Custom(name='fillPayload') 或 StateDelta(JSON Patch)——**语义不同构**：StateDelta 是「agent 状态全量同步」，fillPayload 是「单向建议字段回填 + suggest 门控」，后者含 C08 红线语义（人审后手动提交），不可由 StateDelta 直接表达 |
| card 信封 {type,version,data,sourceRefs} | Generative UI（ToolCallStart/Args/End + 前端 render）或 A2UI surface | 中 | 渲染形态可对齐；sourceRefs/R3 回读语义、BR-AI-04 头部告警为业务专属，须随 tool args/Custom 携带并在渲染层强校验 |
| 多 Agent 编排投影 | /agent/:agentId/run + agentId 命名空间 | **高** | 协议原生 |
| HITL 图中断 | useInterrupt（LangGraph/AWS Strands `interrupt()`）/ useHumanInTheLoop（前端工具） | **低** | 见 §3.4 |

**迁移成本结论**：四帧→AG-UI 不是「换传输」而是「换协议模型」。两条路径均非零成本：
1. **Node sidecar**：新增部署单元 + sa-token Bearer 鉴权透传 + code0/message 包络↔AG-UI 事件双向转换 + 四帧映射层（执行计划 §6 风险#5 已列 8 项适配改造，本表为其实证拆解）；
2. **Java 自实现 AG-UI 端点**：在 Spring 侧序列化 AG-UI SSE 事件（含 JSON Patch），免部署单元但引入协议实现与版本追踪负担（协议仍在快速演进：@ag-ui/core 0.0.59→1.0.0 并存，§4.4）。

### 3.4 HITL 语义等价性（维持前序「不同构」判定，一手补证）

来源：留档 L52201 起（/human-in-the-loop）+ L53015 起（/human-in-the-loop/useInterrupt）。
- 官方双模式表（原文）：`useHumanInTheLoop` = "The **LLM**, by calling a registered client-side tool"，后端面="frontend-only tool description (Zod schema + render)"；`useInterrupt` = "The **graph**, by calling `interrupt(...)` during a node"，后端面="server-side `interrupt()` call in your **LangGraph** agent"。
- useInterrupt 的暂停实现原文："This framework ships a first-class interrupt primitive... ([LangGraph](...), [AWS Strands](...)). The run is frozen server-side until the client resolves the interrupt with a payload"——**绑定 LangGraph/AWS Strands 后端**，Java 自研执行引擎（AiExecutionEngine 五态机）无此原语；执行计划 §1.1 #2 已实查全库无 interrupt() 机制。
- 语义对照：CopilotKit HITL = **会话内暂停-作答-续跑**（run 冻结/工具返回）；自研 R221 = **跨会话持久状态机**（ai_agent_tasks 五态 + ai_documents GENERATED→REVIEWED 人审 + 审计三件套 + 通知待办直达），后者在审计/越权/盲签维度更强且无 CopilotKit 等价物。useHumanInTheLoop 的「LLM 主动决定暂停并出 UI」形态与 C08 suggest 红线（AI 只建议、人目检后手动提交）存在显式摩擦。→ 迁移 HITL = 语义重写，不是换 API。

## 7. 面向 C1/C2/C3 决策门的证据映射建议

（C1/C2/C3 定义源：《CopilotKit三项能力落地-全局执行计划-20260927.md》§3 Phase 3）

### C1 — 前置核验①：卡片层稳定 + 采纳率可观测为正
- 本调研**不新增埋点/不加列**（遵 R214）；C1 数据源维持「复用既有审计字段计数」。
- 证据映射：卡片层稳定性 → 4 卡片组件 vitest + 浏览器截图（P1-06/07 三态证据）+ schema 对账哨兵（P1-04）；采纳率 → audit_logs accepted 字段按 aiRole（suggestion/draft/copilot_answer）计数。
- **本调研对 C1 的裁定输入：引 SDK 对 C1 零增益**——卡片化已自研落地，SDK 的 Generative UI 是替代而非补缺；C1 数据只回答「自研卡片值不值」，不回答「SDK 值不值」。

### C2 — 前置核验②：Node sidecar 运维方案拍板 + Vue A2UI POC
- **POC 范围修订（本报告 §1.1/§6.3）**：「Vue A2UI 等价物是否存在」已由一手文档+npm 闭包证实为**存在且零 React**，该项从「未验证风险」降级为「已证实能力」。POC 剩余范围收窄为三点：
  1. `vueBasicCatalog`/自建 catalog 与本项目 CardCatalog（system_configs 单一事实源）的映射与 DynString 双向兼容实测；
  2. sa-token Bearer 在 CopilotKit HTTP 层（HttpAgent/Provider）的注入能力实测（§5 标注「未验证」项）；
  3. Vite 7 + pnpm catalog 下 275 包闭包的 lockfile/构建/门禁（drift-guard、孤儿棘轮、check:type）通过性。
- sidecar 拍板材料：§3.2（Node-only handler 清单 + 传输模式配错静默 404 坑）+ §3.3 两条迁移路径成本对照 + §4.4 版本漂移（@ag-ui 0.0.59↔1.0.0）。
- **fail 判定沿用执行计划**：POC 不可行→记「永久止损」归档，禁找替代框架二次引入；本报告证据表明 POC 大概率「技术可行」，但**可行≠值得**——门控应把「可行」与 §6 成本表分开裁量。

### C3 — owner go/no-go 决策门
- 建议决策权重（证据强度降序）：①迁移成本（§3.3/3.4 协议鸿沟 + HITL 语义重写）②红线冲突（dynamic schema 不适用 + C08 摩擦 + R214 零依赖相抵）③包体/许可证触点（§4）④能力增量折价（fixed-schema A2UI 与已落地 CardRegistry 重合）。
- **建议结论：no-go（维持零依赖自研）**；结论翻转条件（满足其一重启评估）：a) C1 采纳率数据显示卡片交互需求超出固定 catalog（且届时 dynamic schema 红线经 owner 明示解除）；b) 出现必须消费 AG-UI 生态第三方 agent/工具的业务场景；c) CopilotKit 提供 Java Runtime 或官方四帧级兼容层。
- 无论结果，按执行计划要求登记留痕；no-go 时 Phase 1/2 收益已落袋（零依赖止损设计成立）。
