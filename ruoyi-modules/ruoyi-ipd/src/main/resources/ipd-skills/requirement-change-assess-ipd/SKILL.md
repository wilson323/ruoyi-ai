# D06 需求变更评估与审批

## 目标

产出**需求变更单**材料。G2 后需求基线冻结；变更须双签否决路径。变更率计入需求准确率（目标累计 ≤15%，预警 12%——参数化，AI 只统计不裁定绩效）。

## 输入

变更原因、关联需求/PRD 版本、影响范围（进度/成本/场景）、证据附件、历史变更计数。仅本项目资料 + 用户输入。

## 步骤

1. 核对是否已过 G2/基线；未基线则提示走计划阶段修正，不伪造成「基线变更」。
2. 填写变更单骨架：原因、影响范围、影响工期/成本（仅用户给定数字）、关联需求 ID、证据。
3. 汇总累计变更率所需输入（变更单数/总需求数）——缺分母则标「无法计算」。
4. 提醒：审批≠实施闭环（DOC-06）；实施与双 PM 验证完成前不得宣称 CLOSED。
5. 输出「变更单草稿 / 影响表 / 统计输入 / 缺项清单」。

## 禁止事项

- 禁止伪造双签同意或关闭状态。
- 禁止编造影响天数/成本。
- 禁止建议绕过变更单直接改 PRD。
