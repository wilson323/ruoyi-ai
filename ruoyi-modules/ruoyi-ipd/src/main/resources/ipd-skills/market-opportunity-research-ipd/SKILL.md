# C01 市场机会与痛点调研

## 目标

产出**市场调研报告**，支撑 G1-1「市场机会真实性」（≥5 家一手验证 **或** ≥1 家书面意向）。深管阻断。

## 输入

| 资料 | 用途 | 获取 |
| --- | --- | --- |
| 产品定位与问题空间 | 调研边界 | 项目资料 / 用户 |
| 访谈纪要、走访、意向书 | 一手证据 | 用户优先 / 项目资料 |
| 二手行业材料 | 仅背景，不可替代一手 | 项目资料 |

事实只来自 `project_knowledge_search` 本项目片段或本轮用户输入。不联网；不确定字段标「未取得/不确定」。

## 步骤

1. **定范围**：把用户问题拆成 3–7 个子问题（痛点是谁的、频次、现有替代、付费/采购信号、区域差异等）；超出资料边界的子问题标跳过。
2. **检索既有知识**：按子问题分别检索「痛点」「访谈」「意向」「客户验证」；记录命中文档标题。
3. **证据表**：按客户列出痛点陈述、场景/频率、替代方案、证据类型（访谈/走访/书面意向）、来源；原话与推断分开。
4. **可信度**：每条关键结论标高/中/低（一手书面或可核对纪要=高；二手综述=低，不可计入 G1-1 家数）。
5. **门槛核对**：一手验证家数或书面意向是否够；不够则停止定性「已验证」，只输出缺项与待补清单。
6. **综合**：机会结论仅基于有来源事实；可选在用户给出规模数字时交叉说明量级，无数字不估 TAM。
7. 输出「子问题清单 / 资料核对 / 客户-痛点证据表（含可信度）/ 机会结论 / 不确定项 / 缺项清单」。

## 禁止事项

- 禁止编造客户名、访谈、意向或市场规模。
- 禁止用二手报告冒充一手验证或联网检索。
- 禁止把模型常识当来源；禁止给出 Gate 通过结论。

依据：ruflo deep-research（子问题+交叉+证据质量，改写为项目内）；WorkBuddy research-deep（不确定字段显式化）；上游 interview-script、market-sizing；六阶段 C01；五大 Gate G1-1。
